# ۱. هدف معماری (Architectural Objective)

گام ۱۰ (`P2-NI-08`) تضمین‌کننده پایداری مطلق رویدادهای تغییر داده در سطح ملی است:
1. **ریشه‌کنی اتلاف پیام‌ها (Zero Event Loss / RPO=0s):** ثبت کلیه رویدادهای سیستم در جدول فیزیکی دیتابیس (`server_outbox`) در همان تراکنش ACID داده‌های اصلی، به طوری که هیچ پیامی پیش از کامیت دیسک تولید نشود و هیچ رویدادی در اثر ریستارت پاد از دست نرود.
2. **مقیاس‌پذیری افقی مصرف‌کنندگان بدون ایجاد قفل (SKIP LOCKED Worker):** استفاده از الگوی استاندارد PostgreSQL:
   ```sql
   SELECT id, event_type, payload, retry_count 
   FROM server_outbox 
   WHERE status = 'pending' 
   ORDER BY id ASC 
   LIMIT $1 
   FOR UPDATE SKIP LOCKED;
   ```
   این الگو به چندین پاد موازی اجازه می‌دهد همزمان از صف پیام بردارند بدون اینکه کوچک‌ترین تداخل قفلی (Lock Contention) ایجاد شود.
3. **حذف کامل صف‌های ناپایدار رم:** حذف قطعی آرایه `store.outbox` از حافظه سرور و وابستگی ۱۰۰٪ به پایگاه داده به عنوان SSoT.
4. **صف پیام‌های مرده و بازیابی خطا (DLQ & Jitter Retries):** انتقال پیام‌هایی که پس از ۵ بار تلاش با خطای دائم مواجه می‌شوند به جدول `server_outbox_dlq` همراه با ثبت علت خرابی جهت ممیزی اپراتور.
