# ۱. اهداف بنیادین گام ۰۸ (Step 08 Objectives)

گام ۰۸ (`P2-NI-06`) فونداسیون حیاتی تمامیت داده‌ها در مقیاس ملی است و بر دو ستون اصلی استوار است:
1. **کنترل همزمانی سراسری (Universal OCC):** تجهیز ۱۰۰٪ پایگاه داده (تمام ۹۳ جدول) به ستون نسخه (`version INTEGER NOT NULL DEFAULT 1`) و دنباله‌های سخت‌افزاری (`BIGINT nextval`) به منظور ریشه‌کنی قطعی رونویسی تصادفی داده‌ها (Lost Updates).
2. **احراز هویت توزیع‌شده بدون انسداد (Decoupled Redis OTP):** حذف کامل کلید متمرکز `payesh:otp:state` و قفل سراسری ۱۰ ثانیه‌ای `otp-state` و مهاجرت به ساختار کلیدهای مجزا به ازای هر شماره تماس (`payesh:otp:{sha256(phone)}`) با TTL اتمیک ۱۲۰ ثانیه.

# ۲. مصوبات معماری تکمیل‌شده (Completed Architecture Decisions)

تصمیمات زیر برای گام ۰۸ اخذ و رسماً در مانیفست معماری ثبت شده‌اند:
* **ADR-001 (PostgreSQL as SSoT):** پایگاه داده PostgreSQL یگانه مرجع حقیقت است؛ حافظه رم فاقد هرگونه صلاحیت احراز هویت یا کنترل نسخه است.
* **ADR-002 / ADR-006 (Decoupled OTP Key Schema):** حذف کامل قفل مشترک ردیس؛ مقیاس‌پذیری افقی احراز هویت تا سقف ۲۰,۰۰۰ ورود در ثانیه.
* **ADR-004 (Zero-Downtime Migration Pattern):** الزام به اضافه کردن ستون بدون ایجاد قفل انحصاری (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`) و مقداردهی دسته‌ای در پس‌زمینه.
* **ADR-008 (Absolute Fail-Closed Truth):** در زمان قطعی ردیس یا دیتابیس، سامانه باید صراحتاً پاسخ ۵۰۳ صادر کند و هرگز به رم یا فایل موقت تنزل نکند.
* **ADR-009 / ADR-010 (Sequential Unlocking & Zero Test Tampering):** ممنوعیت ورود به گام ۰۹ قبل از عبور کامل از گام ۰۸ و ممنوعیت دست‌کاری تست‌های موجود.
