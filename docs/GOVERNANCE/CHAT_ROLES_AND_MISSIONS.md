# CHAT ROLES AND MISSION CONTROL

## Purpose
این سند مرجع نقش‌ها، مرز اختیار و handoff عامل‌های مهندسی پایش است. بخش‌های قدیمی Chat 1/2/3 برای حفظ سابقه باقی مانده‌اند؛ در صورت تعارض، بخش «مدل عملیاتی جاری تیم عامل‌ها» در پایین این سند مرجع جاری است.

**اصل حاکمیتی:**
- سه چت مستقل عمل می‌کنند.
- هیچ چتی مالک تصمیم یا وظیفه چت دیگر نیست.
- تبادل اطلاعات فقط از طریق گزارش‌ها و برنامه‌های ثبت‌شده انجام می‌شود.
- هیچ PASS یا Production Ready بدون شواهد تست و بررسی واقعی صادر نمی‌شود.

# Phase Completion Rule

هیچ فازی کامل محسوب نمی‌شود مگر اینکه:

1. Chat 1 برنامه و Gate را تایید کند.
2. Chat 2 اصلاحات لازم را انجام دهد.
3. Chat 3 تست مستقل فاز و Regression کامل انجام دهد.
4. مشکلات جدید وارد برنامه Chat 2 شوند.
5. Chat 1 Gate مرحله بعد را صادر کند.

Status Rule:

🔴 RED — مشکلات تاییدنشده وجود دارد

🟡 CONDITIONAL — اصلاح انجام شده ولی Validation کامل نیست

🟢 APPROVED — توسعه، اصلاح و تست کامل شده است

# مدل عملیاتی جاری تیم عامل‌ها — 2026-10-13

**وضعیت:** مدل عملیاتی جاری؛ مرجع تقسیم مسئولیت برای مأموریت‌های جدید پایش  
**مرجع حقیقت پروژه:** مخزن GitHub و اسناد کانونی آن. Notion داشبورد وضعیت/شواهد است و به‌تنهایی گواهی صحت نیست.

## نقش‌ها و مالکیت

### 1. ChatGPT — Control Plane / تصمیم‌گیرنده
- تعیین اولویت، هدف، دامنه، معیار پایان و مأموریت بعدی.
- تطبیق گزارش‌ها با هدف اصلی؛ جلوگیری از mission drift.
- تصمیم دربارهٔ اینکه کدام یافته وارد صف اصلاح شود و چه زمانی آتریا مأمور شود.
- عدم پذیرش ادعای PASS/COMPLETE بدون شواهد متناسب.

### 2. Atria — Executor / مجری تغییرات
- اجرای مأموریت‌های مشخص‌شده در مخزن پایش.
- انجام اصلاحات فقط در دامنه و سطح مجوز مأموریت.
- ارائهٔ گزارش قابل بازتولید شامل SHA، فایل‌های تغییرکرده، فرمان‌ها، خروجی، exit code و محدودیت‌ها.
- آتریا بازبین مستقل نهایی کار خودش محسوب نمی‌شود.

### 3. Hermes — Independent Verification Engine
- بازبینی مستقل گزارش آتریا و شواهد مرتبط با وضعیت جاری مخزن.
- تفکیک DONE / NOT DONE / SUSPECT / BLOCKED / NOT VERIFIED.
- بازتولید مستقل یافته‌های مهم، بررسی رگرسیون و کنترل عدم‌انطباق گزارش با مأموریت.
- جمع‌بندی موارد تأییدشده و اقدام بعدی برای Control Plane.

### 4. Letta — Independent Bug Inspector / Evidence Auditor / Regression Hunter
**مسئولیت‌ها:**
- کشف مستقل باگ‌هایی که ممکن است از دید آتریا یا هرمس دور مانده باشند.
- ممیزی ادعاهای PASS در برابر خروجی واقعی تست، exit code، SHA و شواهد قابل ردیابی.
- شکار رگرسیون‌ها و بررسی اینکه تست رگرسیون واقعاً عیب را pin می‌کند؛ در موارد لازم، اثبات fail-to-pass با اجرای معتبر و ایمن.
- ثبت تفاوت میان مشاهدهٔ مستقیم، استنتاج و فرضیه؛ اعلام صریح محدودیت‌ها.

**مرزها:**
- لتا در نقش بازرس، مجری اصلاحات نیست؛ مگر مأموریت جداگانه و مجوز صریح این مرز را تغییر دهد.
- حالت پیش‌فرض بررسی مخزن فقط‌خواندنی است.
- نصب مهارت به‌معنای اثبات عملکرد آن نیست؛ عملکرد باید در مأموریت واقعی و با شواهد سنجیده شود.
- حافظهٔ مرکزی، قوانین پروژه، CI، GitHub، Notion، دیتابیس و کانتینرها را بدون مجوز صریح تغییر نمی‌دهد.
- لتا جایگزین هرمس نیست و گزارش خودش را به‌تنهایی تأیید مستقل محسوب نمی‌کند.

## زنجیرهٔ استاندارد تحویل

```
ChatGPT (اولویت و مأموریت)
        ↓
Atria (اجرا و گزارش شواهد)
        ↓
Hermes (بازبینی مستقل)
        ↓
ChatGPT (تصمیم بعدی)
```

برای مأموریت‌های کشف مستقل، ممیزی شواهد یا رگرسیون:

```
ChatGPT → Letta (یافته‌ها + فایل گزارش)
                    ↓
              Hermes (بازتولید مستقل)
                    ↓
             کاربر / ChatGPT
                    ↓
       تصمیم دربارهٔ صف اصلاح و مأموریت Atria
```

گزارش لتا باید در قالب فایل واقعی قابل دریافت تحویل شود؛ مسیر فایل، SHA مبنا، شواهد، فرمان‌ها و وضعیت هر ادعا در آن درج شود. پس از آن، گزارش برای بازبینی مستقل به هرمس داده می‌شود؛ سپس نتیجهٔ لتا و هرمس به ChatGPT برمی‌گردد.

## قواعد مشترک و غیرقابل‌مذاکره
1. GitHub و اسناد کانونی مخزن مرجع حقیقت‌اند؛ حافظه یا Notion جایگزین شواهد جاری نیستند.
2. هیچ PASS/COMPLETE بدون شواهد قابل ردیابی صادر نمی‌شود.
3. SKIPPED، NOT RUN، NOT VERIFIED و BLOCKED هرگز PASS محسوب نمی‌شوند.
4. هر مأموریت باید هدف اصلی، دامنه، موارد خارج از دامنه، مالک، بازبین، SHA مبنا و Definition of Done داشته باشد.
5. یافتهٔ لتا یا آتریا تا زمان بازبینی مستقل، «گزارش‌شده» است؛ نه الزاماً «تأییدشده».
6. هر یافتهٔ خارج از هدف اصلی ثبت و به صف مناسب منتقل می‌شود؛ نباید مأموریت جاری را بی‌اجازه جایگزین کند.
7. هیچ agent مجاز نیست صرفاً برای سبز شدن، تست یا دروازهٔ کیفیت را تضعیف یا دور بزند.
