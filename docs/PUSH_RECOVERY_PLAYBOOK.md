## ۱) چرا پوش نمی‌شود؟

1. **چرخهٔ جلسهٔ آره‌نا:** وقتی پی‌آرِ یک نشست مرج یا بسته می‌شود، نشست «تمام‌شده» علامت می‌خورد؛
   عملیات ریموت (پوش، `gh`، حتی فچ) از همان لحظه شکست می‌خورد. این سندباکس هم‌اکنون همین وضعیت را
   دارد: `git ls-remote origin` با خطای تی‌ال‌اس شکست می‌خورد.
2. **کلون‌های تازه کم‌عمق‌اند:** نشست‌های بعدی از پایهٔ بالادستی با عمق ۱ کلون می‌شوند؛ کامیت‌های
   نشست‌های قبلی نه در تاریخچه هستند و نه قابل واکشی — مگر با انتقال دستی.
3. **باندل تنها راه انتقال است:** `git bundle` کل تاریخچهٔ شاخه را در یک فایل فشرده می‌گیرد که
   بیرون از سندباکس (آپلود به نشست تازه، یا مرج در اولین نشستِ دارای دسترسی) پوش می‌شود.
   سابقهٔ این وضعیت در `RISK_REGISTER.md` ردیف `RISK-E-004` و قلم ۶ ردیاب پی۰ ثبت است:
   «باندل‌های گیت + برنامهٔ ادغام + اولین نشستِ با دسترسی، پوش می‌کند.»

**قاعدهٔ طلایی:** پایان هر مأموریت، بدون استثنا: `git bundle create` + `git bundle verify` +
ذکر رأس و تأییدیه در گزارش مأموریت. باندلِ تأییدنشده، باندل نیست.

## ۳) دستور پوش هر باندل در نشست جدید

در نشستی که دسترسی گیت‌هاب دارد (نشست تازهٔ آره‌نا روی همین ریپو):

```bash
# ۱. باندل را در نشست آپلود کنید (مثلاً در ریشهٔ فضای کار)
# ۲. راستی‌آزمایی — باید «okay» و «complete history» بدهد
git bundle verify <bundle>

# ۳. شاخهٔ کاری از پایهٔ جاری بسازید و باندل را وارد کنید
git fetch origin main
git checkout -b push-<sandbox-name> main
git fetch <bundle> 'refs/heads/*':refs/heads/bundle-<sandbox-name>
git merge bundle-<sandbox-name> --no-ff -m "merge: بازیابی کامیت‌های <نام سندباکس>"

# ۴. گیت کامل پیش از پوش (بدون استثناء)
node tests/smoke.js          # ۵۴۷/۵۴۷
node tools/check-authz.js    # خروجی ۰
node tests/secret-scan.js    # ۱۱/۱۱
node build.js --check        # خروجی ۰

# ۵. پوش و پی‌آر
git push origin push-<sandbox-name>
gh pr create --title "recovery: کامیت‌های سندباکس <نام>" --base main \
  --body "بازیابی از <bundle> — رأس <sha>. گیت: دود/مجوز/راز/بیلد سبز."
```

> نکتهٔ کلون کم‌عمق: اگر `git fetch <bundle>` از نبود پایهٔ مشترک شکست خورد، اول
> `git fetch --unshallow origin` یا فچ عمق بیشتر، تا پایهٔ باندل در تاریخچه حاضر شود.

## ۴) گیت‌های پیش از مرج (بی‌استثناء)

| گیت | انتظار | در صورت قرمز بودن |
|---|---|---|
| `node tests/smoke.js` | ۵۴۷/۵۴۷ | مرج ممنوع؛ ریشه‌یابی با `docs/TROUBLESHOOTING.md` |
| `node tools/check-authz.js` | خروجی ۰ | مدل مجوزها را خراب نکنید؛ با ناظر |
| `node tests/secret-scan.js` | ۱۱/۱۱ | راز لو رفته ⇒ چرخش + پاک‌سازی تاریخچه پیش از پوش |
| `node build.js --check` | خروجی ۰ | بیلد را نشکنید؛ اگر بیلد سندباکس‌های مختلف با هم شکست، ترتیب مرج §۵ را بازبینی کنید |

**هیچ سندباکسی با گیت قرمز مرج نمی‌شود** — حتی اگر «فقط یک تست» باشد.

## ۵) ترتیب مرج و مدیریت تعارض

1. **هر باندل یک پی‌آر جدا** — چند سندباکس را در یک پی‌آر نریزید؛ بازگشت‌پذیری از بین می‌رود.
2. **ترتیب پیشنهادی:** از کم‌ریسک‌ترین (کمترین کامیت / قدیمی‌ترین پایه) شروع کنید تا
   پرریسک‌ترین؛ پس از مرج هر پی‌آر، بقیه را روی مِین تازه ببینید.
3. **تعارض‌های مورد انتظار:** `HANDOFF.md`، `docs/DOCS_INDEX.md`، چنج‌لاگ و سنجه‌ها —
   چون همهٔ سندباکس‌ها هم‌زمان این‌ها را ویرایش کرده‌اند. قاعدهٔ حل: **حفظ دوطرفه** (هر دو
   ورودی بمانند؛ جدیدترین اول در هندآف). هیچ کاری از هیچ سندباکسی حذف نشود.
4. **قفل‌های مستندات تداخلی:** هر سندباکس قفل نسخهٔ خودش را ساخته است؛ هنگام مرج،
   جدیدترین قفل برنده است و بقیه «تاریخی» می‌شوند — با بامپ واحد، نه ادغام دو مانیفست.
5. برنامهٔ تفصیلی ادغام و سطح تعارض پی‌آرها در `docs/PR_MERGE_PLAN.md` است.

## ۷) حالت‌های شکست و درمان

| شکست | علت محتمل | درمان |
|---|---|---|
| `bundle verify` خطا می‌دهد | باندل ناقص/بریده هنگام ساخت | در سندباکس مبدأ دوباره بسازید؛ تنها باندلِ تأییدشده را منتقل کنید |
| «unrelated histories» هنگام مرج | کلون کم‌عمق، پایهٔ باندل را ندارد | `git fetch --unshallow origin` یا افزایش عمق، سپس مرج |
| گیت‌ها پس از مرج قرمزند | تعارض پنهان دو سندباکس روی یک فایل | مرج را واگردید؛ دو طرف تعارض را دستی (حفظ دوطرفه) حل کنید |
| نشست تازه دسترسی گیت‌هاب ندارد | نشست هم بسته شده | نشست دیگری باز کنید؛ باندل را منتقل کنید — هرگز توکن دستی در چت نفرستید |
| باندل در سندباکس مبدأ نیست ولی گزارش، تأییدش را دارد | ریست سندباکس | اگر رأس کامیت در سندباکس دیگری مرج شده، کار نجات یافته؛ وگرنه در گزارش «از دست رفته» ثبت کنید |
