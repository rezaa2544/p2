# E.9 — مدیریت مراجعین (visitors)

**وضعیت:** ✅ کامل — دور ۱۰۴ (2026-09-09)، شاخهٔ `arena/01a08545-p2`
**پیشینه:** «نسخهٔ سبک» بند ۷ (فقط مدیر، دو فیلد) — این نسخه را به
مشخصات کامل E.9 ارتقا داد.

## خلاصه

میزِ پذیرشِ مدرسه: ثبتِ ورود/خروجِ افرادِ غیردانش‌آموز و غیرکارکنان
(مهمان، پیمانکار، کارشناس اداره، والد…) با نام، هدفِ مراجعه، فردِ
ملاقات‌شونده و اطلاعاتِ اختیاری — به‌همراهِ جستجو (نام/تاریخ)، کارتِ
«مراجعین امروز» روی داشبوردِ مدیر و گاردِ دسترسیِ سه‌سطح.

## مدل داده (visitors)

| فیلد | نوع | معنی |
|---|---|---|
| `id` | int | شناسه |
| `school_id` | int | مدرسه (ایزولهٔ اجاره‌نشین) |
| `name` | string | نام مراجع (اجباری) |
| `national_id` | string | کد ملی (اختیاری) — **تازه** |
| `phone` | string | شمارهٔ تماس (اختیاری) — **تازه** |
| `purpose` | string | هدف مراجعه (اختیاری) |
| `visiting_person` | string | فردِ ملاقات‌شونده (اختیاری) — **تازه** |
| `in_at` | ISO | زمان ورود |
| `out_at` | ISO / '' | زمان خروج (در صورت خروج) |
| `status` | 'in'/'out' | در محل / خارج شده — **تازه** |
| `registered_by` | int | کاربرِ ثبت‌کننده |
| `created_at` | ISO | تاریخ ثبت |

**سازگاریِ عقب:** `status` در رکوردهای تازه صریح است؛ `visitorStatus(v)`
برای رکوردهای کهنه (بدونِ status) وضعیت را از `out_at` مشتق می‌کند —
رکوردهای قبلی بدونِ مهاجرت درست نمایش می‌شوند.

## دسترسی (سه سطح)

| نقش | مشاهده | ثبت ورود/خروج |
|---|---|---|
| مدیر (`role=manager` بدونِ عنوانِ معاون) | ✅ | ✅ |
| نگهبان (`role=guard` — تفویضی) | ✅ | ✅ |
| معاون (کاربرِ `role=manager` با عنوانِ «معاون…») | ✅ فقط‌خوان | ❌ |
| سوپرادمین | ✅ (بدونِ school_id ⇒ لیستِ خالی) | ✅ (قاعدهٔ همه‌کاره) |
| سایر نقش‌ها | ❌ | ❌ |

لایه‌های اجرا:
1. **مسیر:** `canRoute` — روتِ `visitors` فقط در NAVِ مدیر و نگهبان
   (سوپرادمین با قاعدهٔ همه‌کاره می‌گذرد). مسیرِ مستقیمِ hash توسط
   نقش‌هایِ دیگر مسدود است (اصلاحِ نشتِ پیشینِ نسخهٔ سبک).
2. **اکشن:** `ACTION_ROLES` — `vis-new`/`vis-save`/`vis-out` =
   `['manager','guard']` (+ write-permsِ سرور، fail-closed).
3. **داده:** `visitorWriteOk` — گاردِ عنوانِ «معاون» + مالکیتِ مدرسه
   (الگوی رایجِ کد: «روی داده تکرار می‌شود، نه فقط دکمه»).

**نقشِ نگهبان:** نقشِ تازه در سراسرِ زنجیره (`USER_ROLES` در
`server/validate.js`، `NAV.guard`، گزینهٔ «نگهبان/پذیرش» در فرمِ کاربر
برایِ سوپرادمین). «مجوزِ تفویضی» = سوپرادمین کاربری با `role=guard`
و `school_id` می‌سازد — بدونِ هیچ تغییرِ کدی.

## رابط کاربری

- **فرمِ ثبت ورود:** نام (اجباری)، هدف، فردِ ملاقات‌شونده، تماس،
  کد ملی — هر سهِ آخر اختیاری.
- **ثبت خروج:** دکمهٔ «خروج» در کنارِ هر ردیفِ حاضر (فقط نقش‌هایِ
  نویسنده)؛ خروجِ تکراری رد می‌شود.
- **لیست + جستجو:** بَجِ «در حال حاضر در مدرسه / کل ثبت‌شده» +
  فیلترِ زندهٔ نام (روی `data-f`/`S.filters`) + فیلترِ تاریخِ ورود
  (شنوندهٔ `change` روی `vis_date`) + دکمهٔ «پاک کردن».
- **کارتِ داشبورد:** `visitorDashCard` روی داشبوردِ مدیر/نگهبان —
  مراجعه‌های امروز + کسانی که همین حالا در مدرسه‌اند + «مشاهدهٔ همه».
- **دادهٔ نمونه:** ۳ رکوردِ قطعی (بدونِ rng/زمانِ اجرا) در نخستین
  مدرسه: یک رکوردِ دیروزِ خارج‌شده + امروز یک «در مدرسه» و یک
  «خارج‌شده» — هر دو با `visiting_person`.

## امنیت

- **fail-closedِ سرور:** whitelistِ فیلدها در `authz/model.json`
  (فیلدهای تازه فقط از این مسیر می‌آیند)، `STATUS_ENUMS.visitors`
  در `server/validate.js`، write-perms برایِ هر سه اکشنِ نویسنده.
- **روزِ غیرحضوری (بند ۱۶):** `visitorRegister` و آینهٔ سرور در
  `server/sync.js` (virtualDayViolation) ورودِ فیزیکی را مسدود می‌کنند.
- **XSS:** همهٔ ورودی‌ها با `esc`/`escAttr`.
- **ایزولهٔ مدرسه:** خروج/ثبت فقط روی رکوردهایِ همان `school_id`
  (گاردِ داده).

## تصمیم‌های باز (برای سوپروایزر)

- **حذف/ویرایش رکورد:** فعلاً نیست (فقط ورود + خروج) — `del` در مدل
  فقط برایِ مدیر/سوپرادمین است ولی UI ندارد.
- **نمایشِ «نگهبان» در گزارش‌ها/آمار:** در آمارِ مراجعین (تعدادِ
  روزانه/هفته‌ای) فعلاً نیست — اگر خواسته شود، یک کارتِ کوچک روی
  همان صفحه.
- **مهاجرتِ خودکارِ رکوردهای کهنه** (نوشتنِ status برایشان): لازم
  نیست — تفسیرِ مشتقی کافی است.
