## ۱) چه ساخته شد

- `server/admin.js`: هستهٔ پشتیبان‌گیری از endpoint جدا شد —
  `backupNow(source, userId)` حالا مشترک است بین:
  - endpoint دستی (superadmin) → آدیت با `source:"manual"` + `user_id`
  - **زمان‌بندیِ خودکارِ درون‌پروسه** → آدیت با `source:"auto"` + `user_id:null`
- `admin.startAutoBackup(ms)` — تایمر سادهٔ `setInterval` (unref)، همان مسیرِ
  اتمی + نگه‌داریِ ۱۰ نسخهٔ مشترک. بدون cron بیرونی، بدون وابستگی جدید.
- `server/index.js`: روشن با `PAYESH_BACKUP_EVERY_HOURS` (production، مثلاً ۲۴)
  یا `PAYESH_BACKUP_EVERY_MS` (تست)؛ بی‌ارزش/صفر = خاموش (پیش‌فرض).
  خطِ boot-log تازه: `backup : automatic every N min (retention 10)`.

## ۳) یافته‌ها و رفع‌ها

1. **ENOSPC در sandbox:** `/tmp` فقط ۹۹۳MB tmpfs است؛ تست‌های سرور هر بار
   یک tmp ~۵MB می‌ساختند و پاک نمی‌کردند → بعد از ~۱۵۰ اجرا دیسک پر شد و
   `copyfile` شکست. به هر هشت `tests/server*.js` یک
   `process.on('exit', () => fs.rmSync(tmp, …))` اضافه شد (امروز ۷۶۳MB آزاد شد).
2. **اسپلسِ خورده:** در بازسازیِ `admin.js` توابعِ بینِ دو لنگر (`apiRestore`)
   حذف شدند و سرور با `ReferenceError` کرش می‌کرد — بازگردانده و با server8
   (9/9) تأیید شد.
3. **تستِ تایمری:** شمارشِ دقیقِ فایل در حضورِ تایمرِ فعال قابل اتکا نیست
   (تیک می‌تواند وسطِ ادعا بیفتد) — به‌جای `count+1`، فایلِ پاسخِ endpoint
   روی disk چک می‌شود.
4. **اسکنِ تایپوی تاریخ:** الگوی قبلی سالِ ۲ رقمی را نمی‌گرفت
   («۲۰۲۶-۰۹-۰۶» از `{3,4}` رد شد) — حالا `{2,4}`.
