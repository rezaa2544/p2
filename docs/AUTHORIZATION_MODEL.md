# مدل مجوز و ایزولاسیون مستأجر — پایش (ویو ۵)

> مرجع واحدِ مجوزها: چه کسی، روی چه داده‌ای، با چه محدوده‌ای.
>
> **اصل بنیادین:** هیچ `resource id` به‌تنهایی مجوز نیست؛ مالکیت و
> محدوده همیشه از دادهٔ واقعیِ فروشگاه حل می‌شود (نه از ادعای کلاینت).
> کنترل‌های کلاینت فقط رابط کاربری را مرتب می‌کنند — **نقطهٔ اجرا
> همیشه سرور است.**

---

## ۱) سطوح چندمستأجری (Tenancy)

```
 ملی (سوپرادمین)
  └─ استان (اداره کل)
      └─ شهرستان (اداره شهرستان)
          └─ منطقه (اداره منطقه)
              └─ مدرسه (مدیر)
                  └─ کلاس (دبیر کلاس/دبیر درس)
                      └─ دانش‌آموز (خودش / ولیِ او)
```

هر نقش فقط در سطح خودش و زیرمجموعه‌اش می‌بیند/می‌نویسد. محدودهٔ
اداره از فیلدهای جغرافیایی دفتر می‌آید (`province_id` / `county_id` /
`district_id` — هرکدام که غیرخالی باشد باید با مدرسه بخواند).

## ۲) لایه‌های اجرا (هر نوشتن از همهٔ این دروازه‌ها می‌گذرد)

| # | دروازه | محل | خطا |
|---|---|---|---|
| ۱ | احراز نشست (ژتون) | `server/auth.js` | ۴۰۱ `no_session` |
| ۲ | مجوز نقش×مجموعه×عمل (فایل تولیدی، نه جدول دستی) | `authz/write-perms.json` ← `tools/generate-write-perms.js` ← `authz/model.json` | ۴۰۳ `role_denied` |
| ۳ | دروازهٔ فیلد: فقط فیلدهای مدل؛ فیلدهای حساس فقط برای نقش‌های معاف | `server/sync.js: fieldGate` | `unknown_field` / `field_denied` |
| ۴ | **محدودهٔ مستأجر (ویو ۵)** | `server/sync.js: inScope` | ۴۰۳ `out_of_scope` |
| ۵ | اعتبارسنجی مقدار | `server/validate.js` | `field_denied` |
| ۶ | قفل خوش‌بینانه/نسخه | `server/occ.js` | `version_conflict` |

ترتیب مهم است: دروازهٔ محدوده **پیش از** اعمال هر تغییر اجرا می‌شود و
شکست در هر لایه = ردِ کل عملیات (بدون اعمال جزئی).

## ۳) محدودهٔ نقش‌ها (خلاصهٔ `inScope`)

| نقش | محدودهٔ نوشتن | مالکیت/مهار |
|---|---|---|
| `superadmin` | همه‌چیز (بدون محدودیت — با آزمون جدا نگهبانی می‌شود) | — |
| `manager` | فقط `school_id === مدرسهٔ خودش`؛ مجموعه‌های بدون `school_id` از مسیر دانش‌آموز→ثبت‌نام→کلاس→مدرسه حل می‌شود (بی‌مهار ⇒ رد) | رکورد واقعی |
| `teacher` | کلاس‌هایی که واقعاً درس می‌دهد (سرپرستی یا برنامهٔ هفتگی)؛ رکورد دانش‌آموز فقط از همان کلاس‌ها؛ رکورد با `teacher_id` فقط خودش | برنامه/سرپرستی |
| `student` | فقط رکوردهای `student_id === خودش`؛ پیام‌ها فقط با `from_id` خودش؛ پروفایل خودش | رکورد واقعی |
| `parent` | فقط فرزندانِ `parent_links` خودش؛ ساخت پیوند جدید فقط برای خودش؛ رزرو نوبت برای فرزند خودش | پیوندها |
| `edu_office` | **ویو ۵:** فقط مدارس داخل محدودهٔ جغرافیایی دفتر (استان/شهرستان/منطقه) برای `announcements`, `teacher_schools`, `attendance_modes`, `notifications`, `notify_queue`؛ مهار از `school_id` یا مدرسهٔ گیرنده (`user_id`) حل می‌شود؛ **بی‌مهار ⇒ رد**؛ `offices` کلاً بسته (ساختاری — فقط سوپرادمین) | دفتر کاربر |

نکتهٔ معماری: `edu_office` مرجع بین‌مدرسه‌ای است اما نه بین‌منطقه‌ای —
مرز، محدودهٔ جغرافیایی دفترِ خود کاربر است.

## ۴) قرارداد خوانش و ضدشمارش (IDOR)

- `GET /api/students/:id` (`server/idor.js`): بررسی محدوده برای **هر
  رکورد**؛ بیرون محدوده ⇒ **۴۰۴ همیشه** (نه ۴۰۳ — ۴۰۳ وجود شناسه را
  لو می‌دهد و شمارش را ممکن می‌کند).
- خروجی همان پروژکشنِ پالایش‌شده است: `phone` و `national_id` هرگز از
  سرور بیرون نمی‌روند.
- روتر تلاش‌های ۴۰۴ پیاپی را می‌شمارد (`§5.7`: کندکردن + هشدار، نه قطع).
- هیچ `resource id` به‌تنهایی مجوز نیست: حتی اگر شناسهٔ دانش‌آموز حدس
  زده شود، بدون رابطهٔ کلاس/فرزند/مدرسه پاسخ ۴۰۴ است.

## ۵) استثناهای عمدی (مستند و آزمون‌دار)

- **ارزشیابی ناشناس معلم (`teacher_evaluations`):** رکورد عمداً فیلد
  هویتی ندارد؛ مالکیت به «مدرسهٔ پاسخ‌دهنده» گره می‌خورد (دانش‌آموز:
  مدرسهٔ خودش؛ ولی: مدرسهٔ فرزندانش). `upd:[] / del:[]` — تغییرناپذیر.
- **پیام‌ها:** مالکیت `from_id` برای نقش‌های رکوردی (جعل فرستنده ⇒ رد).
- **اعلان‌ها:** والد/دانش‌آموز فقط پرچم `read` اعلان خودش را ویرایش می‌کند.

## ۷) افزودن مجموعهٔ تازه — چک‌لیست مجوز

۱. ثبت در `authz/model.json` (فیلدها + نقش‌های هر عمل) — کمترین مجوز ممکن.
۲. `node tools/generate-write-perms.js` و سپردن خروجی به گیت.
۳. اگر مجموعه مهارِ `student_id/teacher_id/from_id` ندارد و نقشِ
   مدرسه‌ای/اداره‌ای به آن می‌نویسد: **کیس صریح در `inScope`** بنویسید
   (الگو: `teacher_evaluations`، دروازهٔ ویو ۵ برای اداره).
۴. آزمون منفی بین‌مدرسه‌ای به `tests/wave5-authz.js` اضافه کنید.
۵. `node build.js --check` + `server16` + `wave5-authz` سبز بماند.
