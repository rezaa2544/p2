**نسخه:** ۱.۰.۰ | **تاریخ:** 2026-09-10 | **مالک:** چت ۶ (مستندات و انتشار)
**وضعیت:** مرجع کامل اسکیمای پستگرس — تولید خودکار از مهاجرت‌ها؛ ویرایش دستی ممنوع (اجرای `node tools/generate-data-dictionary.js`).
**منابع حقیقت:** `migrations/001` تا `004` (ساختار + قیدها) · `server/schema.sql` (جدول‌های زیرساختی) · `authz/model.json` (نقش‌های نوشتار)
**هم‌خانواده:** `docs/MIGRATION_GUIDE.md` · `docs/DATABASE_ARCHITECTURE.md` · `docs/CAPACITY_MODEL.md` (برآوردها) · `docs/SYNC_PROTOCOL.md`

### نمودار روابط اصلی (متنی)

```text
                    ┌────────────┐
                    │  schools   │ ← ریشهٔ مستأجر (۸۶ جدول با FK به آن)
                    └─────┬──────┘
      ┌───────────┬───────┼────────────┬───────────────┐
      ▼           ▼       ▼            ▼               ▼
 ┌────────┐  ┌────────┐ ┌─────────┐ ┌────────────┐ ┌──────────────┐
 │ users  │  │classes │ │subjects │ │school_years│ │ bell/calendar │
 └───┬────┘  └───┬────┘ └────┬────┘ └────────────┘ └──────────────┘
     │  │        │           │
     │  │   enrollments ←────┘ (student, class, year — یکتا در سال)
     │  │        │
     │  ▼        ▼
     │ grades ◄──┴── student_id → users · class_id → classes · subject_id → subjects
     │ attendance ◄─ student_id → users · class_id → classes
     │ schedule ◄── class/subject/teacher(day,period برای دبیر یکتا)
     ▼
 parent_links (parent_id→users, student_id→users)

 زیرساخت همگام‌سازی (بدون مستأجر):
 server_processed_uids · server_revoked_jti · server_auth_codes(OTP ۵د)
 server_outbox (رخدادها) · server_tombstones (سنگ‌قبر) · sync_conflicts (تعارض‌ها)
```

قراردادهای سراسری: همهٔ جدول‌های دامنه `id` از نوع `INTEGER GENERATED BY DEFAULT AS IDENTITY` دارند و
`created_at`/`updated_at` آن‌ها `TIMESTAMPTZ` است. تاریخ‌های تقویمی (`date`) به‌صورت رشتهٔ شمسی
`VARCHAR(50)` نگهداری می‌شوند (نمایش کلاینت). قیدهای مدرسه همه `ON DELETE CASCADE DEFERRABLE
INITIALLY DEFERRED`اند تا همگام‌سازی دسته‌ای چندجدولی در یک تراکنش ممکن بماند.

## ۳) یادداشت‌های اجرایی برای دی‌بی‌ای

- **منبع حاکم:** مهاجرت‌های `migrations/` مسیر رسمی تغییرند؛ `server/schema.sql` تولیدی است و نباید دستی ویرایش شود. هر تغییر ساختاری = مهاجرت تازه طبق `docs/MIGRATION_GUIDE.md`.
- **OCC:** نوشتن‌های همگام‌سازی با `UPDATE ... WHERE id=$1 AND version=$2` محافظت می‌شوند؛ ستون `version` در ۹ جدول فهرست §۱ وجود دارد. دست‌کاری دستی `version` ممنوع است.
- **سنگ‌قبرها:** حذف منطقی با درج در `server_tombstones` همراه است؛ پولِ دلتا از آن می‌خواند (`docs/SYNC_PROTOCOL.md`). جمع‌آوری سنگ‌قبرها فقط با پنجرهٔ امن همگام‌سازی مجاز است.
- **صندوق خروجی:** `server_outbox` با توالی مشترک `payesh_outbox_id_seq` (مهاجرت ۰۰۴) شناسه می‌گیرد؛ جدول در همان تراکنش نوشتن پر می‌شود و مصرف‌کننده آن را پس از پردازش علامت می‌زند.
- **دادهٔ شخصی:** جدول `users` و دفاتر حسابرسی مشمول قواعد `docs/SECURITY_MODEL.md`اند؛ حذف حساب کاربر از مسیر `server/delete-service.js` و با سنگ‌قبر انجام می‌شود.
- **برآوردها:** اعداد «برآورد ردیف» از `docs/CAPACITY_MODEL.md` و `docs/LOAD_TEST_PLAN.md` §۲ گرفته شده‌اند و پیش‌بینی‌اند، نه اندازه‌گیری.
