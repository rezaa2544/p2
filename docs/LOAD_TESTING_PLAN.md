## ۲. انتخاب و مقایسه ابزارهای آزمون بار (Tool Evaluation & Selection)

برای اجرای آزمون‌های بار سنگین در مقیاس ملی، سه ابزار مطرح جهانی مورد ارزیابی فنی قرار گرفتند:

```
┌─────────────────┬───────────────────┬───────────────────┬───────────────────┐
│ شاخص فنی        │ k6 (Grafana)      │ Locust (Python)   │ Gatling (Scala)   │
├─────────────────┼───────────────────┼───────────────────┼───────────────────┤
│ زبان اسکریپت‌نویسی│ JavaScript (ES6)  │ Python            │ Scala / Java      │
│ هسته اجرایی     │ Go (کامپایل‌شده)  │ Python (GIL/Async)│ JVM (Netty Engine)│
│ مصرف حافظه/VU   │ 🟢 بسیار کم (~2KB)│ 🔴 متوسط (~100KB) │ 🟡 کم (~15KB)     │
│ توان تولید بار تکی│ ۵۰,۰۰۰+ VU / Node │ ۵,۰۰۰ VU / Node   │ ۳۰,۰۰۰ VU / Node  │
│ یکپارچگی CI/CD  │ 🟢 بومی و بسیار ساده│ 🟡 نیازمند محیط وب│ 🟡 نیازمند Build  │
│ خروجی متریک‌ها   │ Prometheus/Grafana│ Web UI محلی       │ HTML Reports      │
└─────────────────┴───────────────────┴───────────────────┴───────────────────┘
```

### چرا **k6** به عنوان ابزار مرجع پایش انتخاب شد؟
1. **اشتراک زبان اسکریپت با هسته پایش (JavaScript):** توسعه‌دهندگان پایش بدون نیاز به یادگیری زبان جدید (مانند Scala یا Python)، سناریوها را با جاوااسکریپت استاندارد می‌نویسند.
2. **بهینگی فوق‌العاده در مصرف منابع سخت‌افزاری:** هسته k6 با زبان Go توسعه یافته و بدون بار سنگین مفسر یا ماشین مجازی، توانایی ایجاد بیش از ۵۰ هزار کاربر مجازی فعال روی یک سرور آزمون استاندارد را داراست.
3. **پشتیبانی بومی از مدل توزیع‌شده (Distributed k6 via Kubernetes Operator):** برای دستیابی به ۵ میلیون کاربر مجازی، کلاسترهای تست بار به سادگی در قالب Podهای موازی توزیع می‌شوند.
4. **تعریف دقیق آستانه‌های پذیرش (Thresholds as Code):** اعتبارسنجی سخت‌گیرانه SLOها درون کد اسکریپت تست و توقف خودکار پایپ‌لاین در صورت نقض معیارها (`fail-fast`).

## ۳. سناریوهای آزمون بار واقعی (Load Test Scenarios)

الگوی رفتاری کاربران در ۶ سناریوی حیاتی شبیه‌سازی می‌شود:

```
                  ┌─────────────────────────────────────────────────────────┐
                  │              توزیع ترافیک سناریوهای اوج                 │
                  ├──────────────────────┬──────────────────────────────────┤
                  │ سناریوی ۱: Login     │ ۲۰٪ کل ترافیک (موج ورود صبحگاهی) │
                  │ سناریوی ۲: Bootstrap │ ۱۵٪ کل ترافیک (دریافت اطلاعات اول)│
                  │ سناریوی ۳: Attendance│ ۳۵٪ کل ترافیک (ساعات ۷:۳۰ تا ۸:۳۰)│
                  │ سناریوی ۴: Grades    │ ۱۰٪ کل ترافیک (فصل امتحانات)     │
                  │ سناریوی ۵: Notify    │ ۵٪ کل ترافیک (ارسال بخشنامه‌ها)  │
                  │ سناریوی ۶: Sync      │ ۱۵٪ کل ترافیک (همگام‌سازی دسته‌ای)│
                  └──────────────────────┴──────────────────────────────────┘
```

---

### سناریو ۱: ورود پرحجم کاربران (Concurrent Login Peak)
* **شرح:** ارسال کد OTP، اعتبارسنجی شماره همراه و کد ملی، تولید نشست JWT رمزنگاری‌شده و تنظیم کوکی `HttpOnly`.
* **نقاط فشار:** نرخ هش کدهای OTP، مقاومت ریت‌لیمیتر (`code_rate_ip` و `code_rate_phone`) و پردازش رمزنگاری HMAC-SHA256 در امضای JWT.

### سناریو ۲: دریافت برش اولیه داده (Bootstrap & Initial Scope)
* **شرح:** فراخوانی مسیر `/api/bootstrap` یا `/api/auth/me` جهت دریافت داده‌های اولیه مدرسه و کاربر.
* **نقاط فشار:** سربار فیلتر محدوده (`29-scope.js`)، بازدهی کش حافظه و حجم بایت ارسالی در شبکه.

### سناریو ۳: ثبت انبوه حضور و غیاب صبحگاهی (Morning Attendance Burst)
* **شرح:** ارسال وضعیت حضور و غیاب کلاس‌ها توسط ۱۰۰,۰۰۰ دبیر در یک پنجره ۳۰ دقیقه‌ای (ساعت ۷:۴۵ تا ۸:۱۵ صبح).
* **نقاط فشار:** اعتبارسنجی تقاطع روز/کلاس، اعمال قوانین LWW مشروط، و نوشتن هم‌زمان در دیتابیس.

### سناریو ۴: ثبت نمرات و کارنامه (Grade Registration Spike)
* **شرح:** ثبت نمرات کلاسی و امتحانی با اعتبارسنجی دامنه $[0, 20]$ و بررسی شماره نسخه (`base_version`).
* **نقاط فشار:** مدیریت مسابقه نسخه‌ها (Optimistic Lock Concurrency) و ثبت رکوردهای تعارض در `sync_conflicts`.

### سناریو ۵: اعلان‌ها و پیام‌های گروهی (Notification Fan-Out)
* **شرح:** ارسال یک بخشنامه یا اطلاعیه سراسری توسط اداره کل یا مدیر مدرسه و توزیع آن به هزاران دانش‌آموز و ولی.
* **نقاط فشار:** عملیات Fan-out، نوشتن دسته‌ای در صندوق ورودی پیام‌ها، و تولید بارهای وب‌سوکت/پوش‌نوتیفیکیشن.

### سناریو ۶: همگام‌سازی آفلاین دسته‌ای (Batch Offline Sync Queue)
* **شرح:** اتصال مجدد ۵۰۰۰ مدرسه روستایی پس از رفع قطعی اینترنت و تخلیه هم‌زمان بسته‌های ۵۰۰تایی جهش‌های آفلاین.
* **نقاط فشار:** پردازش اتمیک تراکنش‌های دسته‌ای، بررسی فیلدهای حفاظت‌شده، و مقیاس‌پذیری مکانیزم Idempotency (`__processed_uids`).

## ۵. معیارهای موفقیت و اهداف سطح خدمت (SLOs & Acceptance Criteria)

سامانه زمانی آزمون را با موفقیت پشت سر می‌گذارد که تمامی اهداف سطح خدمت زیر به صورت هم‌زمان احراز شوند:

```
┌──────────────────────────────────────┬────────────────┬────────────────────────┐
│ شاخص کلیدی عملکرد (Metric)           │ آستانه مجاز    │ نوع شاخص              │
├──────────────────────────────────────┼────────────────┼────────────────────────┤
│ زمان پاسخ درخواست‌های خواندن (Read)  │ p95 < 300 ms   │ Service Level Objective│
│ زمان پاسخ جهش‌ها و همگام‌سازی (Write) │ p95 < 500 ms   │ Service Level Objective│
│ حداکثر زمان پاسخ در صدک ۹۹ (p99)     │ p99 < 1200 ms  │ Latency Guardrail      │
│ نرخ خطای کل (Error Rate: 5xx, Drops) │ < 0.1%         │ Reliability Threshold  │
│ نرخ اصابت به حافظه موقت (Cache Hit)  │ > 80%          │ Efficiency Threshold   │
│ حداکثر مصرف پردازنده سرورها (CPU)    │ < 75% Average  │ Capacity Headroom      │
│ نشت حافظه (Memory Leak / Heap Drift) │ صفر (پایدار)   │ Stability Guardrail    │
└──────────────────────────────────────┴────────────────┴────────────────────────┘
```

## ۶. پیاده‌سازی اسکریپت آزمون بار با k6 (k6 Test Scripts)

نمونه کد کامل و اجرایی اسکریپت آزمون بار چندسناریویی برای سامانه پایش:

```javascript
/* ==========================================================================
   k6 Load Testing Suite — Payesh National Scale (10M Users / 5M Peak VUs)
   اجرای هم‌زمان سناریوهای ورود، همگام‌سازی، حضور و غیاب و نمرات
   ========================================================================== */

import http from 'k6/http';
import { check, sleep, group } from 'k6';
import { Counter, Rate, Trend } from 'k6/metrics';

// تعریف متریک‌های اختصاصی سامانه پایش
const syncLatency = new Trend('payesh_sync_duration', true);
const errorRate = new Rate('payesh_error_rate');
const activeLogins = new Counter('payesh_successful_logins');

// تنظیم مراحل پلکانی بار (Ramping Stages)
export const options = {
  scenarios: {
    // سناریوی ۱: ترافیک مستمر حضور و غیاب و همگام‌سازی
    attendance_and_sync: {
      executor: 'ramping-arrival-rate',
      startRate: 500,
      timeUnit: '1s',
      preAllocatedVUs: 2000,
      maxVUs: 50000,
      stages: [
        { duration: '5m', target: 5000 },   // گرم کردن
        { duration: '15m', target: 25000 }, // ورود به اوج صبحگاهی
        { duration: '30m', target: 50000 }, // اوج ترافیک کشوری
        { duration: '10m', target: 1000 },  // فرود بار
      ],
    },
    // سناریوی ۲: آزمون ضربه‌ای ورود (Spike Test on Login)
    login_spike: {
      executor: 'ramping-vus',
      startVUs: 0,
      stages: [
        { duration: '2m', target: 10000 },
        { duration: '5m', target: 10000 },
        { duration: '2m', target: 0 },
      ],
      gracefulRampDown: '30s',
    },
  },

  // آستانه‌های موفقیت (SLOs as Code)
  thresholds: {
    'http_req_duration{type:read}': ['p(95)<300'],
    'http_req_duration{type:write}': ['p(95)<500'],
    'payesh_sync_duration': ['p(95)<500', 'p(99)<1000'],
    'payesh_error_rate': ['rate<0.001'], // خطای زیر ۰.۱ درصد
    'http_req_failed': ['rate<0.001'],
  },
};

const BASE_URL = __ENV.TARGET_URL || 'http://localhost:3000';

export default function () {
  const vuId = __VU;
  const iterId = __ITER;

  group('۱. احراز هویت و ورود (Auth Flow)', function () {
    const payload = JSON.stringify({
      phone: `0912${String(vuId).padStart(7, '0')}`,
      code: '123456',
      national_id: '0012345678',
    });

    const res = http.post(`${BASE_URL}/api/auth/login`, payload, {
      headers: { 'Content-Type': 'application/json' },
      tags: { type: 'write' },
    });

    const loginOk = check(res, {
      'login status is 200': (r) => r.status === 200,
      'login has auth cookie': (r) => r.headers['Set-Cookie'] !== undefined,
    });

    errorRate.add(!loginOk);
    if (loginOk) activeLogins.add(1);
  });

  sleep(1);

  group('۲. همگام‌سازی دسته‌ای آفلاین (Sync Batch Flow)', function () {
    const mutationBatch = JSON.stringify({
      ops: [
        {
          uid: `ULID_${vuId}_${iterId}_1`,
          id: `REC_ATT_${vuId}`,
          c: 'attendance',
          t: 'ins',
          base_version: 1,
          client_time: new Date().toISOString(),
          data: {
            student_id: (vuId % 1000) + 1,
            class_id: (vuId % 50) + 1,
            status: 'present',
            date: new Date().toISOString().slice(0, 10),
          },
        },
        {
          uid: `ULID_${vuId}_${iterId}_2`,
          id: `REC_GRD_${vuId}`,
          c: 'grades',
          t: 'upd',
          base_version: 2,
          client_time: new Date().toISOString(),
          data: {
            student_id: (vuId % 1000) + 1,
            subject_id: 10,
            score: 18.5,
          },
        },
      ],
    });

    const startTime = Date.now();
    const res = http.post(`${BASE_URL}/api/sync`, mutationBatch, {
      headers: { 'Content-Type': 'application/json' },
      tags: { type: 'write' },
    });

    syncLatency.add(Date.now() - startTime);

    const syncOk = check(res, {
      'sync status is 200': (r) => r.status === 200,
      'sync result ok': (r) => JSON.parse(r.body).ok === true,
    });

    errorRate.add(!syncOk);
  });

  sleep(2);
}
```

## ۸. دستورالعمل عیب‌یابی و رفع گلوگاه‌ها (Troubleshooting Runbook)

| نشانه‌های گلوگاه | علت ریشه‌ای احتمالی | اقدام اصلاحی فوری |

| **افزایش p95 به بیش از ۱ ثانیه در sync** | قفل‌های سطری طولانی روی یک مدرسه | افراز داده‌ها (Sharding) بر مبنای `school_id` و کش محلی |

| **تجمع رکوردهای sync_conflicts** | عدم همگامی نسخه کلاینت‌ها با سرور | انتشار خودکار بسته همگام‌سازی سرور (Catch-Up Polling) |

## ۱۰. لایهٔ اجراییِ واقعی (command reference — افزودهٔ چت ۱)

### ۱۰-۱. دستورها

| دستور | چه می‌کند |
|---|---|
| `npm run perf:login` | سناریویِ ۱ (ورودِ انبوه، `01-login`) |

### ۱۰-۲. پیش‌نیازها و محیط‌ها

- **k6** (باینریِ Go، نه پکیجِ npm): روشِ نصب در `tests/performance/README.md` §۲.
  بدونِ k6، دستورها با پیامِ صریح و exit غیرصفر می‌ایستند (fail-closed).
- **local** (پیش‌فرض): سرورِ `127.0.0.1:3000`؛ احرازِ سناریوها با اکویِ کدِ دموست
  (`PAYESH_DEMO_CODE=1` — فقط staging/لوکال، هرگز تولید: `DEPLOY.md` §env).
- **staging/production/cluster**: با `--env` یا `--base-url`؛ آستانه‌ها در
  `tests/performance/config/thresholds.json` و `options` هر فایل (thresholds-as-code).
- **CI**: k6 عمداً در CI نیست (نیازمندِ باینری + محیطِ staging)؛ آزمونِ بار گیتِ
  دستیِ پیشِ‌انتشار است، نه گیتِ هر کامیت.

### ۱۰-۳. تطبیقِ نردبانِ پرامپت با §۴
