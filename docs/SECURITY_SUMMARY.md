## ۱.۳. توصیه‌هایِ نهایی

### برایِ Go-Live ملی
1. `PAYESH_DEMO_CODE=0` (مهم‌ترین؛ وگرنه ورودِ تولید معنادار نیست) + `PAYESH_JWT_SECRET` قوی
   (۶۴+ کاراکتر) — جدولِ env در `docs/DEPLOY.md`.
2. TLS درون‌پروسه (`PAYESH_HTTPS=1`) یا پروکسیِ همان‌ماشین؛ اگر پروکسی رویِ میزبانِ دیگر
   است، IP آن در `PAYESH_TRUSTED_PROXIES` وگرنه XFF نادیده گرفته می‌شود.
3. مالکیت/مجوزِ فایل‌ها: دایرکتوریِ داده + `payesh.json`/`jwt.key`/`audit.log` با 0600/0700؛
   کاربرِ سرویسِ غیرِ root.
4. بکاپِ خودکار (`PAYESH_BACKUP_EVERY_HOURS=24`) + نگهداریِ ۱۰ نسخه + آزمونِ دوره‌ایِ restore.
5. پایش: هشدار رویِ جهشِ `csrf_denied`، `rate_limited`، `login_fail` و `account_delete_denied`
   در `audit.log`؛ داشبوردِ شمارشِ 429/403.
6. نشست‌هایِ صادرشده پیش از وصلهٔ CSRF فاقدِ claim‌اند و رویِ جهش‌ها 403 می‌گیرند —
   در پنجرهٔ نگهداری، کاربران یک‌بار دوباره وارد شوند (یا jtiها ابطال شود).

### برایِ نگهداریِ دوره‌ای
1. گیت‌هایِ هر انتشار: `node tests/smoke.js` ‏547/547‏، `node tools/check-authz.js` خروجیِ ۰،
   `node tests/secret-scan.js` ‏11/11‏، `npm run lint` بدونِ خطا.
2. اجرایِ ماهانهٔ سوئیت‌هایِ امنیتی (`security2`، `otp-ratelimit`، `server17`، `csrf`،
   `ip-trust`) + بازبینیِ `audit.log` برایِ الگوهایِ تازه.
3. ممیزیِ فصلیِ «بدونِ راز در استراحت» (کلاینت + `otp.json`) و بازبینیِ مجوزِ فایل‌ها (S-73-3).
4. هر تغییر در اکشن‌هایِ `data-act` باید `check-authz` را سبز نگه دارد (تستِ رگرسیونِ ۵۳ مورد).
