## ۲) ورود باندل در نشست جدید (حالت عادی)

پیش‌نیاز: نشستی روی ریپوی `rezaa2544/p2` با دسترسی گیت‌هاب و فایل باندل آپلودشده در `/home/user/`.

```bash
# ۱. راستی‌آزمایی — باید «okay» و «complete history» بدهد
git bundle verify /home/user/chat6-master-recovery.bundle

# ۲. گرفتن وضعیت مِین
git fetch origin main

# ۳. شاخهٔ بازیابی
git checkout -b chat6-master-recovery origin/main

# ۴. واردکردن تاریخچهٔ باندل و مرج
#    رف را صریح بنامید: 'refs/heads/*' با مقصد بی‌ستاره «invalid refspec» می‌دهد و
#    این باندل در عمل فقط HEAD دارد (git bundle list-heads)، پس refs/heads/* تهی است.
git bundle list-heads /home/user/chat6-master-recovery.bundle
git fetch /home/user/chat6-master-recovery.bundle HEAD:refs/heads/bundle-chat6
git merge bundle-chat6 --no-ff -m "merge: بازیابی جامع کارهای چت ۶ (مأموریت‌های ۳۶–۴۳)"
```

اگر گام ۴ خطای «تاریخچه‌های نامرتبط/بدون پایهٔ مشترک» داد (کلون کم‌عمق):

```bash
git fetch --unshallow origin   # یا: git fetch --depth=1000 origin main
git merge bundle-chat6 --no-ff
```

## ۳) اگر main جلو رفته باشد (ری‌بیس)

اگر از زمان پایهٔ باندل (`a30fb20`) کامیت‌هایی به مِین اضافه شده‌اند:

```bash
# الف) ترجیح: مرج (تاریخچه حفظ می‌شود، تعارض یک‌بار حل می‌شود)
git merge origin/main            # روی شاخهٔ بازیابی

# ب) جایگزین: ری‌بیس (تاریخچه خطی؛ فقط اگر ناظر تأیید کند)
git rebase origin/main
#   تعارض هر کامیت را حل کنید؛ در تعارض‌های مستندات، قاعدهٔ «حفظ دوطرفه» حاکم است:
#   - هندآف: هر دو ورودی بمانند (جدیدترین اول)
#   - قفل‌ها: جدیدترین فریز برنده؛ بقیه تاریخی می‌مانند (هرگز دو مانیفست را دستی نچسبانید)
```

پس از حل تعارض، **چهار گیت** را اجرا کنید (بدون استثنا — `PUSH_RECOVERY_PLAYBOOK.md` §۴):
دود ۵۴۷ · مجوز ۰ · راز ۱۱/۱۱ · بیلد ۰. سپس پوش و پی‌آر:

```bash
git push origin chat6-master-recovery
gh pr create --title "recovery: بازیابی جامع چت ۶ (مأموریت‌های ۳۶–۴۳)" --base main \
  --body "ورود از باندل جامع؛ رأس و شِی‑۲۵۶ در گزارش مأموریت ۴۳. گیت‌ها سبز."
```
