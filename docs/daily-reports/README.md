# گزارش روزانه — پوشهٔ رسمی وضعیت پروژه (قرارداد جدید)

> **این پوشه تنها مرجع رسمی وضعیت پروژه است.**
> از ۲۰۲۶-۰۹-۱۲ به بعد، هر Arena / چت / موج، گزارش روزانهٔ خود را این‌جا می‌گذارد و
> **بازبین مستقل فقط همین پوشه را پایش می‌کند** (نه گفتگوها، نه اسناد پراکنده).

## ساختار

| فایل | نقش |
|---|---|
| `README.md` | همین قرارداد — ساختار، فرمت، قوانین |
| `YYYY-MM-DD.md` | گزارش روزانهٔ هر روزِ فعال (یک فایل در روز) |
| `ROADMAP.md` | نقشهٔ راه ۲۴گامی + وضعیت موج‌ها + حکم کلی (NO-GO/GO) + درصد پیشرفت واقعی |
| `NEXT_ACTIONS.md` | اقدامات بعدی اولویت‌بندی‌شده (P0 → P1 → P2) با مالک و معیار قبولی |

## قوانین (نقض‌ناپذیر)

1. **وضعیت‌ها صریح‌اند:** هر ادعا یکی از `PASS` / `FAIL` / `SKIP` (قید محیط) / `NOT-RUN` (هنوز اجرا نشده) / `BLOCKED` (مانع خارجی) است. **سبزِ جعلی ممنوع** — تستی که اجرا نشد هرگز PASS گزارش نمی‌شود.
2. **هر ادعا Evidence دارد:** دستور + خروجی واقعی + ‏SHA کامیت + شمارهٔ PR. عدد بدون دستور اجراشده = ادعای بی‌اعتبار.
3. **پوشِ انجام‌نشده هرگز «پوش‌شده» گزارش نمی‌شود؛** وضعیت پوش شامل SHA از `git ls-remote` است یا صریحاً `BLOCKED`.
4. **امنیت اعتبارنامه:** توکن/PAT هرگز در گزارش، کامیت، یا فایل مخزن نوشته نمی‌شود.
5. هر گزارش روزانه باید بخش **«یافته‌هایی که خودم رد کردم/اصلاح کردم»** داشته باشد (خودبازبینی).
6. گزارش روزانه با قالب استاندارد Arena (پایین همین فایل) بسته می‌شود.

## فرمت گزارش روزانه (الگوی الزامی)

```markdown
# گزارش روزانه — YYYY-MM-DD
## خلاصهٔ اجرایی (۳–۵ خط)
## جدول گیت‌ها (دستور + خروجی واقعی + وضعیت)
## وضعیت کارهای امروز (به‌ازای هر کار: PASS/FAIL/SKIP/NOT-RUN + evidence)
## یافته‌های مهم (کمّی، با ریشه‌یابی)
## وضعیت پوش (SHA از ls-remote یا BLOCKED با دلیل)
## باز است / گام بعدی
## قالب Arena (بخش پایانی الزامی — پایین را ببینید)
```

## قالب گزارش Arena (الزامی در پایان هر گزارش روزانه)

```
TASK: / FILES CHANGED: / WHY: / ARCHITECTURAL IMPACT: / DATABASE IMPACT:
SECURITY IMPACT: / PERFORMANCE IMPACT: / NEW TESTS: / ALL TEST RESULTS:
KNOWN LIMITATIONS: / MIGRATION REQUIRED: / ROLLBACK PLAN: / EVIDENCE:
COMMIT: / SHA: / CI RUN: / RAW EVIDENCE:
```

## شاخه‌ها و PRها

- هر تحویل در شاخهٔ جداگانهٔ خودش (`feat/...` یا `docs/...`) با PR قابل ردیابی.
- `main` هرگز مستقیم پوش نمی‌شود؛ مرج فقط با بازبینی.
- وضعیت شاخه/PR در گزارش همان روز با SHA ثبت می‌شود.
