# طرح: ورود با موبایل و مسیر پیگیری نقش

> **وضعیت: طرح — منتظر تأیید. هیچ کدی نوشته نشده.**
> دور ۵۳ (بازنویسی کامل پس از بازبینی کاربر) · کامیت مبنا: `e81fb84`

---

## ۱. جریان — همان‌طور که کاربر توصیف کرد

```
۱. کاربر شمارهٔ موبایل می‌دهد
۲. کد پیامکی می‌رود        ← بعداً به پنل پیامکی وصل می‌شود
۳. کاربر کد را وارد می‌کند
۴. کد درست بود ⇒ وارد می‌شود
۵. نقش دارد؟
   ├─ بله ⇒ نقش‌هایش نمایش داده می‌شود (می‌تواند چند نقش /
   │        چند دانش‌آموز باشد)
   └─ نه  ⇒ «هیچ نقشی برای شما تعریف نشده» + دکمهٔ [پیگیری]
```

### مسیر پیگیری

```
[پیگیری] ⇒ «نقش شما چیست؟»
           زیرنویس: «اگر چند نقش دارید، فقط یکی را بزنید»
              │
              ├─ دبیر · دانش‌آموز · ولی   ⇒ به مدیر مدرسه
              └─ مدیر · رئیس اداره        ⇒ به سوپرادمین
              │
      استان → شهرستان → منطقه/روستا
              │
      ┌───────┴────────┐
   ولی/دانش‌آموز      دبیر
   + مقطع            (بدون فیلتر مقطع)
   + پایه            زیرنویس: «اگر در چند مدرسه
   + جنسیت            درس می‌دهید، یکی کافی است»
      └───────┬────────┘
              │
   فهرست مدارس منطبق ⇒ کشویی + جست‌وجو
              │
   پیام کامل به مدیر (یا سوپرادمین) برای پیگیری
```

## ۲. 🔴 تفاوت مهم با نسخهٔ پیشین — نیاز به تصمیم

**در این توصیف، مرحلهٔ «کد ملی + شاهکار» نیامده.** جریان از کد
پیامکی مستقیم به ورود می‌رود.

⚠️ **این با تصمیم قبلی خودتان تناقض دارد:** در دور ۵۲ تصریح
کردید «کسی که کد ملی با شماره‌اش نخواند کاربر غیرقانونی است و
اصلاً نباید وارد شود — سیم‌کارت حتماً باید به نام خودش باشد».

**سه حالت ممکن است:**

| حالت | معنی | پیامد |
|---|---|---|
| **الف** | کد ملی حذف شده | 🔴 مالکیت سیم‌کارت سنجیده نمی‌شود — تصمیم دور ۵۲ لغو می‌شود |
| **ب** | فقط خلاصه مرور کرده‌اید | کد ملی سر جایش می‌ماند (پس از کد پیامکی، بار اول) |
| **ج** | فقط برای کاربر ناشناس | اگر شماره در پایگاه داده باشد کد ملی نمی‌خواهیم |

🔴 **پیشنهاد من: حالت (ب).** دلیلش این است که در مسیر پیگیری،
خودتان نوشتید «شماره موبایل **و کد ملی** برای پیگیری به مدیر
ارسال شود» — یعنی کد ملی جایی گرفته شده. اگر مرحله‌اش حذف شود،
چیزی برای فرستادن نداریم.

**تا تعیین تکلیف، طرح بر پایهٔ (ب) نوشته شده** و مرحلهٔ کد ملی
پس از کد پیامکی و پیش از ورود می‌آید (بخش ۴).

## ۳. آنچه از قبل هست — سنجیده شد

| نیاز | وضعیت |
|---|---|
| چندنقشی | 🟢 `panelsOf()` + `panelPicker()` کار می‌کنند |
| چند فرزند | 🟢 `viewChildren()` با سوییچ |
| استان/شهرستان | 🟢 `provinces` · `counties` |
| **منطقه/روستا** | 🟢 `districts.kind` از قبل `AREA_KIND={district,village}` دارد |
| مقطع مدرسه | 🟢 `schools.level` |
| جنسیت مدرسه | 🟢 `schools.gender` |
| پایه | 🟢 `classes.grade` (از راه مدرسه) |
| ماندگاری نشست | 🟢 `SESSION_KEY` — فقط `logout` پاکش می‌کند |
| اعلان به مدیر | 🟢 `notifications` |
| تلفن روی کاربر | 🟢 `users.phone` |

🔴 **ولی یک چیز نیست:** هیچ‌جای کد امروز با **شمارهٔ تلفن**
جست‌وجو نمی‌شود. باید ایندکس تازه‌ای ساخته شود
(`idxUserByPhone`) وگرنه ورود در مقیاس ملی کند می‌شود.

## ۴. جریان دقیق پیشنهادی

```
۱. شماره  ⇒ اعتبارسنجی محلی /^09\d{9}$/
۲. کد ۶ رقمی  ⇒ در دمو روی صفحه، در تولید پیامک
۳. تأیید کد  ⇒ محدودسازی نرخ: ۳ تلاش در ۱۰ دقیقه
۴. 🔹 بار اول: کد ملی  ⇒ شاهکار (بخش ۲ منتظر تصمیم)
۵. جست‌وجو:
   الف) کد ملی در users؟  ⇒ نقش‌ها را بده
   ب)  نه ⇒ شماره در users؟ ⇒ 🔴 «شمارهٔ اشتباه» (بخش ۶)
   ج)  هیچ‌کدام ⇒ «نقشی تعریف نشده» + پیگیری
```

## ۵. صفحهٔ «نقشی تعریف نشده»

```
┌─────────────────────────────────────┐
│  هیچ نقشی برای شما تعریف نشده        │
│                                     │
│  اگر باید در سامانه حسابی داشته      │
│  باشید، پیگیری کنید.                 │
│                                     │
│           [ پیگیری ]                │
└─────────────────────────────────────┘
```

**پس از زدن «پیگیری»:**

```
نقش شما چیست؟
اگر چند نقش دارید، فقط کافی است یکی را بزنید.

  [ دبیر ]  [ دانش‌آموز ]  [ ولی ]
  [ مدیر مدرسه ]  [ رئیس اداره ]
```

### فرم بر پایهٔ نقش

| میدان | ولی / دانش‌آموز | دبیر | مدیر / رئیس اداره |
|---|---|---|---|
| استان · شهرستان · منطقه | ✅ | ✅ | ✅ |
| مقطع تحصیلی | ✅ | ❌ | ❌ |
| پایه | ✅ | ❌ | ❌ |
| جنسیت | ✅ | ❌ | ❌ |
| نام دانش‌آموز | ✅ **الزامی** | ❌ | ❌ |
| فهرست مدارس | ✅ فیلترشده | ✅ همهٔ منطقه | ✅ |
| زیرنویس ویژه | — | «اگر در چند مدرسه درس می‌دهید، یکی کافی است» | — |

**فهرست مدارس:** کشویی + جعبهٔ جست‌وجو. با هر تغییر فیلتر،
فهرست خودکار به‌روز می‌شود.

⚠️ **چرا نام دانش‌آموز برای ولی الزامی است؟** شما نوشتید «بگه
اسم دانش‌آموزش چیه و همه‌چیزش برای مدیر شفاف باشه». بدون آن مدیر
نمی‌داند دنبال چه کسی بگردد.

## ۶. 🔴 شمارهٔ اشتباه در مدرسهٔ دیگر — سناریوی ویژه

**خواستهٔ صریح شما:** «امکان دارد یک شماره اشتباهی در مدرسهٔ
دیگری ثبت شده باشد. باید بگردی پیدا کنی در کدام مدرسه ثبت شده و
به مدیر اطلاع بدهی تا اصلاح کند.»

### چه وقت رخ می‌دهد؟

```
کد ملی کاربر در پایگاه داده نیست
   ولی شمارهٔ موبایلش روی کاربر دیگری ثبت است
        ⇓
یعنی مدرسه‌ای این شماره را برای شخص اشتباهی وارد کرده
```

### رفتار پیشنهادی

**به کاربر:**
> این شماره در سامانه برای شخص دیگری ثبت شده است. موضوع به
> مدرسهٔ مربوطه اطلاع داده شد تا بررسی کند.

🔴 **نام آن شخص به کاربر گفته نمی‌شود** — نشت اطلاعات است.

**به مدیرِ آن مدرسه:**
> ⚠️ شمارهٔ `0912***4567` برای «علی رضایی» (دانش‌آموز، کلاس دهم
> تجربی) ثبت شده، ولی شخص دیگری با کد ملی `007***1234` با همین
> شماره تلاش کرد وارد شود. لطفاً بررسی کنید شمارهٔ ثبت‌شده درست
> است یا نه.

⚠️ **این حالت با «نقشی تعریف نشده» فرق دارد** و باید جدا مدیریت
شود — چون یک **خطای دادهٔ موجود** را نشان می‌دهد، نه نبودِ
حساب.

⚠️ **اگر شماره در چند مدرسه ثبت شده باشد**، به **همهٔ** مدیرانش
اطلاع می‌رود.

## ۷. پنل رسیدگی — دو صف جدا

**خواستهٔ شما:** «در پنل‌ها هم باید همچین قابلیتی برای رسیدگی
باشد.»

| نقشِ درخواست‌شده | صف | صفحهٔ تازه |
|---|---|---|
| دبیر · دانش‌آموز · ولی | مدیر مدرسه | `idreq` در منوی مدیر |
| مدیر · رئیس اداره | سوپرادمین | `idreq` در منوی سوپرادمین |

**در هر ردیف:** شماره (ماسک‌شده) · کد ملی · نقش ادعایی · مدرسه ·
نام دانش‌آموز (اگر ولی) · تاریخ · وضعیت

**کنش‌ها:** ✅ ایجاد/تصحیح حساب · ❌ رد با دلیل · ⏸️ در دست بررسی

🟢 **پس از تصحیح مدیر:** کاربر با همان شماره وارد می‌شود و پنل
خودکار بالا می‌آید — چون `SESSION_KEY` می‌ماند و نقش تازه در
`panelsOf()` دیده می‌شود. **کار اضافه‌ای لازم نیست.**

## ۸. مدل داده

```js
/* جدول تازه: identity_requests */
{
  id, phone, national_id,
  claimed_role,          // 'teacher'|'student'|'parent'|'manager'|'edu_office'
  province_id, county_id, district_id,
  level, grade, gender,  // فقط برای ولی/دانش‌آموز
  student_name,          // فقط برای ولی
  school_id,             // مدرسهٔ انتخابی
  routed_to,             // 'manager'|'superadmin'
  status,                // 'pending'|'in-review'|'approved'|'rejected'
  created_at, decided_at, decided_by, note
}

/* جدول تازه: phone_conflicts — سناریوی بخش ۶ */
{
  id, phone, claimed_nid,
  existing_user_id, school_id,
  status,                // 'open'|'resolved'
  created_at, resolved_at, resolved_by
}

/* افزوده به users */
phone_verified_at
nid_verified           // 0|1

/* افزوده به app_settings */
auth_mode              // 'password'|'phone' — سوییچ امن
```

⚠️ **`auth_mode` حیاتی است:** ورود فعلی نباید حذف شود. دمو با
۱۱۳۶ کاربر نمونه کار می‌کند و حساب‌های آزمایشی لازمند.

## ۱۰. 🔴 هشدارهای امنیتی

| ریسک | در دمو | روز تولید |
|---|---|---|
| کد تأیید روی صفحه | عمدی، برچسب‌دار | 🔴 **باید حذف شود** — آزمون نگهبان لازم است |
| تصمیم ورود در مرورگر | مثل امروز | 🔴 سمت سرور |
| محدودسازی نرخ | محلی، دور زدنی | 🔴 سمت سرور |
| نشت نام از شمارهٔ اشتباه | ماسک می‌شود | همان |
| شمارش کد ملی | پاسخ یکسان | همان |
| نشست بی‌انقضا | عمدی | 🔴 `Max-Age=28800` |

⚠️ **پیام خطا باید یکسان باشد.** اگر بگوییم «این کد ملی نیست»،
مهاجم می‌تواند کد ملی‌ها را بشمارد.

⚠️ **کد ملی در اعلان مدیر:** شما خواستید کد ملی برای پیگیری
فرستاده شود. این لازم است، ولی 🔴 **کد ملی در پیامک نباید
برود** (قاعدهٔ دور ۴۲). فقط اعلان درون‌سامانه‌ای.
