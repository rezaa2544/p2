## ۱) سنجشِ بودجه — اول و آخرِ هر نشست

معیارِ درست، «حجم روی دیسک» نیست؛ **حجمی است که در snapshot ذخیره می‌شود.** این
دایرکتوری‌ها هرگز در snapshot نمی‌آیند و نباید در بودجه شمرده شوند:
`.cache` · `.local` · `.arena` · `.npm` · `node_modules` · `dist` · `build` · `out` ·
`target` · `coverage` · `__pycache__` · `.venv` · `.next` · `.turbo` · `.pytest_cache` ·
`.ruff_cache` · `.mypy_cache` · `.nox` · `.nuxt` · `.output` · `.parcel-cache` ·
`.svelte-kit` · `.tox` · `.vite`
(و مسیرهای حساس: `.git/config` · `.git/credentials` · `.netrc` · `.git-credentials`).

**دستورِ سنجشِ درست** (دامنهٔ مؤثر، بدونِ دایرکتوری‌های بالا):

```bash
python3 - <<'PY'
import os
EX={'.arena','.cache','.local','.mypy_cache','.next','.nox','.npm','.nuxt','.output',
    '.parcel-cache','.pytest_cache','.ruff_cache','.svelte-kit','.tox','.turbo','.venv',
    '.vite','__pycache__','build','coverage','dist','node_modules','out','target'}
SENS={'.git/config','.git/credentials','.netrc','.git-credentials'}
tot=n=0
for root,dirs,files in os.walk('/home/user'):
    dirs[:]=[d for d in dirs if d not in EX]
    for f in files:
        rel=os.path.relpath(os.path.join(root,f),'/home/user')
        if rel in SENS: continue
        try: tot+=os.path.getsize(os.path.join(root,f)); n+=1
        except OSError: pass
print('مؤثر: %.1f MB در %d فایل' % (tot/1048576, n))
PY
```

**آستانه‌ها:** 🟢 زیر ۱۰۰MB و زیر ۸٬۰۰۰ فایل · 🟡 ۱۰۰–۱۲۰MB (پاک‌سازی فوری) ·
🔴 بالای ۱۲۰MB (توقفِ کارِ محتوایی تا پاک‌سازی).

## ۲) کلونِ یگانه

- **یک کلونِ کانونیکال:** `/home/user/p2`. کلون دوم/سوم (از جمله `wave22-*`، `stagin`،
  `verify-*`، `replay-manifest`) ممنوع؛ اگر لازم شد، **موقت** و همان نشست حذف شود.
- **حداکثر ۲ checkout هم‌زمان** (کلون + یک worktree برای اثباتِ قرمز یا آدیت).
  هر worktree پس از مرج/پایانِ کار حذف شود (`git worktree remove --force`).
- کارِ جدید روی **شاخهٔ تازه از `main`**؛ مرج به `main` فقط از مسیر مرج و پس از سبزیِ گیت‌ها.

## ۳) قبل از عملیات پرریسک

- **push پیش از هر پاک‌سازی/reset:** هیچ پاک‌سازیِ دروازه‌دار بدونِ `git ls-remote`
  یا ردیفِ رجیستری یا تطبیقِ sha256 انجام نمی‌شود.
- **باندل‌سازیِ کارِ پوش‌نشده:** پیش از reset/rebase پرریسک، `git bundle create` +
  `git bundle verify`؛ باندل در مسیری **بیرونِ** کلون نگه داشته شود.
- **پشتیبانِ درختِ آلوده:** `git diff > dirty.diff` + `tar` از اقلامِ یگانه، سپس
  عملیات. (اقلامِ یگانه، در صورت نبود در هیچ ref، **حذف نمی‌شوند** — منتقل می‌شوند
  و در گزارش ثبت می‌گردند.)

## ۴) حذفِ دروازه‌دارِ باندل‌های loose

یک باندلِ loose فقط وقتی حذف می‌شود که **هر چهار** شرط برآورده باشد:

1. `git bundle verify` سالم باشد؛
2. `sha256` آن با مانیفست/رجیستری مطابقت کند؛
3. **همهٔ** refهای داخلش روی `origin` باشند — یا عیناً (`ls-remote` برابر) یا
   **جدِ** یک ref پوش‌شده (`git merge-base --is-ancestor`)؛
4. یک ردیفِ رجیستری (`docs/BUNDLE_REGISTRY.md`) داشته باشد **یا** شرطِ ۳ کامل باشد.

حذف‌ها در `docs/BUNDLE_REGISTRY.md` («حذف‌های ثبت‌شده») ثبت می‌شوند تا بازیابی
همیشه ممکن باشد. **بازیابی = `git clone` از origin یا بازتولید با
`git bundle create <نام> <refها>`.**

## ۶) node_modules

فقط اگر **همین نشست** تست اجرا می‌کند بماند؛ در غیر این صورت حذف شود و دستورِ

## ۷) گزارش‌ها فقط داخلِ ریپو

هیچ گزارشِ Markdown در ریشهٔ ورک‌اسپیس رها نمی‌شود. مقصد:
`docs/daily-reports/<YYYY-MM-DD>.md` (بخشِ همان چت/موج) + در صورت نیاز زیر `docs/`.
خروجیِ باندل/patch اجازه دارد در پوشهٔ مستقلِ تحویل (`/home/user/bandle`) باشد،
مشروط به: ثبتِ رجیستری + sha256 + مانیفست.

## ۸) `.git` سنگین

`.git` بخشی از بودجه است. پس از fetchهای سنگین:

```bash
git repack -adf --window=50 --depth=50   # ملایم؛ window=250 در این سندباکس OOM می‌شود
git gc --prune=now                        # فقط پس از تأییدِ پوشِ همهٔ refها
```

حذفِ refهای ریموتِ بی‌استفاده مجاز است **به شرطی** که هر شاخهٔ محلی پیش‌تر
«روی origin برابر یا جد» تأیید شده باشد؛ فهرستِ refهای حذف‌شده در پشتیبانِ
همان نشست نگه داشته می‌شود.
