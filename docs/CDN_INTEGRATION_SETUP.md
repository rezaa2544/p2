# یکپارچه‌سازیِ CDN (POC در سطحِ ملی)

> **وضعیت:** POC (ورکر + مانیفست + سند) — هیچ دامنه‌ای پشتِ CDN نرفته و origin
> دقیقاً مثلِ قبل سرو می‌دهد (`Cache-Control: no-cache` دست‌نخورده).
> این سند می‌گوید «CDN رویِ این معماری دقیقاً چه می‌خواهد» — نه اینکه «الان داریم».

## ۰. قیدهایِ معماری (چرا این POC شکلِ خاصی دارد)

| # | واقعیت | نتیجه |
|---|---|---|
| C1 | بیلد **تک‌فایل** است (`index.html` + فونتِ data-URI؛ صفر ساب‌ریسورسِ خارجی) | «هش در نامِ فایل» (`app.[hash].js`) موضوعیت ندارد — اثرِ انگشت = `cdn-manifest.json` (§۱-۴) |
| C2 | origin برایِ استاتیک `no-cache` می‌فرستد و `server/` در دامنهٔ این POC نیست | رفتارِ کش **فقط در edge** (ورکر) تعریف می‌شود؛ origin دست نمی‌خورد (ریسکِ رگرسیون صفر) |
| C3 | نشست JWT + مسیرهایِ `/api/*` پویا و احرازهستند | ورکر `/api/*` را **هرگز** کش نمی‌کند (passthrough صریح — تستِ C2 نگهبان است) |
| C4 | سطرهایِ immutable یک‌ساله امروز چیزی برایِ کش ندارند (C1) | قانونِ ورکر نوشته و تست شده ولی عملاً رزرو است تا روزی که بیلد بشکافد |

## ۱-۱. انتخابِ CDN

| گزینه | داوری |
|---|---|
| **Cloudflare (پیشنهادِ اصلی)** | پلنِ رایگان + WAF یکپارچه + Worker برایِ منطقِ edge (همین POC) + purge آنیِ تکی‌URL |
| AWS CloudFront | جایگزینِ سازمانی (اگر میزبان AWS شد)؛ بدونِ منطقِ edge در پلنِ پایه (نیازمندِ Lambda@Edge) |
| ArvanCloud (داخلی) | با توجه به تحریم‌ها + اینکه آروان از قبل برایِ Object Storage قفل شده، طبیعی‌ترین گزینهٔ داخلی؛ منطقِ این POC (TTLها + مانیفست) مستقل از vendor است و با تغییرِ اندک رویِ آروان هم می‌نشیند |

پیشنهاد **Cloudflare** است (WAF + Worker + رایگان بودن برایِ شروع)؛
فایلِ `cloudflare/worker.js` مرجعِ اجراییِ رفتارِ edge است.

## ۱-۲. استراتژیِ کشینگ

| نوع فایل | TTL | رفتار | وضعیت در POC |
|---|---|---|---|
| HTML (`/` و `/index.html`) | ۵ دقیقه | ‏`public, max-age=300, must-revalidate`‏ | ✅ ورکر اعمال می‌کند |
| CSS/JS بیلدشده (فرضِ چندفایلی) | ۱ سال | immutable با هش در نام | 📋 رزرو (C1: بیلد چندفایل نیست؛ قانونِ ورکر آماده است) |
| Images | ۱ ماه | ‏`public`‏ | 📋 امروز ساب‌ریسورسِ تصویری نداریم (C1)؛ قانونِ ورکر پوشش می‌دهد |
| Fonts | ۱ سال | immutable | 📋 فونت data-URI و داخلِ فایل است (C1)؛ قانونِ ورکر آماده است |
| `/api/*` | — | **هرگز کش نشود** | ✅ passthrough صریح در ورکر (C3) |

## ۱-۳. تنظیماتِ Cloudflare (ورکر)

مرجعِ اجرایی: `cloudflare/worker.js` (این بخش خلاصه است؛ فایل مبناست):

1. `/api/*` ← ‏`fetch(request)`‏ مستقیم (بدونِ دست‌زدن به هدر/بدنه).
2. پسوندهایِ استاتیک (`js|css|png|jpg|jpeg|svg|woff|woff2`) ←
   ‏`Cache-Control: public, max-age=31536000, immutable`‏ (رزروِ C4، ولی فعال).
3. `/` و `/index.html` ← ‏`Cache-Control: public, max-age=300, must-revalidate`‏.
4. بقیه ← passthrough (صفحاتِ سند، راهنما، ...).

استقرارِ ورکر دستی است (wrangler یا داشبورد — ران‌بوکِ §۱-۵) و عمداً در CI نیست.

## ۱-۴. یکپارچه‌سازی با Build (هش‌گذاریِ سازگار با تک‌فایل)

پرامپت «هش در نامِ فایل» می‌خواست؛ رویِ تک‌فایل، معادلِ درستش **مانیفستِ اثرِ انگشت** است:

- `node build.js` علاوه بر `index.html`، فایلِ قطعیِ `cdn-manifest.json` را می‌نویسد:
  ```json
  {
    "version": 1,
    "sha256_index_html": ["<32>", "<32>"],
    "seal12": "<همان مُهرِ راهنما>"
  }
  ```
- **چرا دو تکه؟** اسکنرِ راز، hex ممتدِ ۶۴تایی را کاندیدایِ کلید می‌داند؛ هشِ عمومیِ
  بیلد با دو تکهٔ ۳۲تایی ذخیره می‌شود تا با secret اشتباه نشود (راستی‌آزمایی join می‌کند).
- **قطعی بودن:** بدونِ timestamp — بازسازیِ صدباره بایت‌به‌بایت یکسان می‌دهد و درخت را کثیف نمی‌کند.
- `node build.js --check` مانیفست را هم راستی‌آزمایی می‌کند (مثلِ مُهرِ راهنما) و سبز می‌ماند.
- **جریانِ invalidate پس از بیلدِ تازه:** بیلد ← sha تازه در مانیفست ← purge تکی‌URLِ `/` در
  پنلِ Cloudflare ← راستی‌آزمایی: ‏`curl -s https://HOST/ | sha256sum`‏ باید با join تکه‌ها برابر شود (§۱-۵، تستِ ۲).

## ۱-۵. تست‌ها

**تستِ ۱ — کشینگِ استاتیک:** پس از استقرارِ ورکر رویِ staging:
`curl -sI https://STAGING/` باید `max-age=300, must-revalidate` بدهد و
`curl -sI https://STAGING/api/health` باید **بدونِ** `max-age` (هدرِ origin) برگردد.
(بدونِ کلاستر: بازخوانیِ منطقِ ورکر + تستِ C1/C2 در ریپو.)

**تستِ ۲ — invalidate پس از بیلدِ تازه:** بیلدِ تازه ← purge تک‌URLِ `/` ← حداکثر ۳۰ ثانیه بعد،
sha256 بدنهٔ گرفته‌شده از edge باید با `cdn-manifest.json` تازه بخواند؛ اگر نخواند، purge ناموفق است.

**تستِ ۳ — پرفورمنس (edge در برابرِ origin):** ده بار `curl -o /dev/null -w '%{time_total}'`
رویِ `/` از یک شهرِ دور (edge) و مستقیم به origin؛ انتظار: میانهٔ edge کمتر از نصفِ origin
(آستانهٔ دقیق پس از نخستین اندازه‌گیری در همین بخش ثبت می‌شود — امروز عددِ ادعایی نداریم).

**تست‌هایِ ریپو (خودکار):** `tests/cdn.js` ‏۵ چک‏ (TTLهایِ ورکر، passthrough ای‌پی‌آی،
هم‌خوانیِ مانیفست با `index.html`، Ingress، ارجاعِ سند) + `tests/cdn-mutations.js` ‏۲ جهش‏.

## ۲. فایل‌هایِ POC

| فایل | نقش |
|---|---|
| `cloudflare/worker.js` | منطقِ edge (TTLها + passthrough ای‌پی‌آی) |
| `k8s/ingress-cdn.yaml` | Ingress مبدأ (TLS + روت؛ کش فقط در ورکر — هشدارِ دولایگی در کامنت) |
| `build.js` (+ ‏`cdn-manifest.json`‏) | تولید + راستی‌آزماییِ اثرِ انگشتِ بیلد |
| `tests/cdn.js` (+ جهش) | گاردِ رفتارِ ورکر و هم‌خوانیِ مانیفست |

## ۳. چک‌لیستِ وصل‌کردنِ CDN (وقتی دامنه آمد)

- [ ] ورکر رویِ staging مستقر و هر ۳ تستِ §۱-۵ سبز.
- [ ] مُدِ TLS تصمیم گرفته شده (Full strict با گواهیِ مبدأ — §۴ ‏DEPLOY‏).
- [ ] قانونِ «هرگز کشِ `/api/*`» با `curl -I` رویِ هر ۳ محیط راستی‌آزمایی شده.
- [ ] runbook purge (تستِ ۲) تمرین شده و sha می‌خواند.

## ۴. آنچه این POC ادعا **نمی‌کند**

- دامنه‌ای پشتِ CDN نیست؛ پنل/اکانت/نیم‌سرور واقعی نداریم.
- immutable یک‌ساله امروز چیزی کش نمی‌کند (C1/C4) — قانون آماده است، ترافیک نه.
- origin همچنان `no-cache` می‌فرستد (عمداً دست نخورد — §۰).
- Ingress بدونِ P5 (دیپلویمنت/سرویس/TLS واقعی) اعمال‌شدنی نیست.
