## ۱. اصول توزیع تدریجی ترافیک (Canary Rollout Strategy)

انتشار بار مدارس در هر استان به ۵ گام استاندارد تفکیک می‌گردد:

```
  0% ────────► 5% ────────► 10% ────────► 25% ────────► 50% ────────► 100%
(خاموش)      (قناری ۱)     (قناری ۲)     (قناری ۳)     (نیمه‌فعال)    (فعال کامل)
```

1. **گام ۵٪ (Canary Stage 1):** بررسی اولیه پاسخ دیتاسنترها، ارزیابی تاخیر اتصالات شبکه و اعتبارسنجی احراز هویت بدون فشار بار.
2. **گام ۱۰٪ (Canary Stage 2):** ورود پایلوت حدود ۳۰ تا ۵۰ مدرسه مصوب، بررسی پایداری کوئری‌های همگام‌سازی و کش ردیس.
3. **گام ۲۵٪ (Canary Stage 3):** ارزیابی صف رویدادهای Outbox، پایش خطاهای احتمالی و بررسی مصرف منابع سرورها.
4. **گام ۵۰٪ (Canary Stage 4):** آزمایش مقیاس‌پذیری نیمه‌بار، ارزیابی پایداری اتصال همزمان دانش‌آموزان و معلمان.
5. **گام ۱۰۰٪ (Full Activation):** اتصال سراسری کلیه مدارس استان و بهره‌برداری کامل.

هرگونه تغییر بین این گام‌ها باید به صورت منقطع و با تاییدیه مستقل اپراتور انسانی ثبت گردد.

## ۲. موتور مهار سرریز ظرفیت (Capacity Guardrails)

پیش از افزایش درصد ترافیک هر استان، تابع `assertCapacityQuota` سه شاخص کلیدی را محاسبه می‌کند:

$$\text{Next RPS} = \text{Current RPS} + \Delta\text{RPS} \le \text{Max RPS}$$
$$\text{Next Sessions} = \text{Current Sessions} + \Delta\text{Sessions} \le \text{Max Concurrent Users}$$

در صورت عبور مقادیر از سقف مجاز، بلافاصله خطای زیر صادر می‌شود:
```
PHASE5_CAPACITY_LIMIT_BREACH: افزایش بار درخواستی از سهمیه استان فراتر است
```

## ۴. کدهای خطای رسمی مصوب و رفتارهای امنیتی

1. `PHASE5_PILOT_SCOPE_VIOLATION`: عبور اداره یک منطقه از حوزه صلاحیت یا فراخوانی استان نامعتبر.
2. `PHASE5_TRAFFIC_POLICY_FAILURE`: ارائه درصد ترافیک نامعتبر خارج از گام‌های ۵، ۱۰، ۲۵، ۵۰ یا ۱۰۰ درصد.
3. `PHASE5_CAPACITY_LIMIT_BREACH`: نقض سقف ظرفیت پردازشی کلاستر یا استان.
4. `PHASE5_ROLLOUT_APPROVAL_REQUIRED`: تلاش برای تغییر ترافیک به صورت خودکار یا بدون تایید انسانی.
5. `ZERO_RANKING_VIOLATION`: وجود هرگونه کلیدواژه یا فیلد مقایسه‌ای و رتبه‌بندی.
