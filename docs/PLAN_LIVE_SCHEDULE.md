**حالت‌های دیگر:**
| وضعیت | نمایش |
|---|---|
| تفریح | `☕ زنگ تفریح — زنگ بعدی ۱۰:۲۰` |
| پیش از مدرسه | `🕗 مدرسه هنوز شروع نشده` |

| تعطیل | `🌙 امروز روز درسی نیست` |
| چند فرزند | یک کارت برای هر فرزند |

### 🔴 دو تصمیم حریم خصوصی

**الف) آیا ولی باید نام دبیر را ببیند؟**
پیشنهاد من: ✅ بله — اطلاعات عمومی برنامهٔ هفتگی است.

**ب) آیا ولی باید وضعیت حضور **همان لحظه** را ببیند؟**
🔴 پیشنهاد من: **با احتیاط.** اگر دبیر هنوز حضور و غیاب نکرده،
نمایش «غایب» غلط و نگران‌کننده است. سه حالت:

```
✅ حاضر               ← ثبت‌شده
❌ غایب               ← ثبت‌شده
⏳ هنوز ثبت نشده      ← نه «غایب»!
```

⚠️ **این مهم‌ترین نکتهٔ این بخش است.** ولی که ببیند «غایب» و
بعد معلوم شود دبیر فقط دیر ثبت کرده، اعتمادش به سامانه می‌رود.

**ج) دیوار پرداخت:** پنل ولی `parentLocked()` دارد. آیا این
کارت هم پشت اشتراک باشد؟ پیشنهاد من: **بله**، مثل بقیهٔ پنل.


## ۶. 🔴 خواستهٔ ۴ — نوتیفیکیشن روی گوشی خاموش

### چرا در معماری فعلی ناممکن است

سنجش کد نشان داد:

```
Service Worker : ❌ ثبت نمی‌شود
manifest.json  : ❌ وجود ندارد
Push API       : ❌ به‌کار نرفته
سرور           : ⚠️ سرور ساخته‌شده است (دورهایِ ۷۳–۷۶) ولی مسیرِ push/نوتیفیکیشنِ خاموشِ گوشی وجود ندارد
```

**نوتیفیکیشن روی گوشی خاموش سه چیز لازم دارد که هیچ‌کدام نیست:**

۱. **Service Worker** — کد پس‌زمینه‌ای که وقتی صفحه بسته است
   اجرا می‌شود. نیازمند میزبانی روی **HTTPS** است؛ روی
   `file://` کار نمی‌کند.
۲. **Push Server** — سروری که پیام را به Firebase (اندروید) یا
   APNs (آی‌اواس) بفرستد.
۳. **اشتراک Push** — کاربر باید اجازه بدهد و مرورگر یک
   `endpoint` یکتا بسازد که روی سرور ذخیره شود.

🔴 **پایش امروز یک فایل HTML تک است که آفلاین کار می‌کند.**
دقیقاً همان چیزی که Push را ناممکن می‌کند.

### سه راه — با هزینهٔ واقعی

| راه | چه می‌دهد | هزینه | محدودیت |
|---|---|---|---|
| **الف) اعلان درون‌برنامه‌ای** | دبیر وقتی برنامه باز است می‌بیند | 🟢 ۰٫۵ روز | گوشی خاموش ⇒ نمی‌بیند |
| **ب) پیامک** | 🟢 روی گوشی خاموش هم می‌رسد | 🟡 ۰٫۵ روز + هزینهٔ پیامک | هزینه‌بر · تأخیر · آزاردهنده |
| **ج) PWA + Push** | ✅ دقیقاً خواستهٔ شما | 🔴 **۵ تا ۸ روز + سرور + HTTPS** | معماری عوض می‌شود |

### 🟢 پیشنهاد من: الف + ب با هم

**سازوکار دو مرحله‌ای:**

```
تلنگر مدیر
   ↓
۱. اعلان درون‌برنامه‌ای فوری (رایگان)
   ↓
۲. اگر دبیر تا ۵ دقیقه ندید ⇒ پیامک
```

**چرا این بهتر است؟**
- ۹۰٪ موارد دبیر برنامه را باز دارد (وسط کلاس است) ⇒ رایگان حل
  می‌شود
- ۱۰٪ باقی‌مانده پیامک می‌گیرند ⇒ هزینه کنترل‌شده
- **زیرساخت پیامک از دور ۴۲ آماده است** (`notifyRequest` با
  صف تأیید و سقف روزانه)

⚠️ **ولی صادقانه بگویم:** این «نوتیفیکیشن روی گوشی خاموش» نیست.
پیامک است. اگر واقعاً نوتیفیکیشن می‌خواهید، راه ج ناگزیر است و
باید **پس از** اتصال سرور انجام شود.

### اگر راه ج را خواستید — پیش‌نیازها

```
۱. سرور با HTTPS و دامنهٔ ثابت
۲. manifest.json + آیکن‌ها
۳. service-worker.js (خارج از index.html — نمی‌تواند inline باشد)
۴. کلید VAPID برای Web Push
۵. جدول push_subscriptions
۶. 🔴 iOS فقط از نسخهٔ ۱۶.۴ به بعد و فقط اگر کاربر
   «افزودن به صفحهٔ اصلی» بزند
```

🔴 **بند ۳ با معماری تک‌فایلی در تضاد است.** Service Worker باید
فایل جدا باشد. یعنی «خروجی نهایی همیشه یک `index.html`» — که
قاعدهٔ ثابت پروژه است — شکسته می‌شود.

⚠️ **این تصمیم معماری است، نه فنی.** باید آگاهانه گرفته شود.

## ۶.۵ پیشنهاد من: چه کار کنیم؟

کاربر پرسید «به نظرت چه کار کنیم؟». پاسخ صریح:

### 🟢 گزینهٔ پیشنهادی: راه الف و ب، الان — راه ج، بعداً

**چرا نه راه ج (نوتیفیکیشن واقعی)؟**

سه دلیل، به‌ترتیب اهمیت:

**۱. سرور ندارید.** کارگر پس‌زمینهٔ مرورگر بدون میزبانی امن
(HTTPS) اصلاً ثبت نمی‌شود. تا سرور نیاید، این راه **فنی
غیرممکن** است نه فقط پرهزینه.

**۲. معماری تک‌فایلی می‌شکند.** کارگر پس‌زمینه باید فایل جدا
باشد. قاعدهٔ «خروجی نهایی همیشه یک `index.html`» از روز اول
پروژه بوده و شکستنش تصمیم بزرگی است.

**۳. کار دورریز می‌شود.** اگر امروز کارگر پس‌زمینه بنویسید،
روز اتصال سرور بیشترش را باید دوباره بنویسید — چون منطق اشتراک
و کلید امنیتی به سرور بند است.

### آنچه امروز شدنی است و ارزش دارد

| کار | چه می‌دهد | هزینه |
|---|---|---|
| اعلان درون‌برنامه‌ای | دبیرِ برنامه‌باز فوراً می‌بیند | ۰٫۵ روز |
| پیامک پس از پنج دقیقه | دبیرِ برنامه‌بسته هم باخبر می‌شود | ۰٫۵ روز |

**در عمل ۹۰٪ موارد را پوشش می‌دهد:** دبیری که باید حضور و غیاب
بزند، معمولاً سر کلاس است و برنامه را باز دارد.

⚠️ **و صادقانه بگویم:** پیامک «نوتیفیکیشن» نیست. صدا نمی‌دهد،
روی صفحهٔ قفل با آیکن برنامه ظاهر نمی‌شود. ولی **می‌رسد** —
حتی وقتی گوشی خاموش است.

### روز اتصال سرور چه کنیم؟

آن‌وقت راه ج معنا پیدا می‌کند و پیش‌نیازهایش هم فراهم است:

```
سرور + HTTPS  →  کارگر پس‌زمینه  →  اشتراک نوتیفیکیشن
                       ↓
        همان تلنگری که امروز پیامک می‌شود،
        آن روز نوتیفیکیشن واقعی می‌شود
```

🟢 **نکتهٔ خوب:** اگر امروز تلنگر را از راه سامانهٔ پیام‌رسانی
موجود بسازیم (فایل: `src/js/44-sms-notify.js`)، روز سرور فقط
**کانال خروجی** عوض می‌شود — منطق تلنگر، سقف روزانه، و ضد اسپم
همه دست‌نخورده می‌مانند.

### خلاصهٔ پیشنهاد

| زمان | کار |
|---|---|
| **الان** | سه نمای زنده + تلنگر دستی با اعلان و پیامک |
| **روز سرور** | همان تلنگر، این بار با نوتیفیکیشن واقعی |
| **هرگز** | کارگر پس‌زمینه پیش از سرور |

## ۶.۷ ✅ تصمیم کاربر (دور ۶۱) — تلنگر با تأیید دریافت

کاربر گفت: «فقط می‌خواهم مدیر یک تلنگر بفرستد طوری که دبیر
متوجه شود. اگر صفحهٔ گوشی خاموش بود با صوت، صفحه را که باز کرد
اعلان پایش نمایش داده شود، و وقتی وارد برنامه شد هم نمایش داده
شود. گزینه‌ای برای جواب به مدیر هم داشته باشد تا مدیر بفهمد
تلنگر را دیده و جواب داده.»

### چه چیزی شدنی است و چه چیزی نه

| خواسته | امروز | روز سرور |
|---|---|---|
| نمایش هنگام باز کردن برنامه | ✅ شدنی | ✅ |
| دکمهٔ پاسخ به مدیر | ✅ شدنی | ✅ |
| مدیر ببیند دیده و جواب داده | ✅ شدنی | ✅ |
| رسیدن پیام وقتی برنامه بسته است | 🟡 با پیامک | ✅ اعلان |
| **صوت روی گوشی خاموش** | 🔴 **ناممکن** | ✅ اعلان |
| **اعلان روی صفحهٔ قفل** | 🔴 **ناممکن** | ✅ اعلان |

🔴 **چرا صوت و اعلان روی صفحهٔ قفل امروز ناممکن است؟**

پایش یک فایل وب است که در مرورگر باز می‌شود. وقتی صفحهٔ گوشی
خاموش است، **هیچ کد جاوااسکریپتی اجرا نمی‌شود** — نه از پایش، نه
از هیچ سایت دیگری. این محدودیت خودِ گوشی است، نه ضعف برنامه.

تنها راهش «کارگر پس‌زمینه» است که به سرور و میزبانی امن نیاز
دارد (بخش ۶).

### 🟢 آنچه امروز می‌سازیم — سه لایه

**لایهٔ ۱ — درون برنامه (فوری، رایگان):**
اگر دبیر برنامه را باز دارد، تلنگر **بی‌درنگ** روی صفحه‌اش
می‌آید — با صدا، چون صفحه باز است و کد اجرا می‌شود.

```
┌────────────────────────────────────────┐
│ 🔔 تلنگر از مدیر                        │
│ لطفاً حضور و غیاب دهم تجربی ۱ را ثبت    │
│ کنید. (زنگ سوم)                        │
│                                        │
│  [ چشم، الان ]  [ کلاس تشکیل نشد ]     │
│  [ دیرتر می‌زنم ]                       │
└────────────────────────────────────────┘
```

**لایهٔ ۲ — هنگام باز کردن برنامه:**
اگر دبیر برنامه را بسته بود، **دفعهٔ بعد که باز کند** تلنگر
منتظرش است — همان کادر بالا، پیش از هر چیز دیگر.

**لایهٔ ۳ — پیامک (اگر تا ۵ دقیقه ندید):**
تنها راهی که روی گوشی خاموش هم می‌رسد.

### پاسخ دبیر — مدیر چه می‌بیند

```
دهم تجربی ۱ · محمدی    ✅ دید و گفت «الان می‌زنم» (۰۹:۳۲)
دهم ریاضی ۲ · احمدی    ⏳ هنوز ندیده (تلنگر ۰۹:۳۰)
یازدهم تجربی · رضایی   ℹ️ گفت «کلاس تشکیل نشد» (۰۹:۳۱)
```

⚠️ **گزینهٔ «کلاس تشکیل نشد» مهم است** — گاهی دبیر حضور و غیاب
نزده چون کلاسی نبوده (اردو، امتحان، تعطیلی موردی). بدون این
گزینه، مدیر گمان می‌کند دبیر کوتاهی کرده.

### مدل داده

```js
/* جدول تازه: nudges */
{
  id, school_id, class_id, teacher_id, manager_id,
  period,              // شمارهٔ زنگ
```
