# تحلیلِ ایستا با ESLint — راهنمایِ نصب، پیکربندی و نگهداشت

> وضعیت: فعال در CI (قدمِ `npm run lint` در `Node.js CI`) — قرارداد: **صفر خطا**،
> ‎~۵۹ هشدارِ مستندِ غیرمسدودکننده.
> آخرین صحت‌سنجی: ۲۰۲۶-۰۹-۰۹ — ‏`lint` خروج ۰ • ‏`--fix` اثبات‌شده • ‏smoke ‏۵۴۷/۵۴۷ • ‏authz صفر ناهماهنگی.

---

## §۰. چهار انحرافِ آگاهانه از پرامپتِ اولیه (چرا؟)

پرامپتِ این تسک برای ESLint 8 نوشته شده بود؛ روی ESLint 10 (فعلیِ ۲۰۲۶) چهار
بندِ آن یا حذف شده یا نگهداشت نمی‌شود. هر انحراف با دلیلِ فنی ثبت است:

| # | پرامپت می‌گفت | اجرا شد | چرا |
|---|---------------|---------|-----|
| ۱ | `.eslintrc.json` | `eslint.config.js` (فرمتِ flat) | فرمتِ eslintrc در ESLint 10 **حذف** شده؛ تنها فرمتِ معتبر flat است |
| ۲ | `.eslintignore` | آرایهٔ `ignores` داخلِ `eslint.config.js` | در فرمتِ flat، فایلِ جدا پشتیبانی نمی‌شود؛ ignores بخشی از کانفیگ است |
| ۳ | `eslint-plugin-node` | `eslint-plugin-n` (فورکِ زنده) | پلاگینِ `node` سال‌هاست به‌روز نمی‌شود؛ `n` همان API با نگهداشتِ فعال است |
| ۴ | `eslint-plugin-import` | حذف شد | ریپو CommonJS تک‌گرافی است (بدونِ import/export)؛ این پلاگین چیزی برای چک‌کردن ندارد و روی وابستگی‌هایِ اختیاری (مثلِ `pg`) مثبتِ کاذب می‌دهد |

نسخه‌هایِ نصب‌شده (۲۰۲۶-۰۹-۰۹، همه devDependency): ‏`eslint ^10.10.0` •
‏`@eslint/js ^10.0.1` • ‏`eslint-plugin-security ^4.0.1` • ‏`eslint-plugin-n ^18.3.0` •
‏`globals ^17.12.0`. نیازمندِ Node ‎≥۲۲ (مطابقِ `engines`).

---

## §۱.۱ نصب

```bash
npm i -D eslint @eslint/js eslint-plugin-security eslint-plugin-n globals
```

وابستگی‌ها فقط توسعه‌اند (در `devDependencies`) و روی بیلدِ محصول (`dist/` و
`index.html`) اثری ندارند. در CI با همان `npm ci` فعلی نصب می‌شوند؛ قدمِ
جدیدی برای نصب لازم نیست.

## §۱.۲ پیکربندی (`eslint.config.js`)

### ساختارِ بلاک‌ها (ترتیبِ فایل)

| بلاک | فایل‌ها | کانتکست |
|------|---------|---------|
| `ignores` | `node_modules`، `dist`، `coverage`، `server/data`، `_guide_shots` | آینهٔ `.gitignore` — خروجیِ بیلد و دادهٔ زمان‌اجرا هرگز لینت نمی‌شوند |
| `js.configs.recommended` | همه | ده‌ها قانونِ error بدونِ استثنا |
| فرانت‌اند | `src/js/**` | گلوبالِ مرورگر؛ ۵ قانون خاموش (علت: ماژول‌ها با `build.js` به‌هم می‌چسبند، پس «تعریف‌نشده» و «بلااستفاده» نویزِ ساختاری است، نه عیب) |
| سرویس‌ورکر | `sw.js` | مرورگر + `serviceworker` |
| ابزارِ اسکرین‌شات | `_shots.js` | node + ‏`no-undef` خاموش (کانتکستِ ترکیبیِ `page.evaluate`) |
| node | `server`، `tools`، `scripts`، `build.js`، خودِ کانفیگ | ‏`sourceType: commonjs` (چون `return` سطح‌بالا در CJS معتبر است) |
| تست‌ها | `tests/**` (به‌جز performance) | node + گلوبالِ `gc` (اجرای smoke با `--expose-gc`) |
| ماژولِ ES | `cloudflare/worker.js` + `tests/performance/**` | ‏`sourceType: module` + گلوبال‌های k6 ‏(`__VU`/`__ITER`/`__ENV`/`open`) |

### جدولِ قوانین (هر سطر = یک تصمیمِ مکتوب)

**سدِ CI (‏error‏):** امروز صفر برخورد؛ هر برخوردِ تازه بیلد را قرمز می‌کند.

| قانون | برخوردِ امروز | نقش |
|-------|---------------|-----|
| `security/detect-eval-with-expression` | ۲ (هر دو با کامنتِ مجوز، §۱.۲.۱) | هر `eval` تازه = خطا |
| `security/detect-child-process` | ۰ | نگهبانِ `exec` با آرگومانِ غیرلیترال (محدودیت: الگویِ `*Sync` را نمی‌بیند — §۲.۳) |
| `n/prefer-global/buffer` و `n/prefer-global/process` | ۰ | ممنوعیتِ `require` کردنِ ماژول‌هایِ سراسریِ node |

**صفِ بازبینی (‏warn‏):** کم‌تعداد و خوانا (~۵۹)؛ غیرمسدودکننده.

| قانون | تعداد | تفسیر |
|-------|-------|-------|
| `security/detect-bidi-characters` | ۴۲ | کاراکترِ LRM تایپوگرافی در کامنت‌های فارسی — بی‌ضرر |
| `security/detect-non-literal-regexp` | ۸ | ساختِ RegExp از رشته در تست‌ها — عمدی |
| `security/detect-possible-timing-attacks` | ۲ | مقایسهٔ مُهرِ محلی در `build.js` (بدونِ مهاجمِ راه‌دور؛ احرازِ سرور timing-safe است) |
| `security/detect-unsafe-regex` | ۲ | `tests/client-features.js` و `tools/check-authz.js` — نیازمندِ بازبینیِ انسانی |
| `security/detect-non-literal-require` | ۲ | هارنسِ داینامیکِ تست + ابزارِ چک — عمدی |
| `n/no-missing-require` | ۱ | ‏`puppeteer` در `_shots.js` نصب نیست (ابزارِ دستی؛ هنگامِ نیاز: `npm i -D puppeteer`) |
| `n/no-deprecated-api` | ۱ | ‏`url.parse` منسوخ در `server/pull.js` — یادآوریِ مدرن‌سازی |
| ۵ قانونِ `security/*` صفربرخورد (`pseudoRandomBytes`، `buffer-noassert`، `new-buffer`، `mustache-escape`، `csrf`) | ۰ | نگهبانِ آینده |

**خاموشِ مستند (‏off‏):** نویزِ اثبات‌شده با دلیل (خلاصه؛ متنِ کاملِ دلیل در
کامنتِ همان سطرِ `eslint.config.js`):

- `security/detect-object-injection` (۹۹۹ برخورد در سبکِ رایجِ `db[coll]`) و
  `security/detect-non-literal-fs-filename` (۴۳۲ برخوردِ `path.join`).
- `no-useless-escape`: گریزِ `\/` قراردادِ امنیتِ HTML درون‌خطی است (ضدِ `</script>`).
- سبکِ تاریخیِ ریپو (`no-var`، `quotes`، `eqeqeq`، `prefer-const`، `semi` و
  فاصله‌گذاری‌ها): هزاران برخوردِ پیشینی؛ یکدست‌سازی کارِ codemod جداگانه است، نه سدِ CI.
- `n/hashbang`: قراردادِ ریپو اجرای با `node file.js` است (۲۰۲ برخوردِ بی‌معنا).
- `no-unused-vars` / `no-empty` / `no-regex-spaces` و مشابه: نویزِ بینِ‌فایلی و تستی؛
  پوششِ رفتاریِ واقعی با smoke و check-authz است.

### §۱.۲.۱ تنها تغییرِ سورس: ۲ کامنتِ مجوز (بدونِ تغییرِ رفتار)

قانونِ `eval` در سطحِ error نگه داشته شد و ۲ برخوردِ واقعی (هر دو در
`src/js/42-self-diagnostics.js`، با شناسه‌هایِ ثابتِ سخت‌کدشده و مجوزِ ممیزیِ X2a)
با کامنتِ موضعیِ `eslint-disable-next-line` مستند شدند. این کامنت‌ها رفتار را
عوض نمی‌کنند ولی باندل را عوض می‌کنند؛ پس `index.html`، مُهرِ `USER_GUIDE.html`
و `cdn-manifest.json` با `node build.js` بازتولید شدند.

## §۱.۳ یکپارچه‌سازی با CI

قدمِ تازه در `.github/workflows/node.js.yml` (پس از `scan:secrets`، پیش از پایان):

```yaml
- run: npm run lint
```

قراردادِ خروج: `eslint .` با **هر خطا** کدِ غیرصفر برمی‌گرداند و بیلد را قرمز
می‌کند؛ هشدارها (warn) خروج را صفر نگه می‌دارند. اسکریپت در `package.json`:

```json
"lint": "eslint ."
```

## §۱.۴ آزمون‌ها (چطور صحتِ لینت اثبات می‌شود)

معماریِ آزمونِ لینت آینهٔ `scan:secrets` است: خودِ ابزار، گیتِ خروج‌کددار است و
نیازی به فایلِ تستِ جدا ندارد. چهار لایهٔ اثبات:

1. **سبزبودنِ پایه:** `npm run lint` باید با `0 errors` و خروجِ ۰ تمام شود
   (وضعِ فعلی: ‏۰ خطا، ۵۹ هشدارِ مستند).
2. **اثباتِ `--fix` (تکرارپذیر):** چون درختِ تمیز خطایِ قابل‌رفعی ندارد، اثبات
   با فیکسچرِ موقت انجام می‌شود — قانونِ `no-extra-boolean-cast` (از مجموعهٔ
   recommended، fixable، صفربرخورد در درخت):
   ```bash
   printf "'use strict';\nlet n = 0;\nif (!!process.env.X) { n += 1; }\nmodule.exports = n;\n" > tools/lint-proof-tmp.js
   npx eslint tools/lint-proof-tmp.js        # 1 error، خروجِ ۱
   npm run lint -- --fix                     # خروجِ ۰؛ «!!x» به «x» تبدیل می‌شود
   rm tools/lint-proof-tmp.js
   ```
   خروجیِ اثباتِ ۲۰۲۶-۰۹-۰۹: خطایِ `Redundant double negation` در سطرِ ۳، پس از
   `‎--fix` به `if (process.env.PAYESH_X)` تبدیل شد و هیچ فایلِ دیگری دست نخورد.
3. **پوششِ رفتاریِ مکمل:** لینت جایگزینِ تست نیست — `node tests/smoke.js`
   (۵۴۷/۵۴۷ روی باندلِ نهایی)، `node tools/check-authz.js` (صفر ناهماهنگی) و
   `node build.js --check` همچنان سدهایِ مستقل‌اند و پس از هر تغییر باید سبز بمانند.
4. **نگهبانِ آینده:** قوانینِ errorِ صفربرخورد (`child-process`، ‏`prefer-global/*`)
   هر الگویِ ناامنِ تازه را در اولین CI قرمز می‌کنند (اثباتِ کارکردِ قانونِ
   child-process با فیکسچرِ `cp.exec("ls " + x)` انجام شد: هشدارِ «non Literal
   first argument» صادر کرد).

## §۲. شواهدِ پیمایشِ تجربی (چرا این پیکربندی؟)

پیکربندیِ نهایی حاصلِ ۴ دور پیمایشِ تمام‌درختی (۳۳۶ فایل) است، نه حدس:

| دور | پیکربندیِ پیمایش | خطا | هشدار |
|----|------------------|-----|-------|
| ۱ | فقطِ `recommended` | ۹۸۷۶ (۸۶۳۶ ‏`no-undef` — اثباتِ نیاز به override فرانت‌اند) | ۰ |
| ۲ | ‏+ ۱۴ قانونِ security و سبک | ۹۰۹۶ | ۷۴۱۳ |
| ۳ | ‏+ بلاک‌هایِ دایرکتوری و k6/serviceworker | ۱ (`gc` در smoke — با گلوبالِ `readonly` حل شد) | ۱۳۳۴۷ (اثباتِ نیاز به خاموش‌کردنِ سبک) |
| ۴ | **پیکربندیِ نهایی** | **۰** | **۶۰** (۵۹ پس از ۲ کامنتِ مجوز) |

### §۲.۱ یافته‌هایِ واقعیِ پیمایش (نه نویز)

- `eval` واقعی فقط در ۲ نقطه (هر دو X2a) — بقیهٔ «eval»ها ارجاعِ متنی‌اند.
- `_shots.js` بدونِ `puppeteer` اجراشدنی نیست (ابزارِ دستیِ مستند).
- `url.parse` منسوخ در `server/pull.js:131`.
- ۲ regex پرهزینهٔ نیازمندِ بازبینی؛ ۴۲ LRM تایپوگرافی (بی‌ضرر)؛ مقایسه‌هایِ
  مُهرِ محلیِ `build.js` (فاقدِ مهاجمِ راه‌دور).
- سورس‌ترکیبیِ `tests/api/*.test.js` با glob ناقص (`tests/*.js`) جا می‌ماند؛
  کانفیگِ نهایی از `tests/**/*.js` استفاده می‌کند.

### §۲.۲ قوانینِ نامزدِ `--fix` که رد شدند (چرا؟)

`prefer-const`، ‏`eqeqeq`، ‏`quotes`، ‏`no-var` ده‌ها تا هزاران برخوردِ پیشینی
دارند (قفل‌کردنشان = بازنویسیِ اجباریِ درخت). `no-unsafe-negation` صفربرخورد
است ولی fixer ندارد (اثباتِ تجربی). برنده: `no-extra-boolean-cast` — صفربرخورد،
fixable، و از recommended.

### §۲.۳ محدودیت‌هایِ اثبات‌شده (شکاف‌هایِ شناخته‌شده)

1. `security/detect-child-process` الگویِ غالبِ ریپو (`execFileSync`/`spawnSync`
   با argv ثابت) را **نمی‌بیند**؛ فقط `exec` مستقیم با آرگومانِ غیرلیترال را
   می‌گیرد (با فیکسچر اثبات شد). پوششِ الگویِ *Sync با بازبینیِ کد و smoke است.
2. قوانینِ خاموشِ سبک (`eqeqeq` و ...) یعنی لینت «سبک» را اعمال نمی‌کند — تصمیمِ
   آگاهانه برایِ جلوگیری از تئاترِ هشدار (هشدارِ هزارتاییِ خوانده‌نشده = تئاتر).
3. `no-undef` در `src/` خاموش است؛ سلامتِ ارجاعِ فرانت‌اند را smoke روی باندلِ
   نهایی تضمین می‌کند، نه لینت.

## §۳. نگهداشت

- **قانونِ صفر خطا:** هر PR که `npm run lint` را غیرصفر کند، مرج نمی‌شود.
  اگر قانونی با کدِ تازه برخورد کرد: یا کد را درست کنید، یا (فقط با دلیلِ مکتوبِ
  درخودِ-سطر، مثلِ مجوزهایِ X2a) ‏`eslint-disable-next-line` موضعی بگذارید.
  خاموش‌کردنِ سراسریِ یک قانونِ error فقط با ثبتِ دلیل در همین سند (§۱.۲) مجاز است.
- **صفِ بازبینی:** هشدارها (~۵۹) را دوره‌ای مرور کنید؛ اگر هشداری به خطایِ واقعی
  تبدیل شد، قانونش را error کنید.
- **ارتقای نسخه:** پس از هر ارتقایِ major/minorِ ‏ESLint یا پلاگین‌ها،
  `npm run lint` را اجرا کنید؛ قوانینِ تازهٔ recommended ممکن است برخوردِ تازه
  داشته باشند (قرارداد: همان روز به صفر برگردانید).
- **فایل‌هایِ تازه:** هر `.js` تازه خودکار زیرِ بلاکِ دایرکتوریِ خودش می‌افتد؛
  اگر دایرکتوریِ تازه‌ای ساختید، بلاکِ متناظر را به `eslint.config.js` اضافه کنید.
