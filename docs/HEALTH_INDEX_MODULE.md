# شاخصِ سلامتِ مدرسه (G.1)

> ابزارِ تحلیلیِ **فقط-سوپرادمین**: امتیازِ ۰–۱۰۰ (بالاتر = بدتر) + رنگ + دلیل،
> به‌ازای هر مدرسه. الگو: `atRiskList` (ترکیبِ چند عامل با وزن) — سمتِ سرور و قطعی.

## ۱. اندپوینت

| متد/مسیر | دسترسی | پاسخ |
|---|---|---|
| `GET /api/health-index` | سوپرادمین | `{ ok, schools: [{ id, name, score, color, factors, reasons }] }` |
| `GET /api/health-index?school_id=N` | سوپرادمین | `{ ok, school, score, color, factors, reasons }` |

- بی‌نشست → `401`، غیرِ سوپرادمین → `403` (+ `audit: authz_failure`)، مدرسهٔ ناموجود → `404`.
- رنگ: `۰–۳۰` سبز (سالم)، `۳۱–۶۰` زرد (هشدار)، `۶۱–۱۰۰` قرمز (توجهِ فوری).

## ۲. عامل‌ها

| عامل | وزن | نمره (۰–۱۰۰، بالاتر = بدتر) | منبع |
|---|---|---|---|
| افتِ حضورِ کادر (۳۰ روزِ اخیر در برابرِ ۳۰ روزِ پیش) | ۲۵٪ | درصدِ افت؛ بدونِ مبنا: سکوت ← ۵۰ِ خنثی، فعالیت ← ۰ | `staff_attendance` (`present/late`) |
| افتِ استفاده از حضور/نمره (همان پنجره) | ۲۵٪ | درصدِ افت؛ مشابه | `attendance` + `grades` |
| تیکتِ باز | ۳۰٪ | هر تیکت ۲۵ تا سقفِ ۱۰۰ | `support_tickets` (`status ≠ closed`) |
| عقب‌افتادگیِ تمدیدِ اشتراک | ۲۰٪ | عقب‌افتاده ← ۱۰۰، به‌روز ← ۰ | — (دادهٔ سطحِ مدرسه نیست) |

**بازتوزیعِ وزن:** عاملی که داده ندارد (فعلاً اشتراک) از مخرج حذف می‌شود و
وزن‌ها روی بقیه بازنرمال می‌شوند؛ دلیلِ حذف در `reasons` ثبت می‌شود.
مثال: فقط ۴ تیکتِ باز و بقیه سالم → ‎`(۱۰۰×۰٫۳۰)/۰٫۸۰ = ۳۸` زرد.

**یادداشتِ داده:** «ورودِ کادر» در `audit` (فایل‌محور) است؛ برای قطعی‌بودن و
سرعت، از `staff_attendance` (حضورِ ثبت‌شده) به‌عنوان پروکسی استفاده شد.
