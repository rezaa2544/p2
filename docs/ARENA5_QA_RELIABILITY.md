# آرنا ۵ — تضمین کیفیت و قابلیت اطمینان (QA & Reliability)

**ویو ۲۰** · به‌روزرسانی: ۱۸/۰۶/۱۴۰۵ (2026-09-09) · وضعیت: فعال
طبق افزودهٔ معماری، آرنا ۵ مالکِ استراتژی تست، رگرسیون، تست بار/فشار،
تست جهش، تست آشوب، اعتبارسنجی بازیابی و **دروازهٔ انتشار** است.

## ۲) استراتژی تست (هرم)

```
                 ┌───────────────────────┐
  دستی/دوره‌ای ←  │  بار/فشار/آشوب (k6)    │  پیش از انتشار و تغییرات زیرساختی
                 ├───────────────────────┤
  هر کامیت ←     │  دودی ۵۴۷ + مجوزها     │  سریع، قطعی، بدون سرور واقعی
                 ├───────────────────────┤
  رگرسیون ←      │  یکپارچگی/سرور/جهش     │  ~۲۴۰ سوئیت با بوت سرور و ایزولاسیون
                 ├───────────────────────┤
  همیشه ←        │  واحد/ساختار (run.js)  │  ساختار، بیلد، آفلاین‌بودن، مدل مجوزها
                 └───────────────────────┘
```

| لایه | ابزار/سوئیت | کی اجرا می‌شود |
|---|---|---|
| واحد/ساختار | `tests/run.js` (ساختار، بیلد، آفلاین، نقش‌ها/روت‌ها) | هر کامیت (CI) |
| دومی (smoke) | `tests/smoke.js` — **۵۴۷ چک** | هر کامیت (CI) + قبل/بعد هر تغییر |
| مجوزها | `tools/check-authz.js` + `tools/generate-write-perms.js --check` | هر کامیت (در `build --check`) |
| امنیت | `tests/secret-scan.js` (۱۱ چک)، `tests/waf-ddos.js`، موج‌های امنیتی (ویو۵/۱۲/۱۳) | هر کامیت (CI امنیتی) |
| یکپارچگی سرور | سوئیت‌های `tests/server*.js` + `tests/api/*.test.js` (۷ سوئیت با دوندهٔ `runner.js`) | رگرسیون کامل |
| جهش | ۷۹ سوئیت `*-mutations.js` — هر منطقِ حساس باید جهش‌پذیر باشد | رگرسیون کامل |
| بار/فشار | `tests/performance/` — k6، آستانه‌های `thresholds.json` (p95/p99/خطا) | پیش از انتشار + تغییرات کارایی (معیار: میانهٔ حضوروغیاب <۶۰۰ms) |
| آشوب/بازیابی | قطع ردیس حین کار (فال‌بک/فیل‌کلوزد بسته به محیط)، بازگردانی پشتیبان | دوره‌ای + پیش از انتشار |

## ۳) نقشهٔ اجرا در CI (GitHub Actions)

| گردشِ کار | پرونده | مراحل | اجرا روی |
|---|---|---|---|
| ‏Node.js CI | `.github/workflows/node.js.yml` | `npm ci` → `npm run build` → `npm test` (= `tests/run.js` + دودیِ ۵۴۷) | هر پوش/پی‌آر به `main` × Node 18/20/22 |
| امنیت | `.github/workflows/security.yml` | تستِ واحدِ ‏WAF، ‏`nginx -t`، نشت‌یابِ راز | هر پوش/پی‌آر به `main` |
| امنیت (در انتظار توکنِ اسکوپ‌دار) | `ci/pending/security-sast-sca.patch` | ‏SAST (CodeQL) + ‏SCA (`npm audit`) | پس از اِعمالِ پچ |

**چرا بقیهٔ ~۲۴۰ سوئیت در خودِ گیت‌هاب‌اکشنز نیستند؟** سوئیت‌های سرور/جهش به
استورِ سیدشده، پورت‌های ثابت و ~۷ تا ۱۸ دقیقه زمان نیاز دارند؛ قراردادِ فعلی:
- **هر کامیت:** گیت‌های سریعِ بالا (همه در همین ریپو اسکریپت دارند).
- **رجرسیون کامل:** `bash scripts/run-all-tests.sh` — خوددرمان (نصبِ جی‌اس‌دام،
  سید، هویتِ گیت)، درختِ کثیف را رد می‌کند (خروجی ۳)، لن‌های ایزوله برای
  سوئیت‌های جهش/سرور و لن سریال برای پورت‌های ثابت؛ از ویو ۲۰ سابت‌های
  ‏`tests/api` را هم می‌پوشاند.
- **پیش از مرج هر پی‌آر:** گزارشِ گیت‌ها در کامیتِ مرج ثبت می‌شود (روالِ چت‌ها).

## ۴) موجودی و قوانینِ نگهداشت

- کشفِ زنده: `run-all-tests.sh` همهٔ `tests/*.js` را می‌خواند؛ سوئیتِ تازه
  خودکار وارد رگرسیون می‌شود — **نیاز به ثبت در هیچ فهرستی نیست**.
- کنارگذاشته‌های طراحی: `tests/server11-child.js` (اسکریپتِ کارگر)،
  `tests/helpers/` (توابع مشترک)، `tests/performance/` (لایهٔ بار — دستی).
- قانون جهش: هر اصلاحِ رفتاری/امنیتی باید همان دور یک جهشِ متناظر داشته
  باشد که کشته می‌شود؛ جهشِ زنده = کار ناقص.
- قانون درخت: رگرسیون فقط روی وضعیتِ کامیت‌شده اجرا می‌شود (پاسماندهٔ جهش
  نتیجه را خراب می‌کند) — اسکریپت درختِ کثیف را خروجیِ ۳ می‌دهد.

## ۶) دروازهٔ انتشار (Release Gate)

پیش از هر ‏Go-Live، **همهٔ** موارد باید سبز باشند؛ هیچ استثنایی بدون تأیید
کتبی ناظر ارشد وجود ندارد:

1. `node tests/smoke.js` → ۵۴۷/۵۴۷
2. `node tools/check-authz.js` → خروجی ۰
3. `node build.js --check` → سبز (بیلد + جدول مجوزها + تطبیق اکشن‌ها)
4. `node tests/secret-scan.js` → ۱۱/۱۱
5. `bash scripts/run-all-tests.sh` → رگرسیون کامل بدون شکست (شامل جهش‌ها و ‏`tests/api`)
6. CI گیت‌هاب (نودِ 22.x تک‌نسخه + گردشِ امنیتی) سبز — ماتریس عمداً باریک شده چون لِین‌های 18/20 با jsdom 30 سبزِ کاذب می‌دادند
7. تست بار: اجرای سناریوی مرجِ `tests/performance/` و برآورده‌شدنِ آستانه‌های
   `thresholds.json` (و میانهٔ حضوروغیاب <۶۰۰ میلی‌ثانیه)
8. اعتبارسنجی بازیابی: یک دورهٔ پشتیبان‌گیری + بازگردانیِ موفق روی محیطِ ایزوله
9. بازبینی امنیتیِ تغییراتِ لبه/مجوز (موج‌های ۵/۱۲/۱۳) در صورت لمس‌شدن
10. به‌روزرسانی `HANDOFF.md` + اسنادِ موجِ مربوط
