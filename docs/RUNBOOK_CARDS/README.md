# کارت‌های ران‌بورد — فهرست و نقشهٔ تصمیم (RUNBOOK_CARDS)

**مخاطب:** on-call در لحظهٔ حادثه · **قانون:** هر کارت یک صفحه (A4، ≤۶۰ خط) · **مرجع کامل:** [پاسخ به حادثه](../INCIDENT_RESPONSE.md)، [ران‌بورد بازیابی](../DR_RUNBOOK.md)، [ران‌بورد تولید](../PRODUCTION_RUNBOOK.md)

> کارت‌ها «سریع‌ترین دسترسی» در اضطرارند: فقط گام‌های ضروری با دستور دقیق و تأیید هر گام. شرح کامل و پس‌زمینه در مرجع‌های بالاست — در لحظهٔ حادثه فقط کارت را دنبال کنید و در پایان، گزارش حادثه را پر کنید.

## نقشهٔ درخت تصمیم: اگر این آلارم → این کارت

- **کش/ردیس دان یا تایم‌اوت کش** → [احیای ردیس](REDIS_REVIVE.md)
- **دیتابیس:**
  - پرایمری غیرقابل‌دسترسی (نوشتن‌ها خوابید) → [فیلاور پستگرس](PG_PRIMARY_FAILOVER.md)
  - داده خراب/حذف اشتباه شد → [بازیابی نقطه‌ای](PG_PITR_RESTORE.md)؛ اگر نقطه‌ای کافی نیست → [بازیابی پشتیبان](BACKUP_RESTORE.md)
- **بلافاصله پس از استقرار خراب شد** → [بازگشت سرویس](SERVICE_ROLLBACK.md)
- **امنیت:**
  - نشست/حساب لو رفته → [ابطال نشست‌ها](SESSION_REVOCATION.md)
  - کلید امضا لو رفته → [چرخش کلید](JWT_SECRET_ROTATION.md)
  - سوءاستفادهٔ الگویی (آی‌پی/کاربر مشخص) → [محدودسازی نرخ](RATE_LIMIT_EMERGENCY.md)
  - ترافیک پخش‌شدهٔ عظیم (>۵×) → [مقابله با دیداس](DDOS_MITIGATION.md)
- **زیرساخت:**
  - دیسک >۹۵٪ → [دیسک پر](DISK_FULL_EMERGENCY.md)

## قاعدهٔ نگهداری

- هر کارت ≤۶۰ خط و خودکفاست؛ تغییر کارت = بازنگری همین سند + بامپ قفل.
- دستورهای هر کارت باید با ابزارهای واقعی ریپو (`tools/`) و پیکربندی واقعی هم‌راستا بمانند؛ تست پوشش، ساختار و فهرست را می‌پاید.
