# E.1 — نمره‌های تئوری/عملی هنرستان (grades)

**وضعیت:** ✅ کامل — دور ۱۰۳ (2026-09-09)، شاخهٔ `arena/01a08545-p2`
**پیش‌نیاز:** مدلِ `kind`ِ دور ۶۹ (نمرهٔ عملی/کارگاهی + دفترِ کارآموزی)

## خلاصه

در هنرستان‌های فنی‌وحرفه‌ای/کاردانش نمرهٔ هر درس از دو قسمت — **تئوری** و
**عملی** — تشکیل می‌شود. این نسخه هر دو قسمت را به‌صورتِ فیلدِ جدا در مدلِ
`grades` نگه می‌دارد؛ **نمرهٔ نهایی (`score`) = میانگینِ قسمت‌هایِ پرشده**
است و رفتارِ همهٔ مصرف‌کننده‌هایِ پیشینِ `score` (معدل، رتبهٔ کلاس،
هشدارهای افت، کارنامه‌ها، آمار) بدونِ تغییر درست می‌ماند.

## مدل داده (grades)

| فیلد | نوع | معنی |
|---|---|---|
| `theoretical_score` | number ۰–۲۰ / null | نمرهٔ تئوری (از ۲۰) |
| `practical_score` | number ۰–۲۰ / null | نمرهٔ عملی (از ۲۰) |
| `is_vocational` | boolean | آیا نمرهٔ رشته‌ایِ هنرستان است؟ |
| `score` | number ۰–۲۰ | **نمرهٔ نهایی** = میانگینِ پرشده‌ها (سازگار با قدیم) |
| `kind` | 'theory'/'practical' | مدلِ دور ۶۹ — دست‌نخورده |

- رکوردِ ترکیبی (نوع «تئوری»): `kind='theory'` + هر دو قسمت +
  `is_vocational=true` + `score=round2((t+p)/2)`.
- رکوردِ واحدِ کارگاهی (نوع «عملی/کارگاهی»): `kind='practical'` +
  `practical_score=score` + `theoretical_score=null` +
  `is_vocational=true` — یعنی رکوردِ دور ۶۹ حالا هم‌پیکرِ فیلدهای تازه است.
- رکوردِ مدرسهٔ غیرکارگاهی: هیچ‌کدام از فیلدهای تازه پر نمی‌شود؛
  `score` مستقیم از فیلدِ «نمره» (رفتارِ پیشین).
- رکوردهای کهنهٔ `kind='practical'` (بدونِ فیلدهای تازه) باز هم درست
  تفسیر می‌شوند (زیر).

## تفسیرِ واحدِ قسمت‌ها — `vocationalParts(g)`

تکین‌نقطهٔ تفسیر در `src/js/13-grades.js`:

```js
function vocationalParts(g){
  if(!g) return null;
  if(g.kind === 'practical')
    return { theory: null, practice: (g.practical_score != null ? g.practical_score : g.score) };
  if(g.theoretical_score != null || g.practical_score != null)
    return { theory: g.theoretical_score, practice: g.practical_score };
  return null;
}
```

→ رکوردِ تازه از خودِ قسمت‌ها؛ رکوردِ کهنهٔ `kind='practical'` از `score`
(سازگاریِ عقب)؛ بقیه `null`.

## فرمِ ثبت/ویرایش (`gradeModal`، `18-modals.js`)

فقط وقتی کلاسِ انتخاب‌شده در مدرسه‌ای با توانِ `workshop` باشد:

- فیلدِ «**نوعِ نمره**» می‌آید:
  - «تئوری» (پیش‌فرض): دو فیلدِ **نمرهٔ تئوری** / **نمرهٔ عملی** (از ۲۰،
    کسری با قدمِ ۰٫۲۵) + یادداشتِ «نمرهٔ نهایی = میانگینِ قسمت‌هایِ پرشده».
    فیلدِ «نمره» **پنهان** می‌شود.
  - «عملی/کارگاهی»: فقط فیلدِ «نمره» (رکوردِ واحدِ کارگاهی — رفتارِ دور
    ۶۹) + قسمت‌ها پنهان.
- جابه‌جاییِ فیلدها هنگامِ تغییرِ نوع: `gradeKindToggle(kind)` + caseٔ
  `g_kind` در شنوندهٔ `change`ِ سراسری (`19-actions-core.js`).
- ذخیره (`grade-save`، سه شاخه):
  1. کارگاهی + عملی: `score` ۰–۲۰ → `{kind:'practical', practical_score:score, is_vocational:true}`
  2. کارگاهی + تئوری: حداقلِ یک قسمتِ ۰–۲۰ → `score=میانگین` +
     `{kind:'theory', theoretical_score, practical_score, is_vocational:true}`
  3. غیرکارگاهی: مسیرِ پیشین بدونِ هیچ فیلدِ تازه (همان پیام‌های پیشین).

## نمایش‌ها

- **فهرستِ نمرات** (`viewGrades`): دو ستونِ جداگانهٔ «**تئوری**» و
  «**عملی**» — فقط برای کلاس‌های کارگاهی (دیدِ مدیر/دبیر از
  `workshopSchool`، دیدِ دانش‌آموز از `workshopStudent`؛ ستونِ «عملی»ِ
  پیشینِ نوع‌نشاننده باقی است).
- **پروندهٔ دانش‌آموز** (`17-student-record.js`): در ردیفِ هر درس، پس از
  نمره‌ها، چیپ‌های «• تئوری x» / «• عملی y» وقتی قسمت‌ها پرند.
- **کارنامهٔ A4** (`reportCardCert`، هر دو قالب کلاسیک/فشرده): دو ستونِ
  جدا «نمرهٔ تئوری»/«نمرهٔ عملی» + میانگینِ سراسری — فقط وقتی دانش‌آموز
  رکوردِ ترکیبی داشته باشد (مدرسه‌های نظری دست‌نخورده).
- **دادهٔ نمونه** (`02-demo-data.js`): پایهٔ آخرِ هنرستان یک نمرهٔ
  ترکیبیِ تئوری ۱۵/عملی ۱۷ دارد (`score=16`) — قطعی.

## دسترسی (authz)

- سه فیلدِ تازه به `authz/model.json` (فامیلِ `grades`) اضافه شدند —
  همان نقش‌های فامیل (دبیرِ درس/کلاس، مدیر، …) و همین قاعدهٔ «فقط کلاس
  خودش». `tools/generate-write-perms.js` اجرا شد (فقط ۳ خطِ تازه).
- `server/validate.js`: قواعدِ تازه — قسمت‌ها مثل `score` (number ۰–۲۰)،
  `is_vocational` → boolean.

## سازگاریِ عقب

- `score` همچنان منبعِ «نمرهٔ نهایی» است؛ هیچ مصرف‌کننده‌ای نخوانده شده است.
- رکوردِ کهنهٔ `kind='practical'` بدونِ فیلدهای تازه:
  `vocationalParts` عملی را از `score` می‌گیرد.
- فرم/نمایِ مدرسه‌های غیرکارگاهی: دست‌نخورده (آزمونِ V4 + regression
  smoke).
- سوئیتِ `workshop2.js` (۱۲/۱۲) بدونِ تغییر سبز؛ فقط `expectFail`ِ جهشِ
  M4 به‌روز شد (با معنایِ تازه، جهش زودتر — در ردِّ ذخیره — می‌میرد).

## تصمیم‌های باز (برای سوپروایزر)

- **زیرمجموعه‌های عملی** (چند پروژهٔ کارگاهی با نمرهٔ جدا) — فعلاً یک
  مقدارِ عملیِ تجمیعی؛ اگر خواسته شود، فامیلِ جدا `wsubs` (پیش‌نمونه در
  دادهٔ نمونه: `wsubs[1]`).
- **وزن‌دهی** (مثلاً تئوری ۶۰٪/عملی ۴۰٪) — فعلاً میانگینِ سادهٔ
  پرشده‌ها؛ جایِ تغییر فقط فرمولِ شاخهٔ ۲ِ `grade-save` + `vocationalParts`.
- **انتقالِ خودکار** رکوردهای کهنهٔ `kind='practical'` به فیلدهای تازه —
  لازم نیست (تفسیرِ سازگار کافی است)؛ اگر خواسته شود، یک migrate کوچک.
