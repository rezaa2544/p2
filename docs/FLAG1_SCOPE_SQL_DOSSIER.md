> قاعدهٔ ایستا: تغییر مجوزی بدون تصمیم ناظر ممنوع. این سند Evidence دو گزینه
> را کنار هم می‌گذارد. تاریخ: 2026-09-12 (پ۳). PG: embedded 18.4 (پورت 55470،
> دیتادیر روی دیسک واقعی `/opt/pgdata`).

## ۱. مسئله (flag-1 بازبین Devin روی PR #120)

`scopedSchools` در `server/routes/reports.js` دامنهٔ نقش را از **آینهٔ
درون‌حافظه‌ای** (`store.schools` + `policy.js: officeCoversSchool`) می‌سازد.
با هیدراتاسیونِ سقف‌دار (`PAYESH_PG_HYDRATE_LIMIT/SKIP`) آینه ناقص است و
مدرسهٔ بیرونِ آینه در هر ۴ گزارش (و endpoint حضورِ چت ۶ در main) **۴۰۳**
می‌گیرد — «دامنهٔ ناقص»، pre-existing و مستند در `WAVE23_DB_NATIVE_REPORTS.md`
§۹.۲ب.

## ۲. اندازه‌گیری‌ها (Measured — مقیاس staging؛ Target جدا برچسب خورده)

بستر: DB `flag1_bench`، **۲۰۰۰ مدرسه / ۳ اداره (district-scoped) / ۸۰۰۰ کلاس /
۲۰۰,۰۰۰ حضور**، `ANALYZE` اجراشده. scope ادارهٔ ۱ = ۶۶۷ مدرسه.

### ۲.۱ EXPLAIN ANALYZE — گزارش حضور ماهانه (GROUP BY per-school، LIMIT 50)

| گزینه | Planning | Execution | نکته |
|---|---|---|---|
| **الف — فعلی:** `school_id = ANY($ids)` (idها از آینهٔ حافظه) | 0.980ms | **4.024ms** | آرایهٔ ۶۶۷ id روی سیم |
| **ب — SQL:** `JOIN schools s … JOIN offices o` (قید هندسه truthy مثل policy) | 0.496ms | **3.780ms** | هم‌ارزیِ ردیف‌به‌ردیف تأیید شد (`equal rows: true`) |

### ۲.۲ هزینهٔ آرایهٔ id در مقیاس

| سنجه | Measured/Target | مقدار |
|---|---|---|
| `ANY(۲۰۰۰ id)` کل مدارس bench | Measured @2k | 6ms در برابر JOIN: 1ms |
| اندازهٔ سیمِ ۱۰۰k id در هر کوئری | Target @national (محاسبه) | **≈575KB به‌ازای هر درخواست گزارش** |
| آینهٔ schools در حافظه @100k مدرسه | Target @national (اندازهٔ ردیف دمو 626B) | ≈60MB |
| آینهٔ users @10M کاربر | Target @national (225B/ردیف) | ≈2.1GB — hydration کامل ناممکن؛ یعنی سقف در مقیاس ملی **اجباری** می‌شود و ۴۰۳ی flag-1 از سناریوی sandbox به سناریوی production تبدیل خواهد شد |

### ۲.۳ شمار مدارس در برابر سقف hydration

- seed دمو: ۶ مدرسه — هر سقفی ≥۶ بی‌اثر؛ مشکل در دمو ظاهر نمی‌شود.
- دیتاست ملی (`tools/generate-national-dataset.js`): **۱۰۰,۰۰۰ مدرسه**؛
  الگوی مستند Wave 18 (`s:2000,u:5000`) یعنی آینه فقط **۲٪ مدارس** را دارد →
  ۹۸٪ درخواست‌های گزارشِ اداره/سوپرادمین خارج از آینه = ۴۰۳ نادرست.

## ۳. جدول ریسک/سود

| معیار | الف) ماندن روی آینه (وضع فعلی) | ب) scope-resolution در SQL |
|---|---|---|
| درستیِ دامنه زیر hydration سقف‌دار | ❌ ۴۰۳ برای مدرسهٔ بیرون آینه | ✅ همیشه کامل (منبع حقیقت PG) |
| مقیاس ملی (۱۰M کاربر/۱۰۰k مدرسه) | ❌ آینهٔ کامل ≈2.1GB ناممکن → سقف اجباری → باگ در production | ✅ مستقل از آینه |
| کارایی کوئری | 4.0ms (۶۶۷ id) و بدتر با scope بزرگ + ~575KB سیم @100k | 3.8ms و ثابت (JOIN ایندکس‌پذیر) |
| ریسک تغییر | صفر (کاری نمی‌کنیم) | 🔴 **تغییر مجوزی**: policy مرجعِ ۴۰+ endpoint دیگر است؛ dual-path (SQL برای گزارش‌ها، store برای بقیه) = دو منبع حقیقت authz تا مهاجرت کامل |
| دامنهٔ کار | — | ~۴ endpoint گزارش + سنجه‌های هم‌ارزی policy↔SQL + جهش‌کشی authz؛ سایر مصرف‌کننده‌های `store.schools` جدا می‌مانند |
| سازگاری truthy-check | مرجع (`officeCoversSchool`: قید ۰/'' = بی‌قید) | باید عیناً در SQL بازتولید شود — در بنچ انجام و هم‌ارزی ردیف‌به‌ردیف اثبات شد |

## ۴. پیشنهاد (تصمیم با ناظر)

**گزینهٔ ب — ولی فازبندی‌شده و پس از ACCEPT صریح ناظر:**
1. فاز ب-۱: فقط ۴ endpoint گزارش + `public-report`؛ تابع SQL واحد
   `scopeSchoolIdsSql(session)` با همان truthy-semantics؛ گیت هم‌ارزی
   «policy(store کامل) == SQL» روی PG زنده + جهش‌های authz (حذف هر قید هندسه
   = قرمز).
2. فاز ب-۲ (بعدی): سایر مصرف‌کننده‌های `store.schools` در PG-live.
3. تا آن زمان: ۴۰۳ فعلی زیر سقف = known-issue مستند (env فقط sandbox، هشدار
   بوت، persist خاموش).

دلیل: دادهٔ §۲.۲ نشان می‌دهد مسیر آینه در مقیاس ملی اصلاً قابل نگه‌داشتن
نیست (2.1GB)؛ مسئله «اگر» نیست، «کی» است. اما چون تغییر مجوزی است، بدون
تصمیم ناظر هیچ کدی عوض نشده.
