## ۱. پرسش نخست — ویرایش مشخصات کاربران توسط مدیر

### ✅ پاسخ: بله، آزاد است. سنجیده شد.

| کنش | مجوز |
|---|---|
| ویرایش کاربر | مدیر · مدیر کل ✅ |
| حذف کاربر | مدیر · مدیر کل ✅ |
| فعال و غیرفعال کردن | مدیر · مدیر کل ✅ |
| بازنشانی رمز | مدیر · مدیر کل ✅ |

**و محدودهٔ مدرسه رعایت می‌شود** — سنجش اجرایی: مدیر مدرسهٔ یک،
۲۴۳ کاربر مدرسهٔ خودش را می‌بیند و کاربران مدرسهٔ دو در فهرستش
**دیده نمی‌شوند**.

### 🔴 ولی یک استثنا لازم است

طبق تصمیم دور ۵۹، مدیر باید بتواند **شمارهٔ موبایل** را عوض کند
ولی **کد ملی نه** — چون کد ملی کلید هویت است. امروز هر دو
آزادند.

⚠️ اگر مدیر بتواند کد ملی را آزادانه عوض کند، می‌تواند کد ملی
خودش را روی حساب دیگری بگذارد و از احراز هویت رد شود.

## ۲. تبدیل غیبت به تأخیر با زمان

### سناریو

```
۰۸:۰۰  کلاس شروع · دبیر حضور و غیاب می‌کند · علی غایب
۰۸:۳۰  علی می‌رسد
        ↓
دبیر غیبت را برمی‌دارد ⇒ باید «تأخیر ۳۰ دقیقه» شود
```

### 🔴 مشکل امروز

رکورد حضور و غیاب **هیچ فیلد زمانی ندارد**:

```
school_id · class_id · student_id · date · status · note · id
```

«تأخیر» فقط یک برچسب است — نمی‌دانیم پنج دقیقه بوده یا پنجاه.

### راه‌حل پیشنهادی

```js
/* افزوده به رکورد حضور و غیاب */
late_minutes    // ۳۰
arrived_at      // '08:30'
```

**محاسبهٔ خودکار:** ساعت شروع زنگ از زمان‌بندی مدرسه گرفته
می‌شود (از دور ۴۱ موجود است) و اختلافش با «اکنون» تأخیر است.

⚠️ **دام:** اگر دبیر ساعت ۱۱ یادش بیفتد که علی ۸:۳۰ آمده،
محاسبهٔ خودکار «۱۸۰ دقیقه» می‌دهد. پس **میدان ساعت ورود باید
قابل ویرایش باشد** با پیش‌فرض «اکنون».

### اثر بر پروندهٔ انضباطی

**خواستهٔ شما:** «از زمان تشکیل کلاس تا آمدن علی در پروندهٔ
انضباطی لحاظ شود».

🔴 **پیشنهاد من: خودکار ثبت نشود.**

| اگر خودکار باشد | مشکل |
|---|---|
| هر تأخیر ⇒ رکورد انضباطی | پرونده پر از رکورد کم‌اهمیت |
| تأخیر ۳ دقیقه‌ای هم ثبت | تفاوتی با ۴۰ دقیقه ندارد |
| دبیر نمی‌تواند قضاوت کند | شاید دلیل موجه داشته |

**جایگزین — دو لایه:**

۱. **تأخیر همیشه در رکورد حضور ثبت شود** (با دقیقه) — دادهٔ خام
   همیشه در دسترس.
۲. **رکورد انضباطی با آستانه و تأیید:** اگر تأخیر از حدی بیشتر
   بود (مثلاً ۱۵ دقیقه)، به دبیر **پیشنهاد** داده شود، نه
   خودکار.

⚠️ **آستانه را مدیر تعیین کند** — هر مدرسه سیاست متفاوتی دارد.

🟢 **گزارش تجمیعی مفیدتر است:** «علی این ماه ۷ بار تأخیر داشته،
جمعاً ۹۵ دقیقه» — بهتر از هفت رکورد جدا.

## ۳. خروج موقت از کلاس

### سناریو

```
دانش‌آموز اجازه می‌گیرد ⇒ دبیر «خروج از کلاس» را می‌زند
                              ↓
                        تایمر شروع می‌شود
                              ↓
              برمی‌گردد ⇒ دبیر «بازگشت» را می‌زند
                              ↓
                    مدت غیبت از کلاس ثبت می‌شود
```

### مدل داده

```js
/* جدول تازه: class_exits */
{
  id, school_id, class_id, student_id,
  date, period,
  out_at,         // '09:35'
  back_at,        // '09:48' یا null
  minutes,        // ۱۳
  reason,         // اختیاری
  by_teacher_id, created_at
}
```

⚠️ **چرا جدول جدا؟** یک دانش‌آموز ممکن است در یک روز **چند بار**
خارج شود. رکورد حضور یکی است، خروج‌ها چندتا.

### 🔴 سه حالت مرزی

**۱. برنگشت و زنگ تمام شد.** هنگام پایان زنگ، خروج‌های باز باید
**خودکار بسته شوند** با نشان «تا پایان زنگ برنگشت» — وگرنه
تایمر تا فردا می‌شمارد.

**۲. دبیر یادش رفت «بازگشت» را بزند.** هنگام ثبت حضور زنگ بعد،
اگر خروج بازی هست به دبیر یادآوری شود.

**۳. زنگ تفریح وسط خروج.** اگر دانش‌آموز پنج دقیقه مانده به
تفریح خارج شود و پنج دقیقه پس از تفریح برگردد، آیا ۲۵ دقیقه
غیبت داشته؟ 🔴 **نه** — زمان تفریح باید کسر شود.

## ۴. 🔴 اصلاح و حذف گزارش‌های ارسالی

### چرا مهم است

شما گفتید «همه‌چیز باید آنلاین باشد و سریع اعمال شود». پیامد
ناخواسته: **خطای دبیر هم سریع منتشر می‌شود.**

### 🟢 آنچه از قبل هست — سنجیده شد

از دور ۴۲ چهار لایهٔ دفاعی هست:

| لایه | چه می‌کند |
|---|---|
| پیش‌نویس | تیک‌ها تا «ثبت نهایی» ذخیره نمی‌شوند |
| مرور نهایی | خلاصهٔ تغییرات پیش از ثبت |
| پنجرهٔ ۲۰ دقیقه | اصلاح دبیر ⇒ پیام معلق خاموش لغو می‌شود |
| اصلاحیهٔ خودکار | اگر پیام رفته، پیام اصلاحی ساخته می‌شود |

و سابقهٔ تغییرات هم هست (چه کسی، کِی، از چه به چه).

### 🔴 آنچه کم است

**الف) صفحهٔ «گزارش‌های من» برای دبیر.** امروز دبیر می‌تواند
حضور و غیاب را عوض کند، ولی **جای متمرکزی ندارد** که ببیند
امروز چه ثبت کرده.

```
📋 گزارش‌های امروز من

دانش‌آموز    نوع        زمان    وضعیت        اقدام
علی رضایی    غیبت       ۰۸:۰۵   ✅ پیامک رفت  [اصلاح]
مریم احمدی   تأخیر ۱۵د  ۰۸:۲۰   ⏳ در صف      [اصلاح]
حسن کریمی    خروج ۱۳د   ۰۹:۳۵   —            [حذف]
```

**ب) تفکیک «حذف» از «اصلاح».**

| اقدام | چه وقت مجاز | اثر بر پیامک |
|---|---|---|
| **اصلاح** | همیشه | معلق ⇒ به‌روز · رفته ⇒ اصلاحیه |
| **حذف** | 🔴 فقط اگر پیامی نرفته | پیام معلق لغو می‌شود |

🔴 **چرا حذف پس از ارسال ممنوع است؟** اگر خانواده پیامک «غیبت»
گرفته و بعد رکورد پاک شود، هیچ ردی نمی‌ماند که چرا آن پیام رفت.
**اصلاحیه باید فرستاده شود، نه پاک‌کردن تاریخ.**

**ج) پنجرهٔ مهلت برای خروج از کلاس** — امروز فقط برای حضور و
غیاب است.

## ۷. 🔴 هشدارها

| ریسک | توضیح |
|---|---|
| ثبت خودکار انضباطی | پرونده پر از رکورد کم‌اهمیت |
| تایمر خروج بی‌پایان | هنگام پایان زنگ خودکار بسته شود |
| کسر زمان تفریح | وگرنه خروج ۵ دقیقه‌ای ۲۵ دقیقه محاسبه می‌شود |
| حذف پس از ارسال پیامک | 🔴 ممنوع — اصلاحیه باید برود |

نظارت شدید می‌دهد. پیشنهاد می‌کنم دلیل خروج **اختیاری** بماند و
در پروندهٔ دائمی ثبت نشود مگر با تصمیم دبیر.
