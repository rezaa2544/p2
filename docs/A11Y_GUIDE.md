# راهنمایِ دسترس‌پذیری (A11y Guide)

این سند قاعده‌هایِ دسترس‌پذیریِ پروژه را جمع می‌کند تا نقض‌هایِ رفع‌شده برنگردند.
مبنا: WCAG 2.1 سطح AA. راستی‌آزمایی: اسکنِ axe-core رویِ DOM زنده (`tests/a11y-runtime.js`)
+ نگهبانِ استاتیک (`tests/a11y-regressions.js`).

## ۱) نامِ دسترس‌پذیر برایِ هر کنترلِ فرم (axe: select-name, label — critical)

هر `<select>`, `<input>`, `<textarea>` باید یکی از این‌ها را داشته باشد:

1. `<label for="…">` مرئی — گزینهٔ ترجیحی وقتی جا هست؛
2. `aria-label="…"` فارسیِ توصیفی — برایِ کنترل‌هایِ فشردهٔ نوارِ فیلتر؛
3. `aria-labelledby` به شناسهٔ متنِ مجاور.

قاعده‌ها:
- متنِ برچسب باید «چه چیزی انتخاب می‌شود» را بگوید، نه نوعِ کنترل: «انتخاب کلاس» ✅، «سلکت» ❌.
- اگر کنترل در حلقه ساخته می‌شود، برچسب باید نمونه را یکتا کند —
  نمونه: چک‌باکسِ چک‌لیستِ فردا ← `aria-label="آماده‌سازی زنگ ۳ — ریاضی"`.
- placeholder برچسب نیست؛ axe آن را نمی‌پذیرد.

## ۲) کنتراستِ رنگ (axe: color-contrast — serious)

متنِ عادی ≥ **4.5:1**، متنِ درشت (≥24px یا ≥18.7px bold) ≥ 3:1.

توکن‌هایِ AA-تأییدشده در `src/styles/base.css` (تغییرشان بدونِ اجرای تست ممنوع):

| توکن | مقدار | کاربرد | کنتراستِ سنجیده |
|---|---|---|---|
| `--green` | `#0a6f46` | متنِ سبز رویِ سفید و پس‌زمینهٔ toast.ok | 6.22 |
| `--red` | `#b7253f` | متنِ قرمز رویِ سفید و پس‌زمینهٔ toast.err | 6.27 |
| `--amber` | `#96590a` | متنِ کهربایی رویِ سفید، toast.warn | 5.63 |
| `--green-text` | `#0a6f46` | متن رویِ `--green-soft` (badge، sync-chip) | 5.61 |
| `--red-text` | `#b7253f` | متن رویِ `--red-soft` | 5.50 |
| `--amber-text` | `#96590a` | متن رویِ `--amber-soft` | 5.12 |
| `--muted` | `#556074` | متنِ کم‌اهمیت رویِ سفید/surface-2 | ≥6.0 |

قاعده‌ها:
- رنگِ متنِ رنگی رویِ پس‌زمینهٔ soft باید از توکنِ `-text` بیاید، نه توکنِ پایه.
- `opacity` زیرِ 0.9 رویِ متن ممنوع — کنتراستِ مؤثر را زیرِ آستانه می‌بَرد
  (تاریخ‌هایِ `class="small muted"` قربانیِ همین بودند).
- سرگروه‌هایِ سایدبار (`.nav-group`) باید رویِ **هر دو سرِ** گرادیانِ تیره ≥ 4.5 بدهند.
- تم‌هایِ ۲ و ۳ `--muted` خودشان را override می‌کنند — تغییرِ تم = اجرای دوبارهٔ تست.

## ۲.۵) مودال‌ها و حالت‌هایِ تعاملی (فاز ۲)

- **فیلدهایِ مودال را همیشه با هلپرِ `f(label, inner)`** (در `src/js/18-modals.js`) بسازید:
  اگر کنترل `id` داشته باشد، خودش `<label for=…>` می‌سازد؛ وگرنه متنِ برچسب را
  `aria-label` می‌کند. **قالبِ خامِ `<label>…</label><input>` بدونِ for ممنوع** —
  همین الگو ۷۴ نقضِ critical در مودال‌ها ساخته بود.
- **ناحیهٔ اسکرول‌شونده** (`.table-wrap`، `.vscroll` یا هر چیزِ overflow-دار) باید برایِ
  صفحه‌کلید دسترس‌پذیر باشد. پاسِ `a11yScrollablePass()` بعدِ هر `render()` و
  `openModal()` خودکار `tabindex=0 + role=region + aria-label` می‌دهد — اگر ظرفِ
  اسکرول‌شوندهٔ نو با کلاسِ دیگری ساختید، یا کلاسِ `table-wrap/vscroll` بدهید یا
  سلکتورِ پاس را گسترش دهید.
- حالتِ خطایِ فرم (`invalid()` → `.has-error` + `.field-error-msg`) و toastها با
  توکن‌هایِ AA سازگارند؛ اگر رنگِ نو به پیام‌ها می‌دهید از §۲ پیروی کنید.
- هارنسِ این حالت‌ها: `tests/a11y-interactive.js` (۱۸ سناریو). مودالِ نو ساختید؟
  یک سناریو اضافه کنید — سناریو باید بازشدنِ واقعیِ مودال را assert کند.

## ۲.۶) ناوبریِ صفحه‌کلید (فاز ۳)

- **مودال**: `openModal` خودش trap و focus اولیه و `role=dialog` را می‌دهد؛
  `closeModal` focus را به بازکننده برمی‌گرداند. **مودال را فقط با این دو تابع
  باز/بسته کنید** — دست‌کاریِ مستقیمِ `#modal.innerHTML` این تضمین‌ها را می‌شکند.
- **skip-link**: نخستین عنصرِ پوسته است (`data-act="skip-to-main"`). حذف یا
  جابه‌جاکردنش WCAG 2.4.1 را می‌شکند و تستِ رگرسیون سرخ می‌شود.
- **عنصرِ کلیک‌پذیرِ غیربومی** (div/span با `data-act`): `tabindex="0"` + نقشِ
  مناسب (role=link/button) بدهید — هندلرِ سراسری Enter/Space را خودش به click
  تبدیل می‌کند، ولی فقط اگر عنصر فوکوس‌پذیر باشد. الگو: `.nav-item`.
- **منو/dropdown سفارشی**: ArrowDown/ArrowUp/Home/End/Escape را پیاده کنید؛
  Escape باید focus را به دکمهٔ بازکننده برگرداند (الگو: پاپ‌اورِ پوسته در
  07-shell). هندلرِ Escape را در فازِ capture ثبت کنید تا Escape سراسری
  (goBack) آن را نبلعد.
- **نشانگرِ فوکوس** (WCAG 2.4.7): برایِ هر عنصرِ فوکوس‌پذیرِ نو `:focus-visible`
  با outline مرئی تعریف کنید.
- هارنسِ رفتاری: `tests/a11y-keyboard.js` (۹۲ چک، کلیدهایِ واقعی). مودال یا
  منویِ نو ساختید؟ سناریو اضافه کنید.

## ۳) الگوهایِ موجودِ درست (دست نزنید)

- دکمه‌هایِ پوسته: `aria-pressed` + `title` دارند (`src/js/07-shell.js`).
- سگمنت/منویِ پوسته: `role="group"` / `role="menu"` + `aria-label`.
- بعدِ هر رندر، مودال‌ها با `closeModal()` بسته می‌شوند تا focus گیر نکند.

## ۴) چک‌لیستِ توسعه‌دهنده پیش از PR

```bash
node tests/a11y-regressions.js   # سریع، بدونِ مرورگر — همیشه
node tests/a11y-runtime.js       # اگر UI یا CSS دست خورده — نیازمندِ playwright
node tests/a11y-interactive.js   # اگر مودال/فرم/toast/سایدبار دست خورده
node tests/a11y-keyboard.js      # اگر مودال/ناوبری/منو دست خورده (رفتار کیبورد)
```

- کنترلِ فرمِ تازه ساختی؟ → برچسب بده و به §1 در `a11y-regressions.js` اضافه کن.
- رنگِ تازه تعریف کردی؟ → جفتِ متن/پس‌زمینه‌اش را به §2 اضافه کن.
- اسکنِ runtime نقضِ تازه گرفت؟ → رفع + کامیتِ جدا + چکِ رگرسیون، مطابقِ `docs/A11Y_RUNTIME_REPORT.md`.

## ۵) نمای ماتریسیِ چندپایه (موج ۲۱)

نمای `multigrade` (`src/js/76-multigrade.js`) جدول‌محور است و همان
قاعده‌های بالا را رعایت می‌کند — اگر آن را دست می‌زنید این‌ها را نشکنید:

- **سرستون‌ها `scope="col"` دارند** — صفحه‌خوان ستونِ «پایهٔ …» را به
  هر خانهٔ سطر وصل می‌کند. ستونِ پایه فقط با رنگ متمایز نیست؛ نامِ
  پایه زیر نام هر دانش‌آموز هم تکرار می‌شود (WCAG 1.4.1 — استقلال از رنگ).
- **هر کنترل برچسبِ فارسی دارد:** انتخابگرهای کلاس/پایه/تاریخ/درس/
  نوبت/نوع آزمون `aria-label` دارند؛ هر ورودیِ نمره
  `aria-label="نمرهٔ ‹نام دانش‌آموز›"` می‌گیرد — جدولِ پُر از input
  بدونِ این برچسب‌ها برای صفحه‌خوان فهرستی از «edit text» بی‌نام است.
- **دکمه‌های سریع `<button>` بومی‌اند** (همان `.att-btn`)؛ Enter/Space
  و فوکوس رایگان است. حالتِ فعال با کلاسِ `on-*` هم رنگ و هم سایه
  دارد (همان الگویِ صفحهٔ حضور).
- **خانه‌های خاموش (`.mg-off`) کنترل ندارند** — سلولِ خالی، نه دکمهٔ
  disabled؛ تا ترتیبِ Tab فقط از کنترل‌های واقعی بگذرد.
- بعد از هر تغییرِ این نما: `node tests/a11y-keyboard.js` (۹۲ چک) و
  `node tests/multi-grade.js` (۳۴ چک) باید سبز بمانند.
