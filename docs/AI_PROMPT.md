# پرامپت جامع پروژه «پایش»
### سند انتقال کامل بافتار (Context Handover) برای هر مدل هوش مصنوعی

> **نحوه استفاده:** کل این سند را در ابتدای گفتگو به مدل بدهید. پس از خواندن، مدل باید بدون نیاز به هیچ سؤال اضافه‌ای بتواند روی پروژه کار کند.

---

## ۰. دستور نقش (Role Instruction)

```
تو یک مهندس ارشد نرم‌افزار هستی که روی پروژه‌ی «پایش» کار می‌کنی — یک سامانه‌ی
مدیریت مدرسه‌ی فارسی/RTL که به‌صورت تک‌فایلی و آفلاین‌محور توسعه یافته است.

قواعد الزامی:
۱. هرگز index.html را مستقیم ویرایش نکن — آن خروجی build است. فقط در src/ تغییر بده.
۲. هیچ فریم‌ورک، کتابخانه یا وابستگی خارجی (CDN، npm در زمان اجرا) اضافه نکن.
۳. هر متن قابل مشاهده باید فارسی باشد؛ هر ورودی کاربر باید با esc() فرار داده شود.
۴. تاریخ‌ها داخلی ISO میلادی ذخیره و فقط هنگام نمایش به شمسی تبدیل می‌شوند.
۵. تغییر داده فقط از طریق insert/update/remove — نه دستکاری مستقیم db.
۶. پس از هر تغییر: npm run build && npm test — هر دو باید سبز باشند.
۷. پاسخ‌ها به فارسی، مستقیم و بدون تعارف. اگر چیزی را نمی‌دانی، حدس نزن؛ کد را بخوان.
۸. هرگز الگوی جستجوی خطی در مسیر رندر ننویس. اگر داخل map/forEach به find نیاز
   داری، اول با idxGroup/idxUnique ایندکس بساز. این قاعده مقیاس ملی را ممکن می‌کند.
۹. هر داده‌ای که نقش کاربر اجازهٔ دیدنش را ندارد، نباید اصلاً به مرورگر برسد.
   محدوده را در 29-scope.js تعریف کن، نه با فیلتر سمت نمایش.
۱۰. ⭐ قاعدهٔ دائمی کاربر: پس از **هر** تغییر در برنامه، همین سند
    (docs/AI_PROMPT.md) را به‌روز کن و نسخهٔ به‌روزشده را در ورک‌اسپیس بگذار.
    این کار اختیاری نیست و باید در همان نوبت انجام شود.
۱۱. قاعدهٔ دو نسخه: هر قابلیت جدید باید هم در نسخهٔ تک‌فایلی و هم در نسخهٔ
    سروری پیاده و تست شود.
```

## ۱. هویت پروژه

| ویژگی | مقدار |
|---|---|
| **نام** | پایش (Payesh) — سامانه هوشمند مدیریت مدرسه |
| **مخاطب** | مدارس ایران، ادارات آموزش‌وپرورش، دبیران، دانش‌آموزان، اولیا |
| **زبان/جهت** | فارسی، RTL، تقویم شمسی (جلالی) |
| **وضعیت فعلی** | **نسخه دمو** — بدون بک‌اند؛ سرور بعداً وصل می‌شود |
| **پشته** | Vanilla JS، صفر وابستگی زمان اجرا، بدون فریم‌ورک |
| **خروجی** | یک فایل `index.html` (~۴۹۹KB) شامل همه‌چیز |
| **حجم کد منبع** | ~۴٬۱۰۰ خط JS در **۲۹ ماژول** + ۳ فایل CSS |
| **داده نمونه** | ۳۲٬۱۵۷ رکورد در ۳۰ مجموعه (~۴.۶MB JSON در حافظه) |

### دو معنای متفاوت «آفلاین» — مهم است اشتباه نشود

| اصطلاح | معنی در این پروژه |
|---|---|
| **تک‌فایلی / بدون وابستگی** | فونت، لوگو، CSS و JS همه داخل فایل جاسازی شده‌اند؛ هیچ درخواست CDN وجود ندارد |
| **Offline-first** ⭐ | **قابلیت اصلی محصول:** دبیری که در مدرسه اینترنت ندارد، حضور و غیاب می‌زند؛ داده روی دستگاه می‌ماند و به‌محض وصل شدن اینترنت خودکار به سرور می‌رود |

مورد دوم دلیل وجودی لایه‌ی `27-sync.js` است.

## ۲. معماری

### ۲.۱ توسعه ماژولار، توزیع تک‌فایلی

```
src/head.html  ─┐
src/styles/*.css├─→  node build.js  ─→  index.html  (تک‌فایلی، قابل توزیع)
src/js/*.js    ─┤                        └─→ dist/payesh.html
src/body.html  ─┘
```

`build.js` فقط **الحاق (concatenation)** انجام می‌دهد — نه ترنسپایل، نه باندلر، نه minify.
به همین دلیل `node build.js --check` می‌تواند تضمین کند خروجی **بیت‌به‌بیت** با نسخه‌ی توزیعی یکسان است.

⚠️ همه‌ی ماژول‌ها در **یک scope مشترک** اجرا می‌شوند (نه ES modules). پس:
- ترتیب در `src/js/_order.json` **حیاتی** است
- نام متغیرها سراسری‌اند — خطر تصادم نام وجود دارد
- `const`/`let` سطح‌بالا روی `window` نمی‌نشینند (نکته‌ی مهم برای تست)

### ۲.۳ جریان اجرا

```
بارگذاری صفحه
      │
      ├─ generate()        ← داده پایه با SEED ثابت (قابل بازتولید)
      ├─ generateExtras()  ← مالی، تقویم، پیام
      ├─ generateP8()      ← امتحانات، کد ملی، چندمدرسه‌ای
      ├─ generateP9()      ← تقسیمات کشوری، ادارات
      ├─ generateP10()     ← اشتراک‌ها
      ├─ loadLog()         ← خواندن تغییرات کاربر از localStorage
      ├─ applyLog()        ← بازپخش روی داده پایه  (SYNC_MUTED=true)
      ├─ initSync()        ← بارگذاری صف ارسال + شنود online/offline
      └─ render()
              │
     ┌────────┴────────┐
 renderLogin      renderShell
                       │
                  renderRoute()   ← switch روی S.route
                       │
                  viewXxx()       ← رشته HTML برمی‌گرداند
                       │
                 کلیک کاربر
                       │
        event delegation روی [data-act]
                       │
                  insert/update/remove
                       │
              applyOp() ──┬─→ log  → localStorage
                          └─→ enqueueOp() → صف همگام‌سازی
                       │
                    render()
```

### ۲.۴ الگوی رندر

رشته‌محور، بدون Virtual DOM:
- هر `viewXxx()` یک رشته HTML برمی‌گرداند
- `$('#root').innerHTML = ...` کل صفحه را بازنویسی می‌کند
- رویدادها با **event delegation** روی `document` مدیریت می‌شوند (`data-act`)
- پس نیازی به اتصال مجدد listener بعد از رندر نیست

**استثنا:** `refreshSyncBadge()` فقط نشانگر همگام‌سازی را جایگزین می‌کند تا رندر کامل لازم نشود.

### ۳.۲ فیلدهای کلیدی

**`users`** — همه‌ی نقش‌ها در یک جدول
```js

  national_id, father_nid, mother_nid, phone, active,
  subject_id, subject, degree, title, job, created_at }
```

**`schools`**
```js
{ id, name, code, level, gender, capacity, active,
  province_id, county_id, district_id, area_kind,   // 'district' | 'village'
  city, address, phone, landline, created_at }
```

**`subjects`** — «درس» و «کتاب» یکی هستند
```js
{ id, school_id, name, code, weekly_hours,
  grade,   // 'اول'…'دوازدهم' یا '' برای عمومی
  field }  // فقط برای پایه‌های دهم تا دوازدهم
```

**`attendance`**
```js
{ id, school_id, class_id, student_id, date /* ISO */,
  status /* present|absent|late|excused */, note }
```

### ۳.۳ لایه‌ی ذخیره‌سازی: Event Log

داده به‌جای ذخیره‌ی مستقیم، به‌صورت **گزارش تغییرات** نگه داشته می‌شود:

```
داده پایه (تولید با SEED ثابت)  +  لاگ تغییرات (localStorage)  =  وضعیت فعلی
```

```js
applyOp({t:'ins'|'upd'|'del', c:'collection', id, data})
insert(coll, obj)      // id خودکار + ثبت در لاگ + ورود به صف sync
update(coll, id, patch)
remove(coll, id)
resetAll()             // پاک کردن لاگ + صف → بازگشت به حالت اولیه
```

**پرچم `SYNC_MUTED`** — حیاتی: هنگام تولید داده نمونه و بازپخش لاگ فعال می‌شود
تا ۳۲ هزار رکورد دمو وارد صف ارسال به سرور نشوند.

**کلیدهای localStorage:**
```
sms_log_v1       لاگ تغییرات
sms_session_v1   نام کاربری جلسه فعال
sms_boss_v1      حساب واقعی هنگام جعل هویت (impersonation)
sms_persona_v1   پنل فعال در حالت چندنقشی
sms_syncq_v1     صف ارسال به سرور
sms_syncmeta_v1  زمان آخرین همگام‌سازی
```

### ۴.۴ سازوکارهای ویژه‌ی ارتباطی

**۱. جعل هویت (Impersonation)**
سوپرادمین می‌تواند وارد پنل مدیر یک مدرسه شود:
```js
S.boss = S.user;  S.user = mgr;   // نوار هشدار بالای صفحه نمایش داده می‌شود
// بازگشت با 'stop-imp'
```

**۲. چندنقشی (Multi-role)**
یک شخص می‌تواند همزمان دبیر و ولی باشد:
```js
panelsOf(u)        // فهرست پنل‌های در دسترس
activePersona()    // S.persona || S.user.role
panelPicker()      // صفحه انتخاب پنل هنگام ورود
```
اتصال با **کد ملی** انجام می‌شود: اگر `student.father_nid === user.national_id`
آن شخص خودکار پنل اولیا هم می‌گیرد (`linkAsParent`).

**۳. تأیید فرزندان (Parent Gate)**
پس از اتصال خودکار، ولی باید تأیید کند:
```
pending → ولی «بله فرزند من است» → confirmed
        → ولی «فرزند من نیست»   → rejected + ثبت در corrections → مدیر مدرسه
```

**۴. دبیر مشترک بین مدارس**
`teacher_schools` — دبیر می‌تواند در چند مدرسه تدریس کند.
سیستم **تداخل زمانی** را تشخیص می‌دهد (`overlapP`) و مانع ابلاغ متناقض می‌شود.

**۵. Paywall اولیا**
```js
parentLocked()  // فقط اگر persona==='parent' && paywall فعال && اشتراک منقضی
// در renderRoute:
if(parentLocked() && !['subscription','notifications','announcements'].includes(S.route))
  return viewLocked();
```
اولین ورود → مهلت تست رایگان خودکار (پیش‌فرض ۲۱ روز، قابل تنظیم در پنل سوپرادمین).

## ۵. برنامه درسی (ماژول `26-curriculum.js`)

قاعده‌ی کلیدی که باید رعایت شود:

| مقطع | پایه‌ها | تفکیک کتاب |
|---|---|---|
| ابتدایی | اول تا ششم | فقط بر اساس **پایه** — مشترک بین همه |
| متوسطه اول | هفتم تا نهم | فقط بر اساس **پایه** — مشترک بین همه |
| **متوسطه دوم** | دهم تا دوازدهم | **بر اساس شاخه و رشته** |

**شاخه‌ها و رشته‌ها (۱۴ رشته):**
```
نظری          : ریاضی فیزیک، علوم تجربی، ادبیات و علوم انسانی، علوم و معارف اسلامی
فنی و حرفه‌ای : الکتروتکنیک، مکانیک خودرو، کامپیوتر، حسابداری، ساختمان، گرافیک
کاردانش       : تعمیر لوازم خانگی، طراحی دوخت، تأسیسات، صنایع غذایی
```

**فرمول متوسطه دوم:** `کتاب‌ها = عمومی مشترک پایه + تخصصی رشته`

**API:**
```js
LEVELS                       // ['ابتدایی','متوسطه اول','متوسطه دوم']
GRADES_OF_LEVEL[level]       // آرایه پایه‌ها
BRANCHES                     // {شاخه: [رشته‌ها]}
levelOfGrade(grade)          // 'دهم' → 'متوسطه دوم'
needsField(level)            // آیا رشته لازم است؟
branchOfField(field)         // 'ریاضی فیزیک' → 'نظری'
booksFor(grade, field)       // → [[نام, ساعت], …]
fieldsOfBranch(branch)
```

در UI دکمه‌ی «📥 افزودن کتاب‌های استاندارد» با انتخاب آبشاری و پیش‌نمایش زنده وجود دارد.

## ۶. لایه Offline-First (ماژول `27-sync.js`) ⭐

**سناریوی هدف:** دبیر در کلاس، بدون اینترنت، حضور و غیاب می‌زند.

```
ثبت حضور  →  applyOp()  →  ┬→ db (فوری در UI دیده می‌شود)
                            ├→ log → localStorage
                            └→ enqueueOp() → صف ارسال → localStorage
                                     │
                          ┌──────────┴──────────┐
                     آفلاین؟                 آنلاین؟
                          │                     │
                  در صف می‌ماند          ارسال + حذف از صف
                          │                     │
              رویداد 'online' ────────→ ارسال خودکار
                                                │
                                     خطا؟ → backoff نمایی
                                            ۲s→۴→۸→…→۵min
```

**وضعیت‌های عملیات:** `pending` → `sending` → `synced` (حذف) / `failed` (تلاش مجدد) / `conflict`

**نشانگر نوار بالا:**

| حالت | نمایش |
|---|---|
| 🟢 | همگام |
| 🟡 | در صف ‹تعداد› |
| ⚫ | آفلاین ‹تعداد› |
| 🔵 | همگام‌سازی… |
| 🔴 | تعارض ‹تعداد› |

**اتصال به سرور واقعی — فقط دو خط:**

## ۷. امنیت

### ۷.۱ وضعیت فعلی — سنجیده‌شده با تست واقعی

| مورد | وضعیت | توضیح |
|---|---|---|
| XSS | ✅ امن | همه‌ی ورودی‌ها با `esc()` فرار داده می‌شوند؛ با payload واقعی در ۷ مسیر تست شد |
| فیلتر جستجو | ✅ امن | بازتاب ورودی هم escape می‌شود |
| دامنه دید نقش‌ها | ✅ درست | دانش‌آموز ۱ کلاس، دبیر ۳ از ۳۶، مدیر فقط مدرسه خود |
| Paywall | ✅ مسدود | دور زدن از طریق route مستقیم کار نمی‌کند |
| `safeHTML()` | ✅ | جلوی نمایش placeholder خام (در صورت دستکاری پروکسی) را می‌گیرد |

### ۷.۲ محدودیت‌های ذاتی نسخه دمو — ⚠️ باید هنگام اتصال سرور رفع شوند

```
❌ رمز عبور متن ساده در db (همه: '123456')
❌ احراز هویت فقط سمت کلاینت — با کنسول مرورگر قابل دور زدن است
❌ همه‌ی داده در حافظه‌ی مرورگر — هر کاربر کل دیتابیس را دارد
❌ paywall سمت کلاینت — سد تجاری واقعی نیست
❌ بدون CSRF/rate-limit/audit trail
```

**اینها باگ نیستند — تصمیم آگاهانه‌ی نسخه دمو هستند.**

### ۷.۳ مهم‌ترین تصمیم امنیتی: محدودسازی داده

اگر سرور کل دیتابیس را به مرورگر بفرستد، یک دانش‌آموز با باز کردن کنسول می‌تواند نمرات، کد ملی و اطلاعات تماس **همهٔ** کاربران را ببیند. **هیچ فیلتر سمت کلاینتی این را حل نمی‌کند.**

راه‌حل در `29-scope.js` تعریف شده — سرور فقط برش مجاز هر نقش را می‌فرستد:

| نقش | آنچه سرور مجاز است بفرستد |
|---|---|
| دانش‌آموز | فقط رکوردهای خودش |
| ولی | فقط فرزندان تأییدشده |
| دبیر | فقط کلاس‌های خودش، پنجرهٔ ۴۵ روزه |
| مدیر | فقط مدرسهٔ خودش |
| اداره | 🔒 **فقط آمار تجمیعی — هیچ رکورد فردی** |
| سوپرادمین | آمار ملی + فهرست صفحه‌بندی‌شده |

**قواعد الزامی سرور:** محدوده از **توکن** تعیین شود نه پارامتر کلاینت؛ هرگز دادهٔ خارج از محدوده فرستاده نشود؛ هر عملیات ورودی از صف sync مجدداً اعتبارسنجی شود.
معماری امنیتی واقعی باید سمت سرور پیاده شود:

```
سرور باید:
  • رمزها را هش کند (bcrypt/argon2)
  • دامنه دید را در هر کوئری اعمال کند (نه اعتماد به کلاینت)
  • JWT/session با انقضا
  • اعتبارسنجی مجدد هر عملیات ورودی از صف sync
  • paywall را در لایه API اعمال کند
  • لاگ حسابرسی برای تغییرات حساس (نمره، مالی)
```

### ۸.۴ لایه ایندکس — `28-indexes.js`

**قاعدهٔ صحت (حیاتی):** هر ایندکس با شمارندهٔ نسخهٔ مجموعه اعتبارسنجی می‌شود. `applyOp` در هر تغییر `idxInvalidate(op.c)` صدا می‌زند، پس ایندکس **هرگز دادهٔ کهنه نمی‌دهد**.

```js
idxGroup(coll, name, keyFn)   // کلید → آرایه رکورد
idxUnique(coll, name, keyFn)  // کلید → یک رکورد
idxInvalidate(coll)           // باطل‌سازی (خودکار از applyOp)
idxReset()                    // پاک‌سازی کامل
idxReport()                   // آمار hit/build برای تشخیص

// ایندکس‌های آماده:
idxById(coll) · idxEnrollByClass() · idxEnrollByStudent() · idxAttByClassDate()
idxAttByStudent() · idxGradesByStudent() · idxScheduleByTeacher() · idxClassesBySchool()

sortByNameFa(list)  // مرتب‌سازی فارسی با Intl.Collator یک‌بارساخته
```

**اثر:** `viewAttendance` در مدرسهٔ ۵٬۰۰۰ نفره از ۶٬۴۲۲ms به **۲ms** رسید (۳٬۲۱۱ برابر).

### ۸.۵ لایه محدودهٔ داده — `29-scope.js`

```js
scopeDescriptor(user, persona)  // دقیقاً چه داده‌ای مجاز است
scopeEstimate(user, persona)    // برآورد حجم برش

```

سرور موظف است محدوده را از **توکن** تعیین کند (نه از پارامتر کلاینت)، هرگز دادهٔ خارج از محدوده نفرستد، و فهرست‌های بزرگ را صفحه‌بندی کند.

### ۸.۶ محافظت از حافظهٔ محلی

`saveLog()` دیگر خطا را بی‌صدا نمی‌بلعد: هشدار در ۸۰٪ ظرفیت، پیام صریح هنگام پرشدن، و تابع `storageFull()`.

ظرفیت آفلاین: هر عملیات ≈ ۴۲۳ بایت ⇒ سقف ۵MB ≈ ۱۲٬۳۸۶ عملیات ≈ **۴۱۲ روز** کار یک دبیر با ۳۰ دانش‌آموز.

| `find` خطی داخل `map` در مسیر رندر | ابتدا ایندکس بساز (`idxGroup`/`idxUnique`) |
| فرستادن کل دیتابیس به مرورگر | فقط برش نقش — `scopeDescriptor` |
| بلعیدن خطای `localStorage` | کاربر باید از پرشدن حافظه باخبر شود |
| افزودن ایندکس بدون باطل‌سازی | `applyOp` خودکار انجام می‌دهد؛ دستکاری نکن |
| تست با یک `eval` چندعبارتی | هر عبارت جدا |

## ۱۵. خلاصه‌ی یک‌پاراگرافی

> «پایش» یک سامانه‌ی مدیریت مدرسه‌ی فارسی/RTL است که با Vanilla JS و صفر وابستگی
> نوشته شده و به‌صورت یک فایل HTML تک‌فایلی (~۴۹۹KB) توزیع می‌شود، اما به‌صورت
> ماژولار در `src/` (۲۹ ماژول) توسعه می‌یابد و با یک اسکریپت الحاق ساده build
> می‌شود که یکسانی بیت‌به‌بیت خروجی را تضمین می‌کند. شش نقش کاربری (سوپرادمین،
> اداره آموزش‌وپرورش، مدیر، دبیر، دانش‌آموز، ولی) با دامنه‌ی دید دو لایه از هم جدا
> شده‌اند. داده در ۳۰ مجموعه با الگوی event-log روی localStorage نگه داشته می‌شود.
> مهم‌ترین قابلیت محصول **offline-first** است: دبیر بدون اینترنت حضور و غیاب می‌زند،
> تغییرات در صفی روی دستگاه می‌مانند و با وصل شدن اینترنت خودکار و با backoff نمایی
> به سرور ارسال می‌شوند. سامانه برای **مقیاس ملی** طراحی شده — ۱۰ میلیون دانش‌آموز
> و ۵ میلیون کاربر همزمان — بر پایهٔ این اصل که **بار هر مرورگر ثابت و مستقل از
> اندازهٔ کشور بماند**: لایهٔ ایندکس (`28-indexes.js`) جستجوی خطی را از مسیرهای داغ
> حذف کرده (حضور و غیاب: ۶٬۴۲۲ms → ۲ms) و لایهٔ محدوده (`29-scope.js`) تضمین می‌کند
> سرور فقط برش مجاز هر نقش را بفرستد (دانش‌آموز ۸KB، مدیر ۱MB). پروژه فعلاً **نسخه
> دمو بدون بک‌اند** است؛ امنیت واقعی (هش رمز، احراز هویت، اعمال محدوده سمت سرور)
> باید هنگام اتصال سرور پیاده شود.
