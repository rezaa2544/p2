# مستندات پایش

این پوشه مرجع مستندات پروژه است. برای شروع، از همین صفحه حرکت کنید.

## مسیر پیشنهادی مطالعه

1. [PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md) — پروژه چیست، چه مسئله‌ای را حل می‌کند و چه خدماتی دارد.
2. [REPOSITORY_MAP.md](REPOSITORY_MAP.md) — هر بخش کجاست و برای تغییر هر موضوع باید به کجا رفت.
3. [ARCHITECTURE.md](ARCHITECTURE.md) — معماری و جریان داده.
4. [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md) — روش اجرای پروژه، توسعه و تغییر امن.
5. [CODE_STYLE.md](CODE_STYLE.md) — قرارداد سبک کدنویسی و سازمان‌دهی ماژول‌ها.
6. [TESTING_GUIDE.md](TESTING_GUIDE.md) — تست، Verification و شواهد.
7. [ENGINEERING_EXECUTION_AND_VERIFICATION_POLICY.md](ENGINEERING_EXECUTION_AND_VERIFICATION_POLICY.md) — قوانین الزام‌آور.
8. [ROADMAP.md](ROADMAP.md) — نقشه راه و وضعیت جاری.
9. [ROADMAP_MASTER_EXECUTION_SCHEDULE.md](ROADMAP_MASTER_EXECUTION_SCHEDULE.md) — برنامه اجرایی تفصیلی.
10. [ROADMAP_CURRENT_GROUND_TRUTH_2026-09-21.md](ROADMAP_CURRENT_GROUND_TRUTH_2026-09-21.md) — حقیقت جاری در آخرین reconciliation.

## دسته‌بندی مستندات

- **شروع و معماری:** PROJECT_OVERVIEW، REPOSITORY_MAP، ARCHITECTURE، ARCHITECTURE_DECISIONS
- **توسعه:** DEVELOPMENT_GUIDE، CODE_STYLE، API_REFERENCE، openapi.yaml
- **تست و امنیت:** TESTING_GUIDE، Engineering Policy، Security و audit
- **عملیات و مقیاس:** CAPACITY_MODEL، SCALE_10M، SLO، DEPLOY و runbookها
- **برنامه‌ریزی:** ROADMAP، Master Schedule، Ground Truth
- **ممیزی و شواهد:** docs/audit/
- **سوابق تاریخی:** گزارش‌های قدیمی و handoffها؛ وضعیت جاری را فقط از Current HEAD و Ground Truth بخوانید.

## قانون مهم

مستندات نباید ادعای پیاده‌سازی را جایگزین کد و evidence کنند. اگر سندی با Current HEAD تعارض دارد، آن تعارض باید ثبت و اصلاح شود؛ گزارش تاریخی به‌تنهایی وضعیت جاری نیست.
