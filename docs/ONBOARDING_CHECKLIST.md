# ✅ ONBOARDING CHECKLIST — چک‌لیست عملی ورود توسعه‌دهندهٔ جدید

**نسخه:** ۱.۰.۰ | **تاریخ:** ۲۰۲۶-۰۹-۱۱ | **مالک:** چت ۶ (مستندساز و مهندس انتشار) | **بازبینی:** فصلی
**مکمل:** `docs/ONBOARDING_NEW_DEVELOPER.md` (مسیر یادگیری روایتی) · `docs/DOCUMENTATION_HANDOVER.md` بستهٔ «الف» · `docs/DOCUMENTATION_MAINTENANCE.md` (نگهداری کتابخانه)

> این چک‌لیست **عملی** است: هر مربع یعنی یک اقدام قابل راستی‌آزمایی. مسیر یادگیری عمیق‌تر
> در `ONBOARDING_NEW_DEVELOPER.md` است؛ اینجا «چه کار کنم، با چه ترتیبی، و چگونه ثابت کنم انجام شد» است.

---

## بخش ۱: روز اول — محیط و نخستین اجرای سبز

**محیط:**

- [ ] نصب Node.js نسخهٔ ۲۲ یا بالاتر (`package.json` → `engines.node >= 22`)
- [ ] نصب PostgreSQL 16 (یا دسترسی به نمونهٔ تیمی)
- [ ] نصب Redis 7 (یا دسترسی به نمونهٔ تیمی)
- [ ] دسترسی گیت‌هاب به `rezaa2544/p2` + شاخهٔ کاری خودتان

**راه‌اندازی:**

- [ ] `git clone` ریپو و ورود به شاخهٔ کاری
- [ ] `npm ci` (نصب دقیق وابستگی‌ها از `package-lock.json`)
- [ ] `node server/seed.js` — کاشت دادهٔ اولیه
- [ ] `node tests/smoke.js` — باید **۵۴۷/۵۴۷** سبز شود؛ هر قرمز = توقف و گزارش (نه دور زدن)
- [ ] `node tools/check-authz.js` — خروجی ۰ · `node tests/secret-scan.js` — ۱۱/۱۱

**جهت‌گیری:**

- [ ] خواندن `SKILLS_MASTER.md` ریشهٔ ریپو (≈ ۱ ساعت) — نقشهٔ مهارت‌ها و قواعد تیم
- [ ] خواندن `docs/DOCS_INDEX.md` — فقط فهرست؛ بدانید «چه چیزی کجاست» (نه خواندن کامل)
- [ ] اتصال به حافظهٔ تیمی روفلو (از بیرون ریپو، با متغیرهای محیطی مربوطه) و بازخوانی کلیدهای وضعیت
- [ ] ثبت «روز اول تمام شد» در `HANDOFF.md` با یک خط

## بخش ۲: هفتهٔ اول — درک معماری و نخستین لمس کد

- [ ] خواندن `docs/NATIONAL_ARCHITECTURE.md` — سند چتر: لایه‌ها، چندمستأجری، ضدالگوها
- [ ] خواندن `docs/DATABASE_ARCHITECTURE.md` — پستگرس تنها منبع حقیقت
- [ ] خواندن `docs/SECURITY_MODEL.md` — مدل امنیت؛ مکمل: `docs/AUTHORIZATION_MODEL.md`
- [ ] اجرای ۵ تست کلیدی و فهم دلیل وجود هرکدام:
  - [ ] `node tests/smoke.js`
  - [ ] `node tests/secret-scan.js`
  - [ ] `node tests/docs-freeze-marker.js`
  - [ ] `node tests/wave1-multi-instance.js`
  - [ ] `node tests/demo-thursday.js`
- [ ] خواندن `docs/DOCUMENTATION_MAINTENANCE.md` — قواعد نگهداری که از امروز مشمول شماست
- [ ] برداشتن یک ایشوی ساده (برچسب‌دار/کوچک) و فهم جریان کار با ناظر
- [ ] ثبت یک‌خطی پیشرفت هفته در `HANDOFF.md`

## بخش ۳: ماه اول — مشارکت مستقل و قابل اعتماد

- [ ] یک پی‌آر کوچک مرج‌شده با همهٔ گیت‌ها (دود ۵۴۷ · مجوز · راز · بیلد) — **بدون هیچ میان‌بُر**
- [ ] خواندن حداقل ۲۵٪ اسناد کتابخانه (ترتیب پیشنهادی: `docs/DOCUMENTATION_HANDOVER.md` بستهٔ «الف»)
- [ ] شرکت در یک مانور یا دریل (بازیابی/آشوب/اعلان) در صورت برگزاری — ثبت تجربه در هندآف
- [ ] آموزش یک موضوع به هم‌تیمی (۱۵ دقیقه هم کافی است) — بهترین آزمون فهم
- [ ] به‌روزرسانی دست‌کم یک سند مرتبط با کار خودتان (قاعدهٔ «هر تغییر کد = تغییر سند»)
- [ ] امضای چک‌لیست تحویل توسط ناظر/مستندساز (چت ۶)

## بخش ۴: مسئولیت‌های جاری (پس از آنبوردینگ)

| چرخه | مسئولیت شما |
|---|---|
| **روزانه** | هر پی‌آر: سند مرتبط به‌روز + دروازه‌ها سبز + بدون راز/دادهٔ شخصی در کد و متن |
| **هفتگی** | مرور خروجی `tools/docs-health.sh` در حوزهٔ خودتان؛ پاسخ به سؤال‌های تازه‌واردها |
| **ماهانه** | مرور `tools/docs-consistency-check.sh`؛ گزارش هر عدد ناسازگار به مستندساز |
| **رویدادمحور** | حادثه/مانور/تصمیم تازه → ثبت فوری در سند مربوط + `HANDOFF.md` |

> **سه خط قرمز تازه‌وارد:** تست را برای سبز شدن ضعیف نکنید · بدون تأیید ناظر مرج نکنید ·
> هیچ سند/تغییر محلی را بدون باندل یا کامیت رها نکنید (سندباکس‌ها ریست می‌شوند).
