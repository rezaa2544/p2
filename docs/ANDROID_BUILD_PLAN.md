## ۱. ارزیابی گزینه‌های معماری و انتخاب روش (Architecture Evaluation)

برای تبدیل سامانه تک‌فایلی و آفلاین‌محور پایش به یک اپلیکیشن بومی قابل انتشار در گوگل‌پلی، سه رویکرد اصلی مورد بررسی قرار گرفت:

```

│                      مقایسه روش‌های بسته‌بندی اندروید برای سامانه پایش                │
├─────────────────────┬────────────────────┬─────────────────────┬───────────────────────┤
│ شاخص ارزیابی        │ Trusted Web Activity│ Capacitor / Cordova │ Native Kotlin/Compose │
│                     │ (TWA / Bubblewrap) │ (WebView Wrapper)   │ (بازنویسی کامل)       │
├─────────────────────┼────────────────────┼─────────────────────┼───────────────────────┤
│ تطابق با سیاست گوگل │ ۱۰۰٪ (استاندارد PWA)│ نیازمند تنظیم دستی  │ ۱۰۰٪                  │
│ حجم بسته خروجی      │ زیر ۳ مگابایت (سبک) │ ۱۵ تا ۳۰ مگابایت     │ ۲۵ تا ۵۰ مگابایت      │

└─────────────────────┴────────────────────┴─────────────────────┴───────────────────────┘
```

**نتیجه انتخاب:**  
روش **Trusted Web Activity (TWA)** بر پایه ابزار رسمی گوگل (**Bubblewrap / Android Gradle**) به عنوان بهترین و پایدارترین راهبرد انتخاب شد. این روش:
1. اپلیکیشن را بدون هیچ‌گونه نوار آدرس مرورگر (Full-Screen Standalone) اجرا می‌کند.
2. از موتور رندرینگ به‌روز و شتاب‌یافته مرورگر کاربر بهره می‌برد.
3. مستقیماً خروجی استاندارد **Android App Bundle (`.aab`)** مطابق با الزامات ۲۰۲۶ گوگل‌پلی تولید می‌کند.

## ۵. اسکریپت بیلد خودکار (`tools/build-android.js`)

اسکریپت بیلد اندروید با اجرای دستور زیر کلیه مراحل را به صورت خودکار انجام می‌دهد:

```bash
npm run build:android
# یا
node tools/build-android.js
```

### وظایف اسکریپت:
1. کامپایل بیلد وب و تولید `dist/payesh.html`.
2. تولید فایل‌های `manifest.json` و `sw.js` (Service Worker جهت کش آفلاین).
3. ایجاد ساختار کامل پروژه اندروید در `dist/android/project/`.
4. تولید فایل‌های مانیفست و گریدل (`AndroidManifest.xml`, `build.gradle`).
5. بسته‌بندی فایل نهایی **AAB** (`dist/android/payesh-release.aab`) و **APK** (`dist/android/payesh-debug.apk`).

## ۶. چک‌لیست انتشار در کنسول گوگل‌پلی (Release Gate Workflow)

1. **امضای دیجیتال (App Signing):** ثبت کلید در Google Play App Signing.
2. **فرم محرمانگی و داده‌ها (Data Safety):** منطبق بر سند `docs/DATA_SAFETY.md` (عدم جمع‌آوری غیرضروری و عدم افشای PII).
3. **حذف حساب (Account Deletion):** ارائه لینک مستقیم `/account-deletion` مطابق با سیاست ماده ۵.
4. **تست بسته ۱۴ روزه:** دعوت از ۱۲ ارزیاب برای اجرای نسخه آزمایشی (Internal / Closed Testing).
5. **ارسال نهایی به بازبینی:** انتشار در کانال Production با ریتینگ Everyone.
