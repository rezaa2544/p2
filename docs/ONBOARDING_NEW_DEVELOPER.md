# 🐣 راهنمای توسعه‌دهندهٔ تازه‌وارد — ONBOARDING_NEW_DEVELOPER

**نسخه:** ۱.۰.۰ | **تاریخ:** 2026-09-10 | **مالک:** چت ۶ (مستندساز و مهندس انتشار)
**مخاطب:** توسعه‌دهنده‌ای که امروز وارد پروژهٔ پایش شده و می‌خواهد تا پایان هفته اولین مشارکت معتبر را داشته باشد.

## ۱) خوش آمدید — پروژه چیست؟

**پایش** سامانهٔ ملی پایش حضور و فعالیت مدارس ایران است: ≈ ۱۰ میلیون کاربر (دانش‌آموز/ولی/دبیر/مدیر)، ≈ ۱۰۰ هزار مدرسه، پیک ۲۰هزار درخواست‌برثانیه در صبح مهر. خروجی کلاینت **یک فایل `index.html`** است (توزیع تک‌فایلی) و سرور یک **مونولیت ماژولار** روی Node با پستگرس به‌عنوان تنها منبع حقیقت.

**تیم:** چند چت موازی با نقش‌های تفکیک‌شده — دیتابیس/هسته (چت ۱)، امنیت (چت ۲)، همگام‌سازی/آفلاین (چت ۳)، کارایی/زیرساخت (چت ۴)، کیفیت/پایایی (چت ۵)، مستندات و انتشار (چت ۶)، ادغام (چت ۷) — هماهنگ با ناظر (اصل هشتم: هیچ مرج بدون تأیید صریح ناظر). جزئیات نقش‌ها در `docs/SUPERVISOR_BRIEF.md`.

**نقطهٔ شروع نقشهٔ مستندات:** `docs/DOCS_INDEX.md` — قبل از هر چیز، §۱ «شروع سریع» آن را بخوانید.
**واژه‌نامه:** هر اصطلاح فنی/فارسی/انگلیسی که ندانستید در `docs/GLOSSARY.md` تعریف شده است (۹۰ مدخل انگلیسی + ۴۶ فارسی + نقش‌ها و مسیرها).

## ۲) آماده‌سازی محیط

### ۲.۱ پیش‌نیازها

| ابزار | نسخه | چرا |
|---|---|---|
| Node.js | **≥ 22** (`package.json` → `engines`) | ران‌تایم سرور و بیلد |
| PostgreSQL | 16 | تنها منبع حقیقت (برای مسیر پی‌جی‌محور) |
| Redis | 7 | حالت توزیع‌شده (نشست/ریت‌لیمیت/کش) — تولید بدون ردیس سرویس نمی‌دهد (fail-closed) |
| git | هر نسخهٔ جاری | کلون و پی‌آر |

### ۲.۲ کلون و نصب

```bash
git clone https://github.com/rezaa2544/p2.git && cd p2
npm install                     # بدون node_modules، smoke بی‌صدا خروجی ۰ می‌دهد!
```

### ۲.۳ ساخت دادهٔ اولیه و اولین اجرا

```bash
node server/seed.js             # ساخت استور سرور از دنیای دمو (بذر ثابت ۲۰۲۶۰۹۰۱ — قطعی و تکرارپذیر)
node tools/seed-office-data.js  # دادهٔ نمونهٔ سمت اداره (اختیاری)
npm start                       # یا: node server/index.js
```

### ۲.۴ تأیید سلامت محیط

```bash
node tests/smoke.js             # انتظار: 547/547 موفق
node tools/check-authz.js       # انتظار: خروجی ۰
node tests/secret-scan.js       # انتظار: 11/11
node build.js --check           # انتظار: خروجی ۰ (شامل مُهر راهنما و هم‌زمانی بیلد)
```

اگر هرکدام قرمز شد، مستقیم به `docs/TROUBLESHOOTING.md` بروید — نپرید روی کد.

## ۳) تور کدبیس

### ۳.۱ سرور (`server/`)

| جزء | فایل(ها) | مسئولیت |
|---|---|---|
| روت‌ها | `server/routes/{attendance,bootstrap,classes,grades,students,users}.js` — سوارشدن در `server/index.js` با `createXRoutes` | شش مسیر اصلی ای‌پی‌آی |
| میان‌افزار | `server/middleware/{auth,scope,pagination,projection}.js` | احراز، ایزولاسیون مستأجر (`school_id`)، صفحه‌بندی |
| داده | `server/db.js` + `server/dbquery.js` | اتصال پستگرس + فال‌بک حافظه‌ای (مسیر رسمی تا تکمیل موج ۱) · کوئری‌های صفحه‌بندی‌شده |
| کش/حالت | `server/cache.js` + `server/redis.js` | کش ال۱ + ریت‌لیمیت توزیع‌شده + ابطال نشست |
| همگام‌سازی | `server/sync.js` + `server/pull.js` + `server/syncdelta.js` + `server/conflicts.js` | پوش/پول، کرسر، تعارض‌ها |
| اوت‌باکس | `server/outbox.js` + `server/worker.js`/`worker-service.js` + `server/workers/` | صف نوشتن چندنمونه‌ای + پردازش پس‌زمینه |
| امنیت | `server/auth.js` · `server/policy.js` · `server/rate-limit.js` · `server/waf.js` · `server/otp-store.js` | مجوز یکتا، ریت‌لیمیت، دیوار آتش |
| مشاهدات | `server/metrics.js` · `server/audit.js` · `server/tracing.js` | متریک/لاگ/تریس |

### ۳.۲ کلاینت (`src/js/`)

ماژول‌های شماره‌دار (`00-data-layer.js` … `28-indexes.js` و ویوها مثل `12-attendance.js`)؛ ترتیب الحاق در `src/js/_order.json`؛ خروجی فقط با `node build.js` ساخته می‌شود — **هرگز `index.html` را دستی ویرایش نکنید**.

### ۳.۳ تست‌ها (`tests/`) — سه سطح

| سطح | نمونه | اجرا |
|---|---|---|
| یکپارچگی ای‌پی‌آی | `tests/api/*.test.js` با `tests/api/runner.js` (۷ سوئیت) | `node tests/run.js` |
| هدفمند/ویژگی | `tests/occ.js`، `tests/tombstone.js`، `tests/wave*` | مستقیم با نود |
| سراسری (دودی) | `tests/smoke.js` — ۵۴۷ بررسی، کلاینت واقعی در جی‌ساداوم | `npm run test:smoke` |

### ۳.۴ مستندات (`docs/`)

۲۰۰+ سند؛ تنها درگاه معتبر: `docs/DOCS_INDEX.md` + سلامت لینک‌ها در `docs/DOCS_HEALTH_REPORT.md`.

## ۴) گردش کار توسعه

1. **اول بخوانید:** `SKILLS_MASTER.md` (در `.claude/skills/`) را کامل — اصول معماری، امنیتی و گیت‌ها آنجاست.
2. **شاخه:** از `main` روزانه شاخه بگیرید؛ نام‌گذاری پروژه `arena/<id>-p2` است.
3. **کامیت:** پیام‌های متعارف و مشخص — الگوی رایج این ریپو: `docs:`، `test:`، `feat:`، `fix:` + شرح فارسی کوتاه + برچسب چت.
4. **تست قبل از کامیت — چهار گیت اجباری:** `smoke` ‏547/547 · `check-authz` خروجی ۰ · `secret-scan` ‏11/11 · `build.js --check` خروجی ۰.
5. **پی‌آر:** باید `mergeable: True` + سی‌آی سبز + گیت‌های محلی سبز باشد؛ چک‌لیست کامل مرج در `docs/PR_MERGE_PLAN.md` §۴؛ مرج فقط با تأیید ناظر.

## ۵) کارهای رایج (با مثال واقعی از پروژه)

### ۵.۱ افزودن مسیر جدید

الگو: شش مسیر موجود. گام‌ها: ساخت `server/routes/<name>.js` با خروجی `createXRoutes` ← سوارکردن در `server/index.js` (رجوع: خط‌های ۴۳–۴۸ برای الگوی `createStudentRoutes`) ← اعمال `server/middleware/scope.js` روی همهٔ روت‌ها (قاعدهٔ ایزولاسیون) ← افزودن مجوز نوشتن در `authz/write-perms.json` با بازتولید رسمی (`node build.js` — دستی نه؛ گیت `check-authz` مغایرت را قرمز می‌کند) ← تست در `tests/api/`.

### ۵.۲ افزودن ویوی جدید سمت کلاینت

الگو: `src/js/09-schools.js`. گام‌ها: ساخت فایل شماره‌دار `NN-name.js` ← ثبت در `src/js/_order.json` ← افزودن روت به `NAV` در `05-router.js` ← اجرای `node build.js` ← افزودن انتظار ویو در `tests/smoke.js` (بخش `NAV_EXPECT`).

### ۵.۳ افزودن مهاجرت

قرارداد کامل: `docs/MIGRATION_GUIDE.md`. الگو: `migrations/004_wave1_version_seq.sql` + جفت `*.down.sql`. قواعد: شمارهٔ پیوسته · تغییرناپذیر پس از مرج · بلوک‌های ایمن در برابر تکرار · یک کامیت برای هر جفت · اعمال دستی روی پستگرس محلی و سپس اجرای گیت‌ها.

### ۵.۴ افزودن تست

الگو: `tests/occ.js` (ساختار `chk`/شمار موفق/ناموفق + خروجی ۱ در شکست). قواعد: هر رفع باگ با تست تازه + ترجیحاً تست جهش (نگاه کنید به جهش‌های موج ۵ در `docs/WAVE5_AUTHZ.md`)؛ تست نباید به شبکهٔ بیرونی یا زمان‌بندی حساس باشد.

## ۶) عیب‌یابی — گام‌های اول
