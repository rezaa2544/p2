## ۱. اصول حاکم بر توسعه کد (Coding Standards & Constraints)

به منظور حفظ عملکرد فوق‌سریع و حفظ پایداری تک‌فایلی، تمامی کدهای پایش از اصول زیر پیروی می‌کنند:

1. **جاوااسکریپت خالص بدون فریم‌ورک (Pure Vanilla JS):**  
   هیچ فریم‌ورک خارجی نظیر React، Vue، یا Angular استفاده نشده و نخواهد شد. تمامی رندرهای DOM توسط توابع بازگرداننده رشته‌های HTML به صورت تمیز و بهینه انجام می‌شوند.
2. **قانون ایزوله‌سازی لایه داده (Data Layer Encapsulation):**  
   طبق بررسی تست‌های دودی (`tests/smoke.js`)، **هیچ فایلی در `src/js/` به جز `00-data-layer.js` حق فراخوانی مستقیم `localStorage` یا `fetch(` را ندارد**. هرگونه تعامل با حافظه فقط از طریق شیء `Store` یا `offlineStorage` و هرگونه درخواست شبکه فقط از طریق شیء `Api` مجاز است.
3. **فرار امن از تگ‌های مخرب (XSS Sanitization):**  
   هر متنی که توسط کاربر وارد‌شده باشد باید پیش از درج در HTML با تابع کمکی `escHtml()` ایمن‌سازی شود.

## ۲. گام‌های گام‌به‌گام افزودن یک صفحه یا ماژول جدید

برای افزودن یک قابلیت یا صفحه جدید به سامانه پایش، ۵ مرحله زیر را دنبال کنید:

### گام ۱: ایجاد فایل ماژول در `src/js/`
یک فایل جاوااسکریپت با نام مناسب (مثلاً `src/js/82-sample-feature.js`) بسازید:

```javascript
/* ═══════════════════════════════════════════════════════════════════
   ماژول قابلیت نمونه (Sample Feature)
   ═══════════════════════════════════════════════════════════════════ */

function viewSampleFeature() {
  const currentSchool = S.school || 1;
  const items = db.sample_items || [];
  
  return `
    <div class="card p-4">
      <div class="flex-between mb-3">
        <h3 class="font-bold text-lg">📌 فهرست آیتم‌های نمونه</h3>
        <button class="btn btn-primary" onclick="act('sample-add-modal')">➕ افزودن آیتم</button>
      </div>
      <table class="table w-full">
        <thead>
          <tr>
            <th>عنوان</th>
            <th>وضعیت</th>
            <th>عملیات</th>
          </tr>
        </thead>
        <tbody>
          ${items.map(item => `
            <tr>
              <td>${escHtml(item.title)}</td>
              <td><span class="badge badge-success">${escHtml(item.status)}</span></td>
              <td>
                <button class="btn btn-sm btn-danger" onclick="act('sample-delete', {id: '${item.id}'})">حذف</button>
              </td>
            </tr>
          `).join('')}
        </tbody>
      </table>
    </div>
  `;
}
```

### گام ۲: ثبت فایل در `src/js/_order.json`
نام فایل ایجادشده را در آرایه `src/js/_order.json` در جایگاه مناسب قبل از `99-theme-loader.js` اضافه کنید.

### گام ۳: تعریف مسیر (Route) و دسترسی در `30-authz.js`
در فایل `30-authz.js`، مسیر را به نقش‌های مجاز اضافه نمایید:
```javascript
// در آرایه روت‌های مجاز نقش مثلاً مدیر:
manager: [..., 'sample-feature', ...]
```
و در مپ روت‌ها به تابع نما (`05-router.js` یا `07-shell.js`):
```javascript
'sample-feature': viewSampleFeature,
```

### گام ۴: تعریف اکشن‌های تعاملی در `19-actions-*.js`
اکشن‌های مربوطه را در تابع هندلر اکشن ثبت کنید:
```javascript
case 'sample-add': {
  const title = payload.title;
  if (!title) return toast('عنوان الزامی است', 'error');
  
  const newRecord = {
    id: nextId('sample_items'),
    school_id: S.school,
    title: title,
    status: 'فعال',
    created_at: new Date().toISOString(),
    version: 1
  };
  
  // ذخیره در استور محلی و ثبت خودکار در صف آفلاین
  Store.put('sample_items', newRecord);
  toast('آیتم با موفقیت افزوده شد', 'success');
  render();
  break;
}
```

### گام ۵: ممیزی اکشن و بیلد
دستور ممیزی مجوزها و بیلد را اجرا نمایید:
```bash
node tools/check-authz.js
node build.js
```

## ۳. نحوه نسخه‌گذاری رکوردها جهت حل تعارض در همگام‌سازی (`Version Vectors`)

برای جلوگیری از بازنویسی ناخواسته در شرایطی که دو کاربر همزمان یک نمره یا حضور را ویرایش می‌کنند:
- هر درج رکورد جدید با فیلد `version: 1` آغاز می‌شود.
- در هر ویرایش، نسخه جدید رکورد به `version: old_version + 1` ارتقا یافته و مقدار `base_version: old_version` به صف سینک ارسال می‌شود.
- سرور در صورت عدم انطباق `base_version` با رکورد خود، تعارض را در جدول `sync_conflicts` ثبت کرده و برای داوری در ماژول `68-sync-conflicts.js` به مدیر ارائه می‌دهد.
