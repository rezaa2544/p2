# استقرار ردیس با پایداری کامل — پایش (فاز ۲.۱)

> این دایرکتوری الگوهای پیکربندی تولید را نگه می‌دارد. رمزها به‌صورت
> جای‌دار `{{…}}` هستند و **هرگز** نباید با مقدار واقعی در مخزن ثبت
> شوند (اصل «بدون راز در کد» — `tests/secret-scan.js` نگهبان است).

## توپولوژی پایه: ۳ نود + ۳ سنیتنل (توصیهٔ فاز ۲.۱)

```
 میزبان A                میزبان B                میزبان C
 ┌───────────────────┐  ┌───────────────────┐  ┌───────────────────┐
 │ redis-node-1      │  │ redis-node-2      │  │ redis-node-3      │
 │ (مستر)      :6379 │  │ (تکثیر)     :6379 │  │ (تکثیر)     :6379 │
 │ sentinel-1  :26379│  │ sentinel-2  :26379│  │ sentinel-3  :26379│
 └───────────────────┘  └───────────────────┘  └───────────────────┘
```

- سه سنیتنل با `quorum=2`: تحمل یک خرابی میزبان بدون توقف.
- شکست‌خورد خودکار مستر توسط سنیتنل؛ کلاینت‌ها از همان مسیری که
  `server/redis.js` می‌سازد به‌روزرسانی می‌شوند (بدون تغییر دستی آدرس).
- پایداری روی هر سه نود فعال است: **RDB + AOF هم‌زمان** (جزئیات پایین).

## جای‌دارها

| جای‌دار | مقدار |
|---|---|
| `{{REDIS_PASSWORD}}` | رمز مشترک ردیس (از مخزن اسرار محیط، نه گیت) |
| `{{REDIS_NODE1_HOST}}` | نشانی میزبانِ نود ۱ (مستر اولیه) |

جایگذاری نمونه در زمان استقرار:

```bash
sed -e "s/{{REDIS_PASSWORD}}/${REDIS_PASSWORD:?}/" \
    -e "s/{{REDIS_NODE1_HOST}}/${NODE1_HOST:?}/" \
    ops/redis/redis-node-1.conf > /etc/redis/redis.conf
```

## اتصال از سمت پایش

`server/redis.js` حالت را از محیط می‌گیرد (اولویت: کلاستر، سنیتنل، تنها):

```bash
# حالت سنیتنل (پیش‌فرض این توپولوژی)
REDIS_SENTINELS=HOST_A:26379,HOST_B:26379,HOST_C:26379
REDIS_SENTINEL_NAME=payesh-master
REDIS_PASSWORD=...

# حالت کلاستر (مهاجرت آینده — بخش بعد)
REDIS_CLUSTER_NODES=HOST_A:7000,HOST_B:7000,HOST_C:7000
```

بدون این متغیرها، سرور با فال‌بک درون‌حافظه‌ای بالا می‌آید (فقط توسعه).

## پایداری داده (مصوبهٔ فاز ۲.۱)

| سازوکار | تنظیم | معنا |
|---|---|---|
| RDB | `save 900 1` / `save 300 10` / `save 60 10000` | عکس فوری: هر ۱۵ دقیقه با ≥۱ تغییر، هر ۵ دقیقه با ≥۱۰، هر دقیقه با ≥۱۰۰۰۰ |
| AOF | `appendonly yes` + `appendfsync everysec` | بیشترین زیانِ قابل‌قبول = ۱ ثانیه داده |
| بازنویسی AOF | `auto-aof-rewrite-percentage 100` + `auto-aof-rewrite-min-size 64mb` | فایل دو برابر شود یا از ۶۴ مگابایت بگذرد |
| ایمنی | `stop-writes-on-bgsave-error yes` | شکست ذخیره‌سازی پنهان نمی‌ماند (fail-closed) |
| بازیابی | `aof-load-truncated yes` + `aof-use-rdb-preamble yes` | بارگذاری حتی با فایل بریده‌شده در کرش |

ترتیب بارگذاری ردیس: اول AOF (تازه‌تر)، اگر نبود RDB. رویهٔ کامل
بازیابی: `docs/REDIS_RESTORE_PROCEDURE.md`.

## نسخهٔ پشتیبان خودکار

اسکریپت `tools/redis-backup.sh` هر ۶ ساعت (کرون) یک نسخهٔ `dump.rdb`
و `appendonly.aof` می‌گیرد و در مقصد پشتیبان نگه می‌دارد؛ نگهداری ۷
روز. جزئیات در سرِ همان اسکریپت.

## ارتقا به Redis Cluster (نقشهٔ راه)

برای مقیاس ملی با دادهٔ بیشتر از ظرفیت یک مستر:

1. شش نود (۳ مستر + ۳ تکثیر) با `redis-cli --cluster create ... --cluster-replicas 1`.
2. کلیدهای پایش پیشوند دارند (`rate:*`, `cache:*`, ...) — در صورت نیاز به
   هم‌لوک بودن چند کلید، از هش‌تگ `{…}` در کلید استفاده شود.
3. کلاینت با `REDIS_CLUSTER_NODES` به حالت کلاستر می‌رود — کد برنامه تغییری
   نمی‌خواهد (به‌جز کلیدهای چندکلیدی که باید هش‌تگ بگیرند).
4. پیش از مهاجرت، یک دور کامل «بازیابی در محیط جدا»
   (`docs/REDIS_RESTORE_PROCEDURE.md`) را با دادهٔ واقعی تمرین کنید.

## بررسی سلامت

```bash
redis-cli -h HOST_A -p 26379 SENTINEL get-master-addr-by-name payesh-master
redis-cli -a "$REDIS_PASSWORD" INFO persistence   # rdb_last_bgsave_status:ok / aof_last_write_status:ok
node tests/redis-cluster.js                        # با متغیرهای محیط بالا، اتصال زنده آزموده می‌شود
```
